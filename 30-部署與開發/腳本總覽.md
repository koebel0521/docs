# 腳本總覽

這頁只做索引。每支腳本的使用流程、前提、參數與失敗判讀，改看對應的獨立文檔。

## 使用原則

- 先找對應腳本文檔，再跑腳本。
- 能 `-DryRun`、`-Check`、`-Quiet` 就先看一遍。
- 不收參數的腳本（`.ps1`、`.sh`、`.py` 都一樣）會拒絕多餘參數，不會當成沒看到；要看用法請查對應文檔。
- 說明旗標統一：`.ps1` 用 `-h`／`-Help`（印 `Get-Help -Detailed` 後返回，不進執行路徑）；`.sh` 用 `-h`／`--help`（印說明到 stdout、結束碼 0），用法錯誤（未知旗標、多餘位置參數）一律結束碼 2。只吃環境變數的 `.sh` 在開頭呼叫 `scripts/lib/noargs.sh` 的 `no_args_usage`，純位置參數腳本用同檔的 `require_args`；回歸測試 `scripts/lib/cliusage_test.sh`（以替身 docker／git／go 證明說明與錯誤參數沒走到執行路徑）。
- 會改環境、落檔、發版、封存的腳本，先看相關文檔再動手。
- `scripts/private/p0-daily-check.ps1` 是統一入口，不是取代各腳本文檔。
- `scripts/private/` 已被 `.gitignore` 排除、不在版控（p0-daily-check、alert-selfheal、regression-gate、merge-gate、fault-archive、player-incident-snapshot、check-s2s-docker）；乾淨 clone 沒有這些腳本，CI 與版控內腳本不得依賴它們。

## 監控與文件

- 整理 Go imports 與格式：`make fmt`（`scripts/gotool.sh golangci-lint fmt`，與 CI、pre-commit 同一套 formatter 與版本；原 `scripts/goimports.ps1` 已移除）。
- [`scripts/gotool.sh`](../../scripts/gotool.sh)：`tools/gotools` 鎖定版本工具（golangci-lint、govulncheck、benchstat 等）的**唯一入口**，用法同 `go tool`（例如 `scripts/gotool.sh golangci-lint fmt <檔案>`、`scripts/gotool.sh -n govulncheck` 只印執行檔路徑）；固定 `GOWORK=off`，以腳本位置推導 modfile 絕對路徑，任何工作目錄都能呼叫。pre-commit、Makefile、CI 與其他腳本一律走它，`configaudit` 守門擋其他地方直接寫 `-modfile=tools/gotools`。

## 其他腳本

- [`scripts/core-test-up.ps1`](../../scripts/core-test-up.ps1)：以 `compose.core-test.yml` 起 Central、World、Gate 與依賴，並為各服務開日誌視窗。
- [`scripts/reset-local-deps.ps1`](../../scripts/reset-local-deps.ps1)：`make deps-reset-local` 的實作；只允許本機 `13306` MySQL。
- [`scripts/ci-deploy.sh`](./Docker發版流程.md)：GitLab deploy job 呼叫的部署腳本，失敗自動回退 image 與設定 artifact；`pja` 工具預編進具名 volume `pja-bin` 後直接執行，不再 `go run`；`scripts/migrate-prod.sh` 轉呼叫 `deps/PJA-Database/scripts/migrate-prod.sh`。
- [`scripts/ci-bench-gate.sh`](../../scripts/ci-bench-gate.sh)：MR 的 benchmark 退化守門，只對受影響套件在 base 與 HEAD 交錯量測並以 benchstat 比較。
- [`scripts/check-perf-commit-range.sh`](../../scripts/check-perf-commit-range.sh)：CI `perf-commit-msg` job 實際呼叫的入口（本機 `make perf-msg-check`）；對 `<base>..HEAD` 中尚未進入 develop 的非合併提交逐一呼叫 `check-perf-commit-msg.sh`，已在 develop 的舊提交不重驗。[`scripts/perf-msg-exempt.txt`](../../scripts/perf-msg-exempt.txt) 列已知歷史提交，以完整 SHA **或**逐字相同的提交標題比對（抵擋 rebase／cherry-pick 換 SHA）。
- [`scripts/check-submodule-pushed.sh`](../../scripts/check-submodule-pushed.sh)：pre-push 守門，讀 pre-push stdin 逐個 ref 檢查：只看本次 push 範圍內該 ref 的子模組指標提交，必須已在該子模組的某個遠端追蹤分支上（不連網；子模組 push 後先 `git fetch`；未初始化的子模組略過）。
- [`scripts/ci-race-pkgs.sh`](../../scripts/ci-race-pkgs.sh)：由檔案推導含 `//go:build race` 的套件目錄（`./dir/...`），供帶 `race` 標記的 golangci-lint 使用（CI lint 與 `make ci-lint` 共用，新增 race 開關檔不必手改清單）。
- [`scripts/lib/envfile.sh`](../../scripts/lib/envfile.sh)：`env_get` 依 compose dotenv 規則逐鍵讀 env 檔（備份、還原、`ci-deploy.sh` 共用）。規則與 `docker compose config --environment` 對齊：雙引號內未知跳脫（如 `"p\w0rd"`）保留反斜線並展開 `\r`；單引號內 `\'` 是跳脫的單引號；未加引號的值只有「空格＋`#`」才是行內註解（`a<TAB>#x` 是整串）；`export` 前綴與 CRLF 同 compose。`scripts/lib/envfile_test.sh` 逐案對照，本機有 `docker compose` 時與 compose 結果互驗；`production-smoke.ps1` 不再手寫解析，改由 `docker compose --env-file … config --environment` 取值（與服務實際讀到的一致）。
- [`scripts/check-perf-commit-msg.sh`](../../scripts/check-perf-commit-msg.sh)：單一提交的 `perf:` 證據檢查（benchstat `vs base` 表頭或量測方式），commit-msg hook 與上一支共用。三條守門：前綴白名單、`perf:` 須附 benchstat 或量測方式、非 `perf:` 的效能宣稱或 `- perf:` 條列無證據即拒絕（另有軟提示不擋）；已進 develop 的歷史提交豁免列在 [`scripts/perf-msg-exempt.txt`](../../scripts/perf-msg-exempt.txt)。
- [`scripts/ci-alloc-guard.sh`](../../scripts/ci-alloc-guard.sh)：熱路徑零配置守門，跑名稱含 `AllocatesNothing` 的測試並要求通過數量不得少於下限；以 `go test -json` 計 `Action=pass` 且 `Test` 不含 `/` 的頂層事件（測試輸出不帶換行時 `-v` 的 `--- PASS:` 會接在同一行而漏算），輸出還原成一般 `-v` 文字給 CI log；套件清單可用 `ALLOC_GUARD_PKGS` 覆寫（僅測試用）。`GoTestGate.ps1`（gate 腳本共用）同樣改計 JSON 事件。
- [`scripts/ci-bench-pkgs-check.sh`](../../scripts/ci-bench-pkgs-check.sh)：有非 integration Benchmark 的目錄必須列在 `bench/packages.txt`。
- [`scripts/ci-bench-names-check.sh`](../../scripts/ci-bench-names-check.sh)：benchmark 名稱層漂移檢查（只示警）：實際跑得到的名稱對 `bench/benchmark_baseline.txt`，缺基準的名稱可列在 `bench/pending-baseline.txt`（完整 Benchmark 名稱）；CI `bench-smoke` 與 `make bench-names` 使用，回歸測試 `scripts/lib/benchnames_test.sh`。
- [`scripts/ci-lint-extra.sh`](../../scripts/ci-lint-extra.sh)：CI lint job 與 `make ci-lint` 共用的腳本守門。
- [`scripts/ci-os-pkgs.sh`](../../scripts/ci-os-pkgs.sh)、[`scripts/lint-other-goos.sh`](../../scripts/lint-other-goos.sh)：列出含平台專屬檔的套件，並以另一個 GOOS 跑 golangci-lint（pre-commit、`make ci-lint` 共用）。
- [`scripts/ci-docker-tool.sh`](../../scripts/ci-docker-tool.sh)：`make ci-lint` 用來執行 pwsh、shellcheck；有 docker 就一律用與 CI 同 digest 的映像，`CI_TOOL_LOCAL=1` 才強制用本機工具，沒有 docker 才略過並警告。
- [`scripts/ci-ps-syntax.ps1`](../../scripts/ci-ps-syntax.ps1)：全部 `.ps1` 的語法檢查（只解析不執行），CI `powershell-syntax` job 使用。
- [`scripts/lib/pwsh-checks.txt`](../../scripts/lib/pwsh-checks.txt)：CI `powershell-syntax` job 與 `make ci-lint` 共用的 PowerShell 檢查清單（單一來源，每行一個以 pwsh 執行、不收參數的 `.ps1`，含 `faultdrill_test.ps1`）；`scripts/lib/*_test.ps1` 都要列入（需要 go 的 `gotestgate_test.ps1` 例外，由 `make ci-lint` 另外執行），`TestPwshChecksListCoversScripts` 守門。
- [`scripts/Build-And-Sync-Config.cmd`](../../scripts/Build-And-Sync-Config.cmd)：呼叫同名 `.ps1` 的 Windows 入口，見[配置操作入口](./配置操作入口.md)。
- [`scripts/ci-registry.sh`](../../scripts/ci-registry.sh)：CI 發版 job 登入／登出映像倉庫（`login`｜`logout`）。
- [`scripts/ci-patch-coverage.sh`](./開發規則.md)：MR 改動行覆蓋率檢查。
- [`scripts/migrate-player-variables.ps1`](./配置操作入口.md)：玩家變數 migration。
- [`scripts/gen-pgo-profile.ps1`](../../scripts/gen-pgo-profile.ps1)：產生 `default.pgo`，可用 `-ProductionProfile` 併入正式 pprof。
- [`scripts/get-failed-pipeline-logs.ps1`](../../scripts/get-failed-pipeline-logs.ps1)：下載 GitLab 失敗 pipeline 的 job log（`-PipelineId`、`-OutputDirectory`，預設 `.\failed-pipeline-logs`）。
- S2S 機密（流程見 [S2S身份驗證](./S2S身份驗證.md)）：`new-s2s-dev-secrets.ps1`、`check-s2s-dev-secrets.ps1`、`update-s2s-gate-secret.ps1`、`invoke-s2s-maintenance.ps1`、`new-s2s-maintenance-task.ps1`、`check-s2s-distribution.py`、`check-s2s-maintenance.py`；底層 `s2s-distribute.py`、`s2s-renew-certificates.py`、`s2s-secret-receiver.py` 由維護入口呼叫，不直接執行。
