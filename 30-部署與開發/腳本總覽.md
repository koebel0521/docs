# 腳本總覽

這頁只做索引。每支腳本的使用流程、前提、參數與失敗判讀，改看對應的獨立文檔。

## 使用原則

- 先找對應腳本文檔，再跑腳本。
- 能 `-DryRun`、`-Check`、`-Quiet` 就先看一遍。
- 會改環境、落檔、發版、封存的腳本，先看相關文檔再動手。
- `scripts/p0-daily-check.ps1` 是統一入口，不是取代各腳本文檔。

## 監控與文件

- [`scripts/goimports.ps1`](../../scripts/goimports.ps1)：依專案規範整理 Go imports 與格式。
- [`scripts/monitoring-up.sh`](./scripts/監控啟動.md)
- [`scripts/monitoring-smoke.ps1`](./scripts/監控冒煙測試.md)
- [`scripts/validate-monitoring.py`](./scripts/驗證監控.md)
- [`scripts/docs-drift-check.ps1`](./scripts/文件漂移檢查.md)
- [`scripts/configcheck.ps1`](./scripts/配置檢查.md)
- [`scripts/sync-data-config.ps1`](../../scripts/sync-data-config.ps1)：把 `PJA-Config` 的產物同步到 `pkg/dataconfig/generated` 與 `config/data`；日常建議用 `tools/Build-And-Sync-Config.ps1`，它會先建置再同步。
- [`scripts/sync-protocol.ps1`](../../scripts/sync-protocol.ps1)：從 `PJA-Protocol` 產生並同步 Client 與 S2S 協議到 `pkg/protocol/wire`，並匯入 `pkg/msg` 的訊息包裝；`-Check` 只比對不寫入。
- [`scripts/publish-data-config.ps1`](./配置Artifact發布與回退.md)：驗證並發布 bytes artifact，支援拓樸 migration、lineage 驗證與壓縮。
- [`scripts/initialize-board-topology.ps1`](./配置Artifact發布與回退.md)：初始化、檢查與離線搬遷玩家盤面拓樸版本。
- [`scripts/backup-data-config-release.ps1`](./配置Artifact發布與回退.md)：備份 `current.json` 與指定 release。
- [`scripts/rollback-data-config-release.ps1`](./配置Artifact發布與回退.md)：經 Server 驗證後切換指定 release。
- [`scripts/cleanup-data-config-releases.ps1`](./配置Artifact發布與回退.md)：列出或清理已脫離 lineage 的 release。
