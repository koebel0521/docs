# 後端啟動與發布流程

## 本機完整啟動

環境需求：Go 1.27+、Docker Compose、Bash（Linux、macOS 或 WSL）。在 Server 專案目錄執行：

```bash
./scripts/docker-deps-up.sh
./scripts/dev-up.sh
```

`dev-up.sh` 以 `config/dev/*.yaml` 啟動 Central、Record、Lobby、Chat、World、Gate 與 User。若要連監控一起啟動，改用 Docker 全堆疊：

```bash
./scripts/docker-full-up.sh
```

全堆疊啟動後，檢查容器狀態：

```bash
docker compose -f docker/compose/compose.full.yml ps
```

預設玩家連線埠為 `62001`，Record HTTP 為 `6070`，Grafana 為 `http://localhost:3000`，Prometheus 為 `http://localhost:9090`。

## 正式發布

以下命令在已配置正式環境變數及憑證的發布環境執行。建置及推送腳本會處理 Central、World、Gate；部署所需的 Lobby image 需另外確保已建置並推送。先設定本次版本並建置、推送：

```bash
export REGISTRY=registry.example.com/project
export IMAGE_TAG=<release-tag>
./scripts/docker-build-images.sh
./scripts/docker-push-images.sh
```

在 `PJA-Server` 目錄執行資料遷移；`scripts/migrate-prod.sh` 與 `ci-deploy.sh` 一樣使用子模組 `deps/PJA-Database`（可用 `PJA_DATABASE_DIR` 覆寫）。正式 `.env.prod` 須設定 `AUTO_MIGRATE_DISABLED=true`、正確的 `MYSQL_DSN` 與 `MIGRATION_PLAN_DIR`（留空用映像內 `/src/migrations`；自訂須為宿主機絕對路徑，相對路徑 `ci-deploy.sh` 直接報錯退出）。先驗證版本鏈，再正式套用：

```bash
# 子模組沒有 toolchain 行：沿用根 module 解析出的 Go 版本（go1.27.2），主機 Go 較舊時才不會編出帶已修補標準庫漏洞的 datamigrate
(export GOTOOLCHAIN="$(go env GOVERSION)"; cd deps/PJA-Database && go run ./cmd/datamigrate -dir migrations -mode validate -environment production)
# .env.prod 是 compose 的 dotenv 格式、不是 bash：未加引號的 MYSQL_DSN=...@tcp(...)/... 交給 source 會語法錯誤，改以 env_get 逐鍵讀
source scripts/lib/envfile.sh
ENV_FILE=.env.prod
export AUTO_MIGRATE_DISABLED="$(env_get AUTO_MIGRATE_DISABLED)" MYSQL_DSN="$(env_get MYSQL_DSN)"
plan_dir="$(env_get MIGRATION_PLAN_DIR)"
if [ -n "${plan_dir}" ]; then export MIGRATION_PLAN_DIR="${plan_dir}"; fi
./scripts/migrate-prod.sh   # 內部同樣以 GOTOOLCHAIN=$(go env GOVERSION) 進子模組
```

Migration 成功後，確認 `.env.prod` 的 Central、World、Gate、Lobby image 都指向預期版本，再到 `PJA-Server` 目錄部署：

```bash
docker compose --env-file .env.prod -f docker/compose/compose.prod.yml up -d
docker compose --env-file .env.prod -f docker/compose/compose.prod.yml ps
docker compose --env-file .env.prod -f docker/compose/compose.prod.yml logs --tail 100 central world gate
powershell -ExecutionPolicy Bypass -File .\scripts\production-smoke.ps1
```

Migration 失敗時停止發布並保留現行服務。回退 image 時，把 `.env.prod` 的 tag 改回上一個穩定版本，重新執行 `docker compose ... up -d` 並確認 smoke。若 migration 已套用，先確認舊 image 與新 schema 相容；不可直接對正式資料降版。
