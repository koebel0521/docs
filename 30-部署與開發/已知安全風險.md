# 已知安全風險

本文件記錄審查找到、**決定接受**的安全風險。處理前請先與 PJA-Client 負責人確認，Client 不在本專案範圍。

| # | 項目 | 位置 | 現況 | 影響 | 緩解 |
|---|---|---|---|---|---|
| 1 | 玩家連線無 TLS | `cmd/gate/internal/services/userserver.go`（對外埠 `62001`，見 `docker/compose/compose.prod.yml`） | Gate 收明文 TCP，只有 S2S 連線用 TLS（`pkg/s2sauth`）；PJA-Client 決定不做 TLS（2026-10-13） | 登入帳號與密碼在公網以明文傳輸，路徑上的人可竊聽或竄改封包；bcrypt 只保護資料庫中的密碼 | 玩家走 VPN，或以防火牆／安全群組限制來源網段；之後若 Client 支援 TLS，在 Gate 前放 TLS 終結（nginx stream、HAProxy、stunnel）或讓 Gate 自行 `crypto/tls`，Client 需同步改 |
| 2 | Redis、RabbitMQ 連線無 TLS；MySQL TLS 預設關閉 | `pkg/redis/client_new.go`、`RABBITMQ_URL`（World、Record，`docker/compose/compose.prod.yml`）、`pkg/mysql/mysql.go`（`mysql.tls`） | Redis 沒有 TLS 設定；RabbitMQ 以 `amqp://` 連線，帳密寫在 URL；MySQL 需設 `mysql.tls` 才加密；`mysql.tls` 設為 `skip-verify`（不驗證憑證）或 `preferred`（會靜默退回明文）時啟動只記 Warn、不拒絕啟動（專案沒有可靠的 prod 判斷慣例） | 跨主機部署時密碼與資料明文 | 資料庫、Redis、RabbitMQ 只放同一內網或 Docker network，不對外開放；跨主機時 MySQL 設 `mysql.tls: true` 或帶 CA 的自訂設定名（`skip-verify`、`preferred` 擋不住中間人）、RabbitMQ 改 `amqps://` |
| 3 | 登入限流不含每帳號全域上限；首次登入自動建帳 | `cmd/gate/internal/flow/user/login/coordinator.go`、`cmd/central/internal/flow/login/new_user.go` | 只限每 IP、每（帳號, IP）；不鎖帳號是刻意設計。首次登入的帳號自動建立，建帳速率原本只受每 IP 登入限流約束、新帳號沒有最短密碼 | 換 IP 的分散式猜密碼對同一帳號沒有全域上限；可大量建立垃圾帳號（從未活躍的帳號 360 天才清） | bcrypt 槽位已加 3 秒等待期限，滿載回服務暫不可用，不會拖垮 Central。Central 選填 `new_user.rate`／`new_user.burst`（全服建帳速率，超過回 `AuthServiceUnavailable`）與 `new_user.min_password_bytes`（新帳號最短密碼，過短回 `AuthWrongPassword`），預設皆 0＝不限制；最短密碼**須先與 PJA-Client 註冊提示同步**才開（見[設定注入與熱更新](../00-導讀/設定注入與熱更新.md#central-new_user-選填鍵)）。Gate 每 IP 同時連線上限可用 `session.max_connections_per_ip` 調整（預設 100，CGNAT 取捨）。**未登入連線有全域上限**：未登入（`sock.ID() == 0`）連線可存活到握手逾時（約 30 秒），只靠每 IP 上限時約 11 個來源（每來源 100 條）即可佔滿預設 1024 的連線槽、擋掉所有新玩家；Gate 現在把未登入連線總數限制在 `max_connections` 的 1/4（未設定 `max_connections` 時為 256，`user.DefaultMaxUnauthenticated`），超過時**關閉最舊的未登入連線**讓新連線進來，計入 `tcp_rejected_connections_total{service="user",reason="unauth_evicted"}`。正常玩家的新連線因此永遠進得來，攻擊者必須持續用新連線換掉自己的舊連線；代價是尖峰時剛連上、還沒送完登入的合法連線也可能被淘汰（客戶端重連即可）。計數為樂觀計數（連線時加一，超過上限才掃描，每 5 秒的連線檢查順便重算修正偏差），平時不遍歷連線 |
| 3a | Lobby 公開 `:8080` 的資源上限 | `cmd/lobby/internal/handler/servers.go`（`BuildServers`、`MaxConns`） | 同時連線上限 2048、每個來源 IP（IPv6 以 /64 計）每秒 20 個請求、突發 40（超過回 429）；每個請求 3 秒期限；公開 listener（Lobby、Record）keep-alive 閒置 5 秒（原 30 秒） | CGNAT 下大量玩家共用 IP 時可能被 429；超過 2048 條同時連線的新連線要排隊 | 數值寫在程式常數，需要時調整後重新發版；閒置連線約 20 KB／條，2048 條約 40 MB，遠低於 Lobby 容器上限 |
| 4 | Lobby admin 與 Record `/events` 以明文 HTTP 收 Bearer token | `cmd/lobby/internal/handler/servers.go`（`ADMIN_ADDR`／`admin_addr`）、`cmd/record/run.go`（`addr`） | 預設只綁 loopback（開發用 `config/dev/lobby.yaml` 的 `addr`／`admin_addr` 與 `compose.full.yml` 的 `8080` 對外埠也只綁 `127.0.0.1`，不再是 `0.0.0.0`）；綁內網介面時 token 在內網路徑上明文傳輸（2026-10-16 審查） | 內網被竊聽時 token 可被重放，取得 GM 發放與玩家事件查詢權限 | 只綁 loopback，或以 nginx／stunnel 在前面做 TLS 終結；token 常數時間比對、最短 32 字元、拒絕 `change-me` 開頭的範本佔位（Lobby 三個 token 與 Record `http_token` 皆是），Lobby 的 admin／ops／gm 三個非空 token 不可相同；每 IP 失敗鎖定只有 Lobby admin 有，Record `/events`（`requireBearerToken`）沒有，只靠 token 的熵。Lobby admin 鎖定期間直接拒絕、不再比對 token：被鎖定的來源連正確 token 也回 429，同一 NAT 後的合法維運會與攻擊者共用額度而被暫時擋住（每 12 秒回復一次嘗試機會）；HTTP 伺服器另限制標頭 `MaxHeaderBytes=16KB`，存取日誌的 path 截斷為 256 bytes，避免未驗證來源以超長 URL 灌爆日誌 |
| 5 | MR 可在 deploy runner 執行任意程式碼；MR 與發版共用 BuildKit 快取（**待處理**） | `.gitlab-ci.yml`（`build-images-mr`、`build-images` 共用 `tags: [deploy]`）、`docker/app.Dockerfile`（`RUN --mount=type=cache`） | rules 只限同專案 MR 才上 deploy runner，但 `.gitlab-ci.yml` 本身在 MR 內，有 push 權限者可自加 `tags: [deploy]` 的 job；MR 與發版建置共用 `/go/pkg/mod`、`/root/.cache/go-build` 快取（2026-10-17 審查 H4） | 在 production 主機（shell executor、可存取 docker.sock）執行任意指令；MR 可改寫快取內的模組原始碼，之後發版直接使用而產出被植入的正式映像 | 待處理：GitLab 將 deploy runner 設為 Protected（只跑 protected branch／tag）；`build-images-mr` 改用獨立的 docker executor runner 或 rootless 建置；發版建置使用不同的 cache id 或 `--no-cache` |
