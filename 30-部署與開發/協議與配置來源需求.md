# 協議與配置來源需求

Server 的生成物（`pkg/protocol/wire`、`pkg/msg` 的訊息包裝、`pkg/dataconfig/generated`、`config/data`）來自子模組 `deps/PJA-Protocol` 與 `deps/PJA-Config`，不得手改。子模組指標即本專案依賴的來源版本；更新子模組後必須重新同步生成物並一起提交。來源版本不夠新時，同步後會編譯失敗或測試失敗。本文記錄目前依賴的來源版本與合併順序；同步指令見專案根目錄的 `AGENTS.md`。

## 來源版本需求

### PJA-Protocol

子模組 `deps/PJA-Protocol` 目前指向 `63c31d9`（`origin/develop`，協定版本 3），至少必須包含 commit `662c0f3`。`develop` 累積了 Server 目前依賴的全部協議變動：

- `Templates/go-bin` 產生 `Serialize`／`Deserialize`，以及 bytes 欄位以 `ReadBytesInto` 解碼。`pkg/msg` 依賴它們；來源不含時 `sync-protocol.ps1` 直接失敗，不覆寫 `pkg/protocol/wire`，`pkg/msg` 的 `TestTransportUnpackAllocations` 與 Payload 重用測試也會失敗。
- `server-go` 合併輸出：Client 與 S2S 結構輸出到單一套件 `pkg/protocol/wire`（`4f66aa4`）。
- `gomsg` 標籤與 TemplatesMsg 包裝層生成，`sync-protocol.ps1` 會把產物匯入 `pkg/msg`（`a058abc`、`4928746`）。
- S2S 與 Client 的 `responseCode` 改用 `AuthResultCode` 列舉（`79b0827`、`58f5c77`）。
- 新增 Client 時間同步協議 `TimeSyncRequest`（2007）、`TimeSyncResponse`（2008）（`ac2b373`）。
- 每個結構附帶具體型別的 `AppendTo`／`DecodeFrom`／`UnpackFrom`，gomsg 包裝的 `PackTo`／`Unpack` 改用它們（`662c0f3`）；手寫訊息也直接呼叫，`pkg/packet` 已刪除。來源不含時同步後無法編譯。

從不含這些 commit 的來源同步，`sync-protocol.ps1 -Check` 會失敗，或產生無法編譯的程式碼。

### PJA-Config

必須包含 commit `957ea19`（`GameRules` 新增 `DefenderProtectionPeriod`；原記為 `0b36905`，已由 `957ea19` 合併進 `PJA-Config` 主線 `develop`），子模組目前的 `ddab18d` 已包含它。

- World 讀取並要求 `DefenderProtectionPeriod` 大於 0。
- 從不含此 commit 的 `PJA-Config` 執行 `Build-And-Sync-Config.ps1`，`pkg/dataconfig/generated` 會少掉此符號而無法編譯。
- `BoardSpaceKind` 不含 `CommandCenter`：`Start` 即指揮中心。

## 2026-10-14 新增的協議變動（已在 `origin/develop`）

下列 3 個 commit 原在 `PJA-Protocol` 本機分支 `develop-batch-2026-10-14`，現已包含在 `origin/develop`（`63c31d9` 的祖先）：

- `e1f4f85`：Go 產生器解碼改就地重用配置，物件池 `Reset` 保留切片容量（只影響生成碼，wire 位元組不變）。
- `76b2a0e`：新增 S2S `ChatDeliverBatch`（30202），Chat 每個 Gate 一幀；舊 `ChatDeliver` 保留給 client 協定。
- `b28c1fe`：新增 S2S `LogoutBatchCentralToWorld`（30013），Central 依 World 分組批次登出；不改既有 `LogoutCentralToWorld`。

這些都是新增項目，本身不需要協定版本升級（協定版本後來因 `63c31d9`「ChatDeliver 移除 targetPlayerId」升為 3，`protocol.version.json` 與 `pkg/release/release.json` 都是 3），`protocol.lock.json` 已重寫。頻道相關 bean（30403–30405）仍保留在 `protocol.xml`，Go 端已停用，移除需要升版，見[聊天服務](../10-核心流程/聊天服務.md)。

推送順序：PJA-Server 的子模組指標指向的 PJA-Protocol commit，必須先存在於子模組遠端（目前 `63c31d9` 已在 `origin/develop`）。

## 合併順序

Server 的 `develop` 依賴上面的外部變動，必須依序合併。CI 取的是本倉庫**子模組指標記錄的 commit**（`.gitlab-ci.yml` 的 `GIT_SUBMODULE_STRATEGY`／`GIT_SUBMODULE_PATHS`），不是 `PJA-Protocol` 的 `main`；指標指向的 commit 必須已 push 到子模組遠端，否則 CI clone 失敗（pre-push 的 `submodule-pushed` 守門會擋）：

1. **PJA-Protocol**：`develop` 已包含上述全部 commit，已完成。
2. **PJA-Protocol**：把 `develop` 合併到 `main`（分支管理待辦，**不阻塞 CI**：CI 取子模組記錄的 commit，不取 `main`）。`main` 是受保護分支，需走 Merge Request；`main` 目前落後 `origin/develop` 84 個 commit。
3. **PJA-Config**：已完成。`DefenderProtectionPeriod` 已由 `957ea19` 合併進 `develop`，子模組 `ddab18d` 已含它（原 `0b36905` 與 `claude/solid-review-config` 的合併已不再是待辦）。
4. **PJA-Server**：合併 `develop`。合併前先執行 `scripts/sync-protocol.ps1 -Check` 與 `scripts/Build-And-Sync-Config.ps1`，確認生成物與來源一致。
5. **部署**：Gate、Central、World 必須同一版一起上線。`responseCode` 列舉化讓 S2S 封包每個欄位多 2 位元組，新舊版本混跑會解碼失敗。
6. **PJA-Client**：`LoginResponse`、`LogoutResponse` 的 `ResponseCode` 由 `short` 變 `AuthResultCode`（wire 由 2 位元組變 4 位元組），Client 必須用新版契約重新生成並與 Server 同一個版本發布。`TimeSyncRequest`、`TimeSyncResponse` 是純新增，不影響既有訊息。

全部合併完成後，上面的 commit 清單與合併順序就沒有維護價值，整份文件可以刪除。
