# 工具總覽

這頁只做索引。每個 `tools/` 的使用流程、參數與失敗判讀，改看對應的獨立文檔。

## 使用原則

- 先找對應工具文檔，再跑工具。
- 運維工具入口分三個，不帶參數都會列出子命令：版控內 `go run ./tools/pja <子命令>` 只有 `configartifact`／`configaudit`／`releasemanifest`（CI 與部署用）；其餘維運工具（staterepair、datasurgeon、supportdiag、`flow replay`／`flow sample` 等）走 `go run ./tools/private/pja <子命令>`；壓測工具走 `go run ./tools/private/pjaload <loadtest|capacityforecast>`。`tools/private/` 不在版控，沒有該目錄的 clone 跑不了後兩者。
- `cmd/world/tools/topologybaseline`、`cmd/world/tools/variablemigrate` 依賴 World 內部套件，不在 `pja` 內，仍各自獨立執行。
  - 兩者的 `-dsn` 預設為空，解析後才退回環境變數 `WORLD_MYSQL_DSN`（`-h` 不會印出密碼）；漏 `-dsn` 與漏模式是兩種不同錯誤訊息，錯誤前綴工具名，被訊號中斷（Ctrl+C／SIGTERM）結束碼 130，其餘失敗為 1（兩者的 `main` 都只是呼叫 `run(args, stdout, stderr) int`，結束碼語意不變，用法錯誤為 2、`-h` 為 0）；收到第一個訊號後恢復預設訊號處理，工具關機卡住時再按一次 Ctrl+C 可強制結束。
- `pja` 的 `configartifact`／`configaudit`／`releasemanifest` 結束碼一致：用法錯誤（多餘位置參數、缺或未知子命令、旗標解析失敗、`configartifact -switch-version ""`）回 2，`-h`／`--help` 回 0，執行失敗回 1；`pja help`、`pja releasemanifest help` 同樣回 0，`pja` 與 `releasemanifest` 的頂層用法印 stdout，子命令旗標層的 `-h`（`flag` 套件預設）仍印 stderr。服務本體（`startup.Main`）與 `topologybaseline`、`variablemigrate` 同樣拒絕多餘位置參數（避免漏寫 `-config` 時默默用 dev 設定啟動）。
- 能 `-json`、`-output`、`-dry-run`、`-validate` 就先看一遍；`configartifact` 發布類模式有 `-dry-run`（只驗來源與換版規則、不寫 releases 與 `current.json`，輸出 `dry_run=true`；不可與 `-switch-version`、`-verify-topology-lineage` 併用），`scripts/publish-data-config.ps1 -DryRun` 會轉成它。
- 需要統一入口時，優先走 `scripts/private/p0-daily-check.ps1`（不在版控）。
- 工具總覽只留入口，不再重複各工具的細節。

## 結束碼與旗標錯誤

- 上述結束碼語意（2、130 等）只對編譯後的 binary（`go build -o`、`make` 目標產物）成立；`go run ./tools/pja ...` 一律把子程序的任何非零結束碼壓成 1，只在 stderr 印 `exit status N`。需要區分 2、130 與 1 的腳本或 CI，請先 `go build` 再執行 binary。目前 `scripts/*.ps1`、`scripts/*.sh`、`.gitlab-ci.yml` 都只檢查是否非零，不受影響。
- World 維運工具（`cmd/world/tools/*`）被 SIGINT／SIGTERM 取消時以 130 結束（比照 shell 慣例），其餘錯誤以 1 結束；第二個訊號直接強制結束。經 `go run` 執行時 `go` 只保留「非 0」並印 `exit status N`，要判斷是被中斷還是一般失敗，看該行訊息或改用編譯後的執行檔。
- 服務與工具的啟動旗標錯誤用結束碼 2：`-protocol-record` 寫錯（如 `ture`，接受 `on／off／yes／no／true／false` 等）與 `LOG_LEVEL`、`LOG_FORMAT` 環境變數寫錯都是用法錯誤，錯誤訊息標明來源（例如 `(from env LOG_LEVEL)`）。`-version` 優先處理，不會被與版本無關的環境變數寫錯擋住。

## 本機私人工具

`tools/private/` 放個人使用、不進 git 的工具，與 `tools/` 其餘工具同屬 `local/server` module，可 import `internal/*`。私有工具清單以目錄實況為準（30 餘個：`pja`／`pjaload` 入口、staterepair 等維運工具、loadtest 與各種 *load 壓測、boardsimulator／itemsim／missionsim 模擬器、opsconsole）。

- 規則：CI、`scripts/`、其他工具與測試**不得**依賴 `tools/private/`；乾淨 clone 必須能 `go build ./...` 與 `go test ./...`。
- 與正式程式共用的規則（例如 `internal/game/simulation`，World 一致性測試也使用）放在 git 內，不放 `tools/private/`。
- 排除方式：`.gitignore` 已列 `tools/private/` 與 `scripts/private/`，`.dockerignore` 也列 `tools/private/`，新 clone／worktree 不需另設 `.git/info/exclude`。

- 驗證：`git check-ignore -v tools/private/<檔案>` 有輸出即生效。
- 改名或刪除符號時要手動同步：CI 與乾淨 clone 編譯不到 `tools/private`，必須用**明確路徑** grep（經 `rtk` 改寫的 `grep` 會略過 gitignore 的 `tools/private`）。第六輪的同步紀錄：`tools/private/boardsimulator/protocol_test.go:27` 的 `boardconfig.BuildingLevel` 改為 `boardconfig.BuildingLevelConfig`（`BuildingPlan.Level` 改 `Config`）；刪除 `mysql.Connect`、`GormLogger`、`ErrorEvent` 前已確認 `tools/private` 無引用，其餘改名（抽獎群組欄位 `LotteryGroupID`、`TurnProgress`→`Progress`、`Session.Invalidated`→`InvalidatedAt` 等）也已 grep 確認無引用。`simulation.Runner` 因 boardsimulator 以 `(simulation.Runner{}).CombatPlayerSnapshot(...)` 呼叫而維持值接收者，改指標接收者會讓它編不過。
- 備份：已 commit 的歷史不會移除；私人工具需另外備份（例如在 `tools/private/` 內自行 `git init`，推到私人倉庫）。
- 測試或工具要讀倉庫內的 `config/data` 等檔案時，用 `pkg/testutil/repo` 的 `repo.Path("config", "data")`，不要依目錄深度寫死 `..` 層數。

## 部署驗收

- `tools/private/s2sprobe`（`-address`、`-server-name`、`-ca`、`-token-file`、`-expect-rejection`）：先確認 S2S TLS 握手，再檢查身份准入是否符合預期，不輸出機密；`scripts/private/check-s2s-docker.ps1` 會編譯並呼叫它。
- `tools/releasemanifest`（`generate`、`verify`；`-release`、`-commit`、`-release-file`、`-config-version-file`、`-migrations-dir`、`-protocol-lock`）：依實際產物（協定產生碼、`config/data/version.json`、migration 鏈）產生並驗證 `pkg/release/release.json`；`-migrations-dir`（預設 `deps/PJA-Database/migrations`）不存在或不是目錄時直接報錯，目錄存在但沒有任何 plan 才視為 database schema `none`；`scripts/docker-release.sh` 建置映像前呼叫。
