# 版本回收策略

這份文檔只講一件事：舊版本何時留、何時砍、何時黑名單。

## 目標

- 不讓 registry / compose / config 一直堆歷史版本
- 出事時保留足夠回退點
- 壞版本先封鎖，不讓它繼續進主鏈路

## 保留層級

### 1. 目前穩定版
~~~~
- 正在對外服務的版本
- 永遠保留

### 2. 上一版穩定版

- 最新可回退版本
- 至少保留到下一次完整升級驗證通過

### 3. 上一個回退點

- `upgrade-compatibility-drill` 驗證過的 rollback tag
- 至少保留 1 個

### 4. 黑名單版

- 曾經出過嚴重 bug 或協定不相容的版本
- 不刪也可以，但不能再被排進 release / deploy

## 回收條件

可以回收的版本，至少要符合：

1. 已被更新版完全取代
2. 已有新的穩定回退點
3. 沒有任何已知流量還在吃這個版本
4. 升級窗口鎖已解除
5. 監控與 smoke 連續通過至少一次

## 黑名單策略

- 協定不相容版本先進 `protocol_version_blacklist`
- image tag 黑名單則留在 release / deploy 流程裡
- 只要被標成黑名單，就不要再當預設 upgrade tag

## 建議保留期

- image tag：至少保留 14 天
- rollback tag：至少保留 2 個穩定版本
- 黑名單版本：保留到復盤結束，之後再決定是否清掉

## 實際操作

1. 先確認 `upgrade-compatibility-drill` 與 smoke 都過
2. 確認新的 stable tag 已部署完成
3. 確認回退點存在且可用
4. 把舊版本從 release / deploy 預設值移除
5. 若舊版本是黑名單，補進封鎖清單
6. 觀察 1 個 release cycle，再做最終回收

## 不要做的事

- 只看 registry 空間就砍版本
- 還沒驗 rollback 就把舊版刪掉
- 黑名單只寫在腦袋裡
- upgrade window 還開著就回收版本
