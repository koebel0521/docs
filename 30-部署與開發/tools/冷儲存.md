# `tools/private/coldstorage`

> 私人工具：原始碼在本機 `tools/private/`（被 `.gitignore` 忽略、不在版控），乾淨 clone 沒有這個工具；沒有時改用各服務診斷埠的 `/ready`、`/metrics`、`/diag/*`（見[SLO 值班流程](../../20-排障與監控/SLO值班流程.md#沒有私人工具時)）。

## 作用
把舊 dead-letter、audit cache、snapshot 類 key 匯出成 JSONL。

## 目的
做冷資料封存與可選 purge。

## 流程
1. 先 `-dry-run` 看 manifest。
2. 確認輸出檔與 pattern。
3. 需要時再加 `-purge -confirm`：匯出後刪除 key。
4. 要放回時用 `-restore <匯出檔> -confirm`；已存在的 key（list 除外）不覆寫，list 若目前內容已包含匯出的整段會略過，重跑不會重複接回。

## purge 的保護
匯出後刪除前，依 Redis 型別先確認內容仍和匯出時相同：string、hash、set 與以 DUMP 匯出的 key 比對內容，list 只移除匯出的開頭那幾筆。匯出後被改動的 key 會保留並列在「skipped」。

## 主要參數
- `-redis`
- `-db`
- `-timeout`
- `-output`：匯出檔路徑；預設 `coldstorage/export-<UTC 時間>.jsonl`，既有檔案一律不覆寫
- `-pattern`：要匯出的 key pattern，可重複指定
- `-purge`：匯出後刪除 key；必須加 `-confirm`
- `-allow-any-pattern`：`-purge` 預設只允許冷資料前綴（`gm:grant_item:deadletter:`、`central:audit:record:`、`fault:archive:`），其他 pattern 需加此旗標
- `-restore`：從匯出檔寫回 Redis，不能與 `-purge` 併用；必須加 `-confirm`
- `-confirm`：確認執行 `-purge` 或 `-restore`
- `-dry-run`：只印 manifest

## 常用指令
- `go run ./tools/private/pja coldstorage -output .\.run\coldstorage\export.jsonl -dry-run`
- `go run ./tools/private/pja coldstorage -restore .\.run\coldstorage\export.jsonl -dry-run`
