# `tools/private/dephealth`

> 私人工具：原始碼在本機 `tools/private/`（被 `.gitignore` 忽略、不在版控），乾淨 clone 沒有這個工具；沒有時改用各服務診斷埠的 `/ready`、`/metrics`、`/diag/*`（見[SLO 值班流程](../../20-排障與監控/SLO值班流程.md#沒有私人工具時)）。

## 作用
一次看 readiness、service class、queue 深度。

## 目的
值班先抓整體健康，再決定要不要往下看細節。

## 涵蓋範圍
本機 `compose.full` 的 central、gate、world、user、lobby、record、chat 七個服務；其中 central、gate、world、record 為 critical。

## 流程
1. 跑一次 health 掃描。
2. 先看 `critical / core / peripheral`。
3. 看到 `degraded` 再往下查 queue 或 async failure。

## 主要參數
- `-timeout`
- `-output`：輸出格式，`table`（預設）或 `json`
- `-fail-on-class`
- `-fail-on-status`：值必須是 `ok`、`degraded`、`down`；`-fail-on-class` 的值必須是 `critical`、`core`、`peripheral`，打錯字以退出碼 2 回報

## 降級判定
- `/ready` 回 503 時錯誤帶出失敗的檢查項目（`503 Service Unavailable: status=fail <檢查項目>`），不再只丟原始 JSON；`opsdiag`、`consistencysnapshot` 同。
- `game_async_failure_total` 只計捨棄類 outcome（`appcore.IsDiscardOutcome`，與告警規則一致：`retry_schedule_failed`、`dead_letter_failed`）；正常的重試排程與進死信不算降級。
- `game_msg_queue_dropped_total`（啟動後累計）任何非零值列入 DegradedReasons（`Summary.MsgQueueDropped`）。

## 常用指令
- `go run ./tools/private/pja dephealth --fail-on-class critical,core --fail-on-status down,degraded`
