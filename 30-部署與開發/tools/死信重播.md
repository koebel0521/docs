# `tools/deadletterreplay`

## 作用
挑選 dead-letter 再送回 queue 或丟棄。

## 目的
處理 retry 仍可恢復的壞命令。

## 流程
1. 先 `-dry-run` 看選到哪批。
2. 再決定 `-replay` 或 `-discard`（兩者互斥），並加 `-confirm` 才會執行。
3. 必要時加 `-retryable` 只看還在預算內的樣本。
4. 重送或丟棄必須以 `-world-id`、`-user-id` 或 `-operation-id` 縮小範圍；確定要處理全部死信時改加 `-all`。

## 主要參數
- `-redis`
- `-db`
- `-timeout`
- `-world-id`
- `-user-id`
- `-operation-id`
- `-replay`：預設關閉，送回 queue
- `-discard`：從死信移除
- `-all`：未指定任何篩選條件時，允許 `-replay`／`-discard` 作用在全部死信
- `-confirm`：確認執行 `-replay` 或 `-discard`
- `-dry-run`
- `-json`
- `-retryable`
- `-limit`

## 常用指令
- `go run ./tools/deadletterreplay -world-id 9 -operation-id grant-op-1 -retryable -dry-run`
