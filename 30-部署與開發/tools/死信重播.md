# `tools/private/deadletterreplay`

> 私人工具：原始碼在本機 `tools/private/`（被 `.gitignore` 忽略、不在版控），乾淨 clone 沒有這個工具；沒有時改用各服務診斷埠的 `/ready`、`/metrics`、`/diag/*`（見[SLO 值班流程](../../20-排障與監控/SLO值班流程.md#沒有私人工具時)）。

## 作用
挑選 dead-letter 再送回 queue 或丟棄。

## 目的
處理 retry 仍可恢復的壞命令。

## 流程
1. 先 `-dry-run` 看選到哪批。
2. 再決定 `-replay` 或 `-discard`（兩者互斥），並加 `-confirm` 才會執行。
3. 必要時加 `-retryable` 只看還在預算內的樣本。
4. 重送或丟棄必須以 `-world-id`、`-user-id` 或 `-operation-id` 縮小範圍；確定要處理全部死信時改加 `-all`。

## 主要參數
- `-redis`
- `-db`
- `-timeout`
- `-world-id`
- `-user-id`
- `-operation-id`
- `-replay`：預設關閉，送回 queue
- `-discard`：從死信移除
- `-all`：未指定任何篩選條件時，允許 `-replay`／`-discard` 作用在全部死信
- `-confirm`：確認執行 `-replay` 或 `-discard`
- `-dry-run`
- `-json`：只印出選到的項目，不能與 `-replay`／`-discard` 併用
- `-retryable`
- `-limit`

## 行為說明
- 指定 `-world-id` 時只處理該 World 的佇列，其他格式異常的 key 不會讓作業失敗；沒指定時遇到異常 key 會中止並回報。
- `-replay` 逐筆處理：死信已被他人處理會略過計數；目標 World 不可用時跳過該 World 其餘項目、死信保留，其他 World 照常重送。結束印出成功／略過／World 不可用筆數，有未處理項目時以非零結束。
- `-discard` 在 `LREM` 前先把選到的死信原始內容寫成 JSON Lines 備份檔（0600、原子寫入），備份失敗就不丟棄。
- `-discard` 輸出「discarded N of M」：N 是 `LREM` 實際移除的筆數，項目已被其他人處理時 N 會小於 M。

## 常用指令
- `go run ./tools/private/pja deadletterreplay -world-id 9 -operation-id grant-op-1 -retryable -dry-run`
