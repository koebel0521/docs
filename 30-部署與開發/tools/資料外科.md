# `tools/private/datasurgeon`

> 私人工具：原始碼在本機 `tools/private/`（被 `.gitignore` 忽略、不在版控），乾淨 clone 沒有這個工具；沒有時改用各服務診斷埠的 `/ready`、`/metrics`、`/diag/*`（見[SLO 值班流程](../../20-排障與監控/SLO值班流程.md#沒有私人工具時)）。

## 作用
修 Redis 內的衍生資料。

## 目的
清掉壞 route、player store、dead-letter 這類 derived data。

## 流程
1. 先選 `-mode`。
2. 不加 `-apply` 先看差異（沒有 `-dry-run` 旗標，預設就是只列出）。
3. 確認後以 `-apply -confirm` 才真的修。

## 主要參數
- `-mode`：`route`（預設）、`playerstore`、`deadletter`
- `-redis`
- `-db`
- `-timeout`
- `-apply`：套用修正；必須加 `-confirm`
- `-confirm`
- `-limit`
- `-world-id`
- `-purge-malformed`

## 死信模式的刪除與備份
- `-purge-malformed` 刪除無法解碼的指令、以及鍵名解析不出 World ID 的整個佇列。刪除前一律先把原始內容寫成 JSON Lines 備份檔（0600、原子寫入）到 `-backup-dir`，備份失敗就不刪。
- 不加 `-apply` 時只列出筆數與「would-delete」，不寫備份也不刪。

## 乾跑預覽範圍
乾跑與 `-apply` 走同一套判斷，預覽列出的就是實際會刪的：
- `playerstore`：`would add`／`would remove` World 成員（要移除的含無法解析、不在期望集合、0、負數與非標準寫法如 `007` 的成員）；完整掃描時另列出 `would delete stale|malformed world set`（鍵名格式錯誤或不屬於任何現存 World 的玩家集合）。
- `route`：列出 `would delete malformed player key`（格式不符的 player key）與 `would delete stale route`（沒有對應 player 的 `routing:*`）。有 `-limit` 時掃描不完整，不列出過期路由，也不清除。
- 逐筆以 `LREM` 移除，中途中斷只會少刪幾筆，重跑會繼續刪剩下的。

## 常用指令
- `go run ./tools/private/pja datasurgeon -mode route`
- `go run ./tools/private/pja datasurgeon -mode route -apply -confirm`
