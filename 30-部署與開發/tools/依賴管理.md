# 依賴管理工具

本專案的 Go 依賴管理工具與流程。

## Makefile 指令速查

| 指令 | 說明 | 需要安裝 |
|------|------|----------|
| `make vuln` | 依賴漏洞掃描 | 無（`go tool -modfile=tools/gotools/go.mod govulncheck`） |
| `make ci-vuln` | CI 等價漏洞掃描 | 無（同上） |
| `make outdated` | 列出有新版的依賴（主 module 與 `tools/gotools` 各一次） | 無（`go list -u -m`） |
| `make deps-size` | 分析 binary 大小分布（以 Central 為代表，輸出 `.run/size-report.html`） | 無（`go tool -modfile=tools/gotools/go.mod gsa`） |
| `make dep-graph` | 產生依賴圖 .run/deps.png | Graphviz `dot`（`modgraphviz` 鎖在 `tools/gotools/go.mod`） |

## 工具模組（`tools/gotools`）：CLI 工具版本鎖定

CLI 工具（golangci-lint、govulncheck、benchstat、goimports、gocover-cobertura）宣告在獨立的 `tools/gotools/go.mod`，不進主 module 的 `go.mod`／`go.sum`。`make`、pre-commit 與 GitLab CI 都經這個 modfile 執行同一版本，不需要另外 `go install`。

### 鎖定的工具

| 工具 | 套件路徑 | 用途 |
|------|----------|------|
| `golangci-lint` | `github.com/golangci/golangci-lint/v2/cmd/golangci-lint` | 靜態分析與格式化 |
| `govulncheck` | `golang.org/x/vuln/cmd/govulncheck` | 漏洞掃描 |
| `benchstat` | `golang.org/x/perf/cmd/benchstat` | Benchmark 比較 |
| `goimports` | `golang.org/x/tools/cmd/goimports` | import 整理（pre-commit） |
| `gocover-cobertura` | `github.com/boumenot/gocover-cobertura` | CI 覆蓋率轉換 |

### 執行

```bash
go tool -modfile=tools/gotools/go.mod golangci-lint run ./...
go tool -modfile=tools/gotools/go.mod govulncheck ./...
```

不加 `-modfile=tools/gotools/go.mod` 在根目錄執行會得到 `no such tool`。`go tool cover` 等標準工具不受影響。

### 升級

```bash
go get -C tools/gotools -tool github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.13.2
go -C tools/gotools mod tidy
```

### 新增工具

1. `go get -C tools/gotools -tool <path>@<version>`
2. `go -C tools/gotools mod tidy`
3. 以 `go tool -modfile=tools/gotools/go.mod <name>` 呼叫

### 注意

- 不要在根目錄對工具 modfile 執行 `go mod tidy -modfile=...`：根目錄的套件會被算進工具模組，tidy 會拉進整棵專案的依賴。工具模組一律在 `tools/gotools` 目錄內 tidy。
- CI 的 `lint` job 與 `make ci-lint` 會在 `tools/gotools` 內 tidy，並檢查 `go.mod`／`go.sum` 與工具模組的 `go.mod`／`go.sum` 都沒有未提交的改動。

## govulncheck: 漏洞掃描

### 使用

```bash
# 掃描整個 module
go tool -modfile=tools/gotools/go.mod govulncheck ./...

# 或透過 Makefile
make vuln
```

### 注意

- GitLab 的 `govulncheck` job 執行 `go tool -modfile=tools/gotools/go.mod govulncheck ./...`，有可達漏洞即擋下合併
- govulncheck 由 `tools/gotools/go.mod` 的 `tool` directive 管理，目前為 `golang.org/x/vuln v1.8.0`（其 go.mod 宣告 `go 1.26.0`，與本專案的 1.27.0 相容）
- 本機開發時若遇到 `package requires newer Go version` 錯誤，表示某個工具版本尚未追上專案使用的 Go 版本，可升級該工具或暫緩升級 Go，不影響專案建置

## 過時依賴追蹤

不需另裝工具，`make outdated` 直接用 `go list -u -m` 列出主 module 與 `tools/gotools/go.mod` 中有新版本的依賴（indirect 會標註）：

```bash
go list -u -m -f '{{if .Update}}{{.Path}} {{.Version}} -> {{.Update.Version}}{{if .Indirect}} (indirect){{end}}{{end}}' all
go list -modfile=tools/gotools/go.mod -u -m -f '{{if .Update}}{{.Path}} {{.Version}} -> {{.Update.Version}}{{if .Indirect}} (indirect){{end}}{{end}}' all

# 或透過 Makefile
make outdated
```

## gsa: 二進位大小分析

`go-size-analyzer`（`gsa`）鎖在 `tools/gotools/go.mod`，不需另行安裝。`make deps-size` 以 Central 為代表建置後輸出 HTML 報告：

```bash
go build -trimpath -o .run/central ./cmd/central
go tool -modfile=tools/gotools/go.mod gsa -f html -o .run/size-report.html .run/central

# 或透過 Makefile
make deps-size
```

依賴圖同樣由 `tools/gotools/go.mod` 的 `modgraphviz` 產生，只需另裝 Graphviz `dot`：

```bash
go mod graph | go tool -modfile=tools/gotools/go.mod modgraphviz | dot -Tpng -o .run/deps.png
# 或 make dep-graph
```

## golangci-lint 依賴檢查

`.golangci.yml` 已啟用以下依賴相關 linter：

| Linter | 作用 |
|--------|------|
| `gomodguard` | 封鎖 `log/slog`，強制使用 `github.com/rs/zerolog` |
| `gomoddirectives` | 不允許任何 `replace`（白名單為空），`retract` 須附原因 |

## Pre-commit 自動檢查

`.pre-commit-config.yaml` 的 `golangci-lint` 是 local hook，以 `go tool -modfile=tools/gotools/go.mod golangci-lint run --new-from-rev HEAD --fix` 只檢查相對 HEAD 的改動；`make lint` 與 CI 則檢查全樹（`.golangci.yml` 不設 `new-from-rev`）。

`go-mod-tidy` local hook 的作用：

- 偵測 `go.mod` / `go.sum` 變更後，在根目錄執行 `go mod tidy`
- 工具模組 `tools/gotools` 目前只在 CI 檢查 tidy，pre-commit 尚未涵蓋（待補）
- 若 tidy 後仍有未提交的變更，commit 會被擋下並提示執行 `go mod tidy`
- 安裝：`pre-commit install`

## 依賴圖視覺化

```bash
make dep-graph
```

產生 `.run/deps.png`，可用於理解依賴引入鏈。

## Renovate 自動更新設定

Renovate 設定在 `renovate.json`，運作方式：

| 類型 | 行為 | 標籤 |
|------|------|------|
| minor/patch | 自動開 PR，CI 通過後 auto-merge | 無 |
| major | 開 PR 但不 auto-merge，需人工審查 | `major-update`, `needs-review` |
| 漏洞修復 | 優先 auto-merge（不受 schedule 限制） | `security` |

## 定期維護流程

1. **每週一**：Renovate 自動開 minor/patch 更新 PR，CI 通過後 auto-merge
2. **發版前**：執行 `make vuln` 掃描 CVE
3. **每月**：執行 `make outdated` 檢視 major 更新 backlog
4. **每季**：執行 `make deps-size` 監控 binary 膨脹趨勢

## Module 現狀

專案有兩個 module：

- 主 module `local/server`（根目錄）：`cmd/`、`internal/`、`pkg/`、`integration/` 與 `tools/` 下的運維工具（`tools/gotools` 除外）。
- 工具 module `local/server/tools/gotools`（`tools/gotools/go.mod`）：只宣告 CLI 工具，見上方「工具模組」。

服務邊界靠 Go 的 `internal` 規則（`cmd/<service>/internal/`）加上 `pkg/cmd_boundary_test.go` 維持。`tools/pja` 把各運維工具編成單一 binary，子命令直接分派到各工具套件，見[工具總覽](../工具總覽.md)。
