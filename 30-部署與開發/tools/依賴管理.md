# 依賴管理工具

本專案的 Go 依賴管理工具與流程。

## Makefile 指令速查

| 指令 | 說明 | 需要安裝 |
|------|------|----------|
| `make vuln` | 依賴漏洞掃描 | `govulncheck` |
| `make ci-vuln` | CI 等價漏洞掃描 | `govulncheck` |
| `make outdated` | 列出過時 direct 依賴 | `go-mod-outdated` |
| `make deps-size` | 分析 binary 大小分布 | `goweight` |
| `make dep-graph` | 產生依賴圖 .run/deps.png | `modgraphviz` + Graphviz `dot` |

## tools.go: CLI 工具版本鎖定

本專案使用 `tools.go`（專案根目錄）鎖定常用 CLI 工具版本。該檔案透過 `//go:build tools` 建置標籤確保不編入正式程式碼。

### 鎖定的工具

| 工具 | go.mod 套件路徑 | 用途 |
|------|----------------|------|
| `golangci-lint` | `github.com/golangci/golangci-lint/cmd/golangci-lint` | 靜態分析 |
| `govulncheck` | `golang.org/x/vuln/cmd/govulncheck` | 漏洞掃描 |
| `benchstat` | `golang.org/x/perf/cmd/benchstat`（由 `tools/` 模組管理） | Benchmark 比較 |

### 安裝鎖定版本

```bash
# 按照 go.mod 鎖定的版本安裝
go install github.com/golangci/golangci-lint/cmd/golangci-lint
go install golang.org/x/vuln/cmd/govulncheck
```

不加 `@latest` 或 `@版本` 時，`go install` 會使用 `go.mod` 中記錄的版本。

### 新增工具

1. 在 `tools.go` 加入空白 import
2. 執行 `go mod tidy`
3. 執行 `go install <path>`（不加 `@` 後綴）

## govulncheck: 漏洞掃描

### 安裝

```bash
go install golang.org/x/vuln/cmd/govulncheck@latest
```

### 使用

```bash
# 掃描所有模組
govulncheck ./...

# 或透過 Makefile
make vuln
```

### 注意

- CI 已用 `golang/govulncheck-action@v1` 自動執行（含 `continue-on-error`）
- govulncheck 由 `go.mod` 的 `tool` directive 管理，目前為 `golang.org/x/vuln v1.8.0`（其 go.mod 宣告 `go 1.26.0`，與本專案的 1.26.3 相容）
- 本機開發時若遇到 `package requires newer Go version` 錯誤，表示某個工具版本尚未追上專案使用的 Go 版本，可升級該工具或暫緩升級 Go，不影響專案建置

## go-mod-outdated: 過時依賴追蹤

### 安裝

```bash
go install github.com/psampaz/go-mod-outdated@latest
```

### 使用

```bash
# 列出所有有更新的 direct 依賴
go list -u -m -json all | go-mod-outdated -update -direct

# 或透過 Makefile
make outdated
```

## golangci-lint 依賴檢查

`.golangci.yml` 已啟用以下依賴相關 linter：

| Linter | 作用 |
|--------|------|
| `gomodguard` | 封鎖 `log/slog`，強制使用 `github.com/rs/zerolog` |
| `gomoddirectives` | `replace` 白名單（`github.com/koebel0521/project`），`retract` 須附原因 |

## Pre-commit 自動檢查

`.pre-commit-config.yaml` 已加入 `go-mod-tidy` local hook，作用：

- 偵測 `go.mod` / `go.sum` 變更後，自動執行所有 workspace module 的 `go mod tidy`
- 若 tidy 後仍有未提交的變更，commit 會被擋下並提示執行 `go mod tidy`
- 安裝：`pre-commit install`

## 依賴圖視覺化

make dep-graph

## Renovate 自動更新設定

Renovate 設定在 `renovate.json`，運作方式：

| 類型 | 行為 | 標籤 |
|------|------|------|
| minor/patch | 自動開 PR，CI 通過後 auto-merge | 無 |
| major | 開 PR 但不 auto-merge，需人工審查 | `major-update`, `needs-review` |
| 漏洞修復 | 優先 auto-merge（不受 schedule 限制） | `security` |

## 定期維護流程

1. **每週一**：Renovate 自動開 minor/patch 更新 PR，CI 通過後 auto-merge
2. **發版前**：執行 `make vuln` 掃描 CVE
3. **每月**：執行 `make outdated` 檢視 major 更新 backlog
4. **每季**：執行 `make deps-size` 監控 binary 膨脹趨勢

## Module 現狀

### Module 數量

全專案只有 **1 個 module**：根目錄的 `github.com/koebel0521/project`。7 個 app、`pkg/`、
`tools/` 都在同一 module 內，已無 `go.work`。

- 原本 7 個 app 各自是獨立 module（共 9 個）並以 `go.work` 聯集；併回單一 module
  後，服務邊界改由 Go 的 `internal` 規則（`cmd/<service>/internal/`）加上
  `pkg/cmd_boundary_test.go` 維持。
- `go.mod` 同時包含應用與工具依賴；工具以 `tool` directive 宣告，用
  `go tool <name>` 執行。

tools 目錄的所有工具共用以下 direct deps：

| 依賴 | 使用工具數 |
|----------|-----------|
| `github.com/stretchr/testify` | 全部 17 個 |
| `github.com/koebel0521/project` | 7 個 |
| `github.com/alicebob/miniredis/v2` | 5 個 |
| `github.com/spf13/viper` | 3 個 |
| `golang.org/x/sync` | 2 個 |
| `gopkg.in/yaml.v3` | 1 個 |
