# `tools/private/flowreplay`

> 私人工具：原始碼在本機 `tools/private/`（被 `.gitignore` 忽略、不在版控），乾淨 clone 沒有這個工具；沒有時改用各服務診斷埠的 `/ready`、`/metrics`、`/diag/*`（見[SLO 值班流程](../../20-排障與監控/SLO值班流程.md#沒有私人工具時)）。

## 作用
重放 login / logout / recovery fixture。

## 目的
重現事故或驗證回歸樣本。

## 流程
1. 先載入 fixture。
2. 視需要給 gate 位址。
3. `-dry-run` 時只驗證 fixture。

fixture 步驟的 `expect` 在載入時驗證（`regressionsample -validate` 同規則）：名稱同 `errcode.MetricOutcomeFromAuthResultCode`（含 `protocol_mismatch`），另保留舊別名 `logged_out`（等同 `already_logged_out`）；空白與 `any` 都表示不比對回覆碼；其他名稱（例如打錯的 `sucess`）在載入時就被拒絕，不必連上 Gate 才失敗。

## 主要參數
- `-fixture`
- `-gate`
- `-dry-run`
- `-client-contract`：版本握手帶的 client contract；預設 0 表示沿用 `pkg/release/release.json`，與 Server 不同時 Gate 在握手回強制更新，重放必定失敗

## 常用指令
- `go run ./tools/private/pja flow replay -fixture .\tools\regressionsample\samples\login_logout.json -dry-run`
