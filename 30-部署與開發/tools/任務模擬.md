# `tools/missionsim` 與任務測試網頁

## 作用
離線重播一份任務腳本，逐步印出任務狀態。不連資料庫、MQ、World。

## 目的
- 企劃不必等真實時間，就能驗證每日／每週重置、限時失敗、失敗冷卻、領獎冷卻。
- 工程師用同一份腳本重現問題，也能放進回歸測試。

## 為什麼準
規則全部呼叫 `internal/game/mission`，World 也呼叫同一份：

- `Load`：決定輪次與重置週期。
- `ApplyEvent`、`ActivateManual`：逾時、失敗重試、啟用、累計進度。
- `CompletionOf`、`ClaimCooldown`、`ManualRewardGroup`：完成後的待領獎勵與領獎冷卻。

改規則只改一處，工具與 World 一起變。

## 入口
- 網頁（企劃）：`tools/boardsimulator\run.bat` 啟動後開 `http://localhost:5173/mission.html`。
- CLI（工程師、CI）：

```bash
go run ./tools/missionsim -data config/data -scenario scenario.json
```

任一步執行失敗或 `expect` 不符，印完結果後以非 0 結束。

## 腳本格式
```json
{
  "missionId": 1001,
  "start": "2026-10-04T06:00:00Z",
  "seed": 1,
  "resetZone": "Asia/Taipei",
  "resetHour": 5,
  "variables": { "10": 5 },
  "steps": [
    { "op": "activate" },
    { "op": "event", "metric": "ItemUseCount", "target": 1001, "amount": 2,
      "expect": { "status": "active", "progress": [2] } },
    { "op": "advance", "duration": "1d" },
    { "op": "claim" }
  ]
}
```

| `op` | 說明 | 欄位 |
|------|------|------|
| `activate` | 手動接取 | 無 |
| `event` | 送一筆權威事件 | `metric`（`ItemUseCount`、`CombatWinCount`）、`target`、`amount` |
| `advance` | 推進虛擬時鐘 | `duration`（Go 時間長度，另支援整數天如 `1d`） |
| `claim` | 領獎 | `choice`（自選 SubID，0 為抽獎）、`cycle`（0 為最新待領） |
| `setVariable` | 改玩家變數 | `variable`、`value` |

`expect` 欄位都選填：`status`、`progress`、`completionCount`、`cycle`、`pendingClaims`、`claimed`。`status` 值為 `available`、`active`、`completed`、`failed`。

## 行為說明
- 每次從頭重播整份腳本，不保存 session。
- 虛擬時鐘從 `start` 起算，只有 `advance` 會推進。
- 逾時失敗在 `advance` 後結算，對應玩家讀取任務列表時寫成失敗。
- `resetZone`、`resetHour`、`resetMinute` 對應 World 的 `mission_reset` 設定。
- 抽獎使用 `seed`，相同種子結果相同。
- 自動領獎的任務在完成事件之後立刻領獎，與事件消費端一致。

## 不涵蓋
- 保存與還原、設定版本相容、事件 ID 去重、MQ 重送：由 `cmd/world/internal/mission` 的整合測試負責。
- 依賴盤面狀態的條件：條件只支援變數運算元，缺值取變數表預設值。
- 一個事件同時推進多個任務：一次只模擬一個任務。
