# PJA-Config Server 配置資料同步

PJA-Config 的 Server 生成物不是服務 YAML，而是由 Luban 產生的 Go 程式碼與二進位資料。建置 PJA-Server 前，先從 PJA-Config 匯入同一批輸出。

## 目標目錄

```text
PJA-Server/
├─ config/data/
│  ├─ *.bytes
│  └─ version.json
└─ pkg/dataconfig/generated/
   └─ *.go
```

`config/dev/`、`config/docker/` 與 `docker/prod/config/` 保留給服務環境 YAML，不放 Luban 資料。

## 使用方式

### 雙擊工具（建議）

直接雙擊：

```text
scripts\Build-And-Sync-Config.cmd
```

工具會先建置 PJA-Config，再將結果同步到目前的 PJA-Server。PJA-Config 專案目錄的選擇順序是：`-ConfigRoot` 參數 > 子模組 `deps/PJA-Config`（存在就直接用）> 環境變數 `PJA_CONFIG_ROOT` > 跳出視窗讓你選擇。注意**子模組存在時，只設 `PJA_CONFIG_ROOT` 不會生效**，工具會默默改建子模組並同步它的生成物；要從本機 PJA-Config 來源同步，必須用 `-ConfigRoot`（例如 `.\scripts\Build-And-Sync-Config.ps1 -ConfigRoot D:\workspace\PJA-Config`）。

在 PJA-Server 目錄執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\sync-data-config.ps1
```

預設來源是子模組 `deps\PJA-Config\Output\Server`。若來源在其他位置（例如尚未推送的本機 PJA-Config）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\sync-data-config.ps1 `
  -ConfigOutput C:\path\to\PJA-Config\Output\Server
```

也可以只指定 `PJA-Config` 根目錄，或設定環境變數，適合每個人的工作區路徑不同的情況：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\sync-data-config.ps1 `
  -ConfigRoot D:\workspace\PJA-Config
```

```powershell
$env:PJA_CONFIG_ROOT = "D:\workspace\PJA-Config"
powershell -ExecutionPolicy Bypass -File .\scripts\sync-data-config.ps1
```

`sync-data-config.ps1` 的來源優先順序為 `-ConfigOutput`、`-ConfigRoot`、`PJA_CONFIG_ROOT`，最後才是子模組 `deps/PJA-Config`（與上面的雙擊工具順序不同：這支腳本環境變數優先於子模組）。

一般同步只會新增或覆蓋檔案；要清理已不存在的舊生成檔，明確加入 `-Clean`：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\sync-data-config.ps1 -Clean
```

同步腳本會檢查 `version.json` 的 `config_version`，並將它複製到 `config/data/version.json`。`config/data` 與 `pkg/dataconfig/generated` 都在版控內（不在 `.gitignore`），同步後要連同子模組指標一併提交，使生成物與 `deps/` 一致；CI 不會在建置前重新同步。發版 tag 的 `release-info` job 以 `releasemanifest verify -config-repo deps/PJA-Config` 守門：`config_version` 必須等於 `deps/PJA-Config` 子模組指標或是它的祖先，否則發版失敗。
