# PJA-Config Server 配置資料同步

PJA-Config 的 Server 生成物不是服務 YAML，而是由 Luban 產生的 Go 程式碼與二進位資料。建置 PJA-Server 前，先從 PJA-Config 匯入同一批輸出。

## 目標目錄

```text
PJA-Server/
├─ config/data/
│  ├─ *.bytes
│  └─ version.json
└─ pkg/dataconfig/generated/
   └─ *.go
```

`config/dev/`、`config/docker/` 與 `config/prod/` 保留給服務環境 YAML，不放 Luban 資料。

## 使用方式

### 雙擊工具（建議）

直接雙擊：

```text
tools\Build-And-Sync-Config.cmd
```

工具會先建置 PJA-Config，再將結果同步到目前的 PJA-Server。若兩個專案不是同層資料夾，會跳出視窗讓你選擇 PJA-Config 專案目錄。

在 PJA-Server 目錄執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\sync-data-config.ps1
```

預設來源是相鄰的 `PJA-Config\Output\Server`。若來源在其他位置：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\sync-data-config.ps1 `
  -ConfigOutput C:\path\to\PJA-Config\Output\Server
```

也可以只指定 `PJA-Config` 根目錄，或設定環境變數，適合每個人的工作區路徑不同的情況：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\sync-data-config.ps1 `
  -ConfigRoot D:\workspace\PJA-Config
```

```powershell
$env:PJA_CONFIG_ROOT = "D:\workspace\PJA-Config"
powershell -ExecutionPolicy Bypass -File .\scripts\sync-data-config.ps1
```

來源優先順序為 `-ConfigOutput`、`-ConfigRoot`、`PJA_CONFIG_ROOT`，最後才是相鄰的 `PJA-Config`。

一般同步只會新增或覆蓋檔案；要清理已不存在的舊生成檔，明確加入 `-Clean`：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\sync-data-config.ps1 -Clean
```

同步腳本會檢查 `version.json` 的 `config_version`，並將它複製到 `config/data/version.json`。生成目錄已列入 `.gitignore`，由 CI 或本機在 Server 建置前同步。
