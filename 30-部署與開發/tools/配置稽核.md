# `tools/configaudit`

## 作用
檢查 `.env.prod.example`、compose、prod config、Prometheus / Grafana。

## 目的
先抓環境分叉，再查 runtime 問題。

## 流程
1. 先跑審核。
2. 再看哪一份設定不一致。
3. 把不一致的地方修回來。

## 主要參數
- `-env`
- `-compose-full`
- `-compose-prod`
- `-prod-central`
- `-prod-world`
- `-prod-gate`
- `-prod-lobby`
- `-prometheus`
- `-datasource`

## 檢查項目
- 環境：`.env.prod.example` 列出部署必填的鍵（資料庫、RabbitMQ、Redis、Grafana、映像等）。
- compose：開發與正式 compose 的埠綁定、World 故障注入（開發有、正式不得有）、所有 compose 的 bind mount 來源存在、正式 World 掛載 `/app/config/data`。
- 服務設定：正式 Central 監聽 `60001`（world）、`60002`（gate）、`60003`（chat）、`60004`（lobby），World、Gate、Lobby 的埠；`config/dev`、`config/docker`、`docker/prod/config` 三套鍵集合雙向一致（dev 有而其他環境沒有的鍵除 `devOnlyKeys` 外報錯，其他環境有而 dev 沒有的鍵除 `nonDevKeys`（Redis 密碼／DB、Central 對外位址與灰度分流、OTel、Record `addr`／`http_token`）外也報錯）；三套環境的 listen／dial 路由（`world->central`、`gate->world`、`gate->central`、`gate->chat`、`user->gate`、`user->lobby`、`chat->central`、`lobby->central`，共用 `tools/internal/configroute`）。
- 監控：依 `debug.Endpoints()` 稽核四份 Prometheus 設定（`docker/monitoring/prometheus.yml`、`prometheus.prod.yml`（無 user）、`prometheus.dev.yml` 與 `monitoring/prometheus/prometheus.yml`（後兩份抓宿主機）），每個 job 的 target 集合必須恰好一致；Grafana datasource；告警規則與面板 PromQL 引用的全部指標名（排除函式、關鍵字、標籤、字串、時長與 `go_`／`process_`／`up` 等外部指標）都須由程式或錄製規則產生；規則檔沒有 `groups` 或面板 glob 沒有檔案視為錯誤。

## 常用指令
- `go run ./tools/configaudit`
