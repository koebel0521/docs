# `tools/configaudit`

## 作用
檢查 `.env.prod.example`、compose、prod config、Prometheus / Grafana。

## 目的
先抓環境分叉，再查 runtime 問題。

## 流程
1. 先跑審核。
2. 再看哪一份設定不一致。
3. 把不一致的地方修回來。

## 主要參數
- `-repo-root`（相對路徑的基準目錄，預設為工作目錄）
- `-env`
- `-compose-full`
- `-compose-prod`
- `-prod-central`
- `-prod-world`
- `-prod-gate`
- `-prod-lobby`
- `-prometheus`
- `-datasource`

## 檢查項目
- 環境：`.env.prod.example` 列出部署必填的鍵（資料庫、RabbitMQ、Redis、Grafana、映像等）。
- compose：開發與正式 compose 的埠綁定、World 故障注入（開發有、正式不得有）、所有 compose 的 bind mount 來源存在、正式 compose 未列入預期清單的額外埠必須綁 `127.0.0.1`（開發 compose 不限）、正式 World 掛載 `/app/config/data`。
- 服務設定：正式 Central 監聽 `60001`（world）、`60002`（gate）、`60003`（chat）、`60004`（lobby），World、Gate、Lobby 的埠；`config/dev`、`config/docker`、`docker/prod/config` 三套鍵集合雙向一致（dev 有而其他環境沒有的鍵除 `devOnlyKeys` 外報錯，其他環境有而 dev 沒有的鍵除 `nonDevKeys`（Redis 密碼／DB、Central 對外位址與灰度分流、OTel、Record `addr`／`http_token`）外也報錯）；三套環境的 listen／dial 路由（`world->central`、`gate->world`、`gate->central`、`gate->chat`、`user->gate`、`chat->central`、`lobby->central`，共用 `tools/internal/configroute`）。沒有 `user->lobby` 列：Client 會連 Lobby，位址由 Client 端自行設定，`user.yaml` 不再有 `lobby_url`，Lobby `addr` 的埠（8080）仍由服務設定檢查。
- 讀設定：`configaudit` 與 `configroute.Check`／`Load` 與服務啟動走同一條路徑 `bootstrap.ReadConfigPair` 加 `bootstrap.ValidateLoaded`（含八進位整數、鍵衝突、`id` 嚴格解析與環境變數遮蔽檢查），所以 `db: 010`、缺 `id` 或本機環境變數遮蔽整段設定在稽核與在服務啟動同樣失敗；測試 fixture 的設定檔必須有頂層 `id`。
- 鍵集合除了 dev↔docker、dev↔prod，也互比 docker↔prod（docker 有正式沒有的鍵除 `devOnlyKeys` 與 `dockerOnlyKeys`〔Record 的 `addr`、`http_token`〕外報錯，反向除 `nonDevKeys` 外報錯）；設了 `otel.exporter` 的設定檔必須明示 `otel.sample_rate`（`otel.sample_rate` 只留在 `nonDevKeys`，沒有 `otel` 區段的服務不要求）。
- 腳本對帳測試：`scripts/docker-full-up.sh` 提示的 Gate user 埠（62001）與 Record http 埠（6070）、`scripts/world-autoscale.ps1` 改寫 `public_addr` 的 `world:61001` 規則，都從 `config/docker` 讀值比對；`scripts/private` 不進版控，不在範圍內。
- 監控：依 `debug.Endpoints()` 稽核四份 Prometheus 設定（`docker/monitoring/prometheus.yml`、`prometheus.prod.yml`（無 user）、`prometheus.dev.yml` 與 `monitoring/prometheus/prometheus.yml`（後兩份抓宿主機）），每個 job 的 target 集合必須恰好一致；Grafana datasource；告警規則與面板 PromQL 引用的全部指標名（排除函式、關鍵字、標籤、字串、時長與 `go_`／`process_`／`up` 等外部指標）都須由程式或錄製規則產生；規則檔沒有 `groups` 或面板 glob 沒有檔案視為錯誤。

另有測試 `TestEveryEnvironmentVariableReadByServicesIsDocumented`（`go test ./tools/internal/configaudit`，CI 也會執行）：`cmd`、`pkg`、`internal` 非測試程式以 `os.Getenv`／`os.LookupEnv` 讀的環境變數，都必須出現在主倉的 docker、config、scripts、monitoring、README／AGENTS 或 `.env` 範本；`docs/` 與 `.run` 不算，新增環境變數須在主倉留下說明。讀取端改引用常數時（例如 `debug.PprofBasicAuthEnv` 對應 `DEBUG_PPROF_BASIC_AUTH`）掃不到字面值，測試把這類常數直接列入合法清單。

## 常用指令
- `go run ./tools/pja configaudit`
