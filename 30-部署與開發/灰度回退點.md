# 灰度回退點

灰度回退點是先定好「做到哪一步，出事就退回哪一步」。

目的不是漂亮。目的是：

- 出事時不用現場想
- 縮小回滾範圍
- 讓 canary / rolling / config change 都有可停點

## 什麼是回退點

回退點是一個可驗證的 checkpoint，通常要同時滿足：

1. 已完成某一小步變更
2. 已看過最基本 smoke / ready
3. 若下一步壞掉，可以直接退回這一步

## 在這專案裡常見回退點

### 1. Canary 流量切片

- `traffic_slice_percent = 1` 可以當第一個回退點
- `5`、`10` 可以是放量前的下一個回退點
- 一旦指標掉，就先退回 0%

### 2. Rolling upgrade

- `central` 升完後先停
- `world` 升完後再看一次
- `gate` 最後升
- 每一台升完都是一個回退點

### 3. 設定變更

- `protocol_version_blacklist`
- `feature flag`
- `drain` / `limit` / `timeout`

這些都要先定「改前」與「改後」的回退點。

### 4. 資料變更

- migration apply 前
- migration rollback 前
- 任何 schema / key 改動都要先定回退點

## 好回退點的條件

1. 小
2. 可逆
3. 可觀察
4. 已驗證
5. 不會把壞狀態擴散到全站

## 不好的回退點

- 全量流量已切完才想回退
- code + config + 流量一起改
- 只看功能通不通，不看 queue / latency / reconnect
- 沒有驗 rollback，就先把舊版砍掉

## 實務做法

1. 先列操作步驟
2. 每一步後面寫回退動作
3. 每一步後面寫觀察指標
4. 每一步都要能單獨停

範例：

1. 上 `central`
2. 跑 smoke
3. 若正常，再上 `world`
4. 跑 smoke
5. 若正常，再上 `gate`
6. 跑 smoke
7. 最後才放大 canary
