# `scripts/upgrade-compatibility-drill.ps1`

## 作用
驗證升版（整批替換）與 rollback 相容性。

## 目的
確認同一發版的服務整批替換後與回退後，服務還能維持可用。

服務之間的 `ServiceHello` 會比對發版身分（`Release`、`ServerCommit`、`ProtocolSchemaHash`、`ClientContract`），任一項不一致就斷線（見 [版本握手與強制更新](../../10-核心流程/版本握手與強制更新.md#服務之間)）。因此不同發版不能逐台混跑，正式升版須整批替換所有服務。

## 流程
1. 指定 `-NewTag`。
2. 預設：把正式 compose 的六個自建服務（`central`、`record`、`world`、`chat`、`gate`、`lobby`）映像一起換成 `-NewTag`，一次 `up --force-recreate` 後跑 `production-smoke.ps1`。
3. 必要時再 rollback（同樣整批換回原映像後跑 smoke）。
4. 可選擇加 monitoring 驗證。

### 逐服務重建（`-PerService`）
只允許同一發版：`-NewTag` 必須與 env 檔六個 `*_IMAGE` 的現行 tag 一致，否則直接報錯。用途是驗證單一服務重建不影響可用性。依 `central -> record -> world -> chat -> gate -> lobby` 順序重建（被依賴的一方先），每重建一個服務跑一次 smoke；回退順序相反。

## 主要參數
- `-ComposeFile`
- `-EnvFile`
- `-NewTag`
- `-PerService`：改為逐服務重建，限同一發版
- `-Rollback`
- `-CheckMonitoring`
- `-NoLock`
- `-ConfirmDrill`：非 `-DryRun` 時必須加，否則拒絕執行（預設 compose／env 是正式環境）
- `-DryRun`

失敗時只回退已被重建過的服務（整批模式即全部六個），沒動到的服務不會被重建。
