# `scripts/upgrade-compatibility-drill.ps1`

## 作用
驗證 rolling upgrade 與 rollback 相容性。

## 目的
確認舊新混跑時，服務還能維持可用。

## 流程
1. 指定 `-NewTag`。
2. 依 `central -> record -> world -> chat -> gate -> lobby` 順序升級正式 compose 的六個自建服務；被依賴的一方先升級（Gate 連 Central／World／Chat，Record 消費 World 的事件），玩家入口 Lobby 最後；回退順序相反。
3. 必要時再 rollback。
4. 可選擇加 monitoring 驗證。

## 主要參數
- `-ComposeFile`
- `-EnvFile`
- `-NewTag`
- `-Rollback`
- `-CheckMonitoring`
- `-NoLock`
- `-ConfirmDrill`：非 `-DryRun` 時必須加，否則拒絕執行（預設 compose／env 是正式環境）
- `-DryRun`

每重建一個服務就跑一次 `production-smoke.ps1`。服務之間的 `ServiceHello` 會比對發版身分，`-NewTag` 若是不同發版，舊新服務互連會被斷線，中間步驟預期 smoke 失敗；正式升版須整批替換所有服務（見 [版本握手與強制更新](../../10-核心流程/版本握手與強制更新.md#服務之間)）。

失敗時只回退已被重建過的服務，沒動到的服務不會被重建。
