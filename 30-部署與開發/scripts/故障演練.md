# `scripts/fault-drill.ps1`

## 作用
固定打 async fault。

## 目的
驗證 retry、dead-letter、metrics 的收斂行為。

## 流程
1. 設定環境變數 `FAULT_INJECT=<FaultName>`，並以 `docker compose up -d --no-deps --force-recreate world` **直接重建 World**（沒有確認提示；預設 compose 是 `compose.full.yml`，指到正式 compose 會踢掉該 World 的玩家）。
2. 等 World `/ready` 通過。World 診斷網址優先用 `WORLD_DIAG_URL`，未設定時為 `http://localhost:6062`（與 Go 維運工具同規則）。
3. 經 **Lobby** 的 `/admin/grant-item`（`-AdminUrl`，預設 `http://localhost:8080`，以環境變數 `LOBBY_ADMIN_TOKEN` 帶 Bearer token）送出 grant item。
4. 等待對應的 `game_async_failure_total{service="world",queue="grant_item",outcome=...}` 指標增加。
5. 依 expected outcome（`retry_scheduled` 或 `ack_failed`）判定通過與否。
6. 移除故障並重建 World：`finally` 會不帶 `FAULT_INJECT` 重建 world 並等 `/ready`，演練結束後 World 回到正常（TR-M1）。

## 主要參數
- `-ComposeFile`（預設 `docker/compose/compose.full.yml`）
- `-AdminUrl`；管理 token 不接命令列參數（會留在歷史與行程列表），改讀環境變數 `LOBBY_ADMIN_TOKEN`，未設定時用本機開發堆疊的預設值（只能用於本機）
- `-PlayerID`（必填）
- `-ItemID`、`-Quantity`
- `-FaultName`（預設 `world.grant_item.on_grant`；只收 `world.grant_item.on_grant`、`world.grant_item.ack` 兩個）
- `-ExpectedOutcome`（選填，`retry_scheduled`／`ack_failed`；依 `-FaultName` 推導：`on_grant`→`retry_scheduled`、`ack`→`ack_failed`）
- `-MaxAttempts`、`-SleepSeconds`：等待就緒與指標的輪詢次數與間隔
- `-DryRun`：只印出會做的事
