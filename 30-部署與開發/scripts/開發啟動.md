# `scripts/dev-up.sh`

## 作用
在本機以 `config/dev/*.yaml` 啟動全部開發服務。

## 目的
讓本機除錯有固定的 app 入口與設定檔；設定只有 `config/dev/` 一份，不再另抄範本。

## 流程
1. 建立 `.run/dev-up/logs/`。
2. 先 `go build` 各服務到 `.run/dev-up/bin/`（任一編譯失敗就在啟動前中止），再從倉庫根目錄依序以 `APP_CONFIG=config/dev/<服務>.yaml` 直接執行二進位，啟動 Central、Record、Lobby、Chat、World、Gate、User（World 以相對路徑 `config/data` 讀設定表，故必須在根目錄啟動）。不用 `go run`：它不轉送 SIGTERM，服務本體會變成孤兒佔住埠。
3. 各服務 `/ready`：Central `127.0.0.1:6060`、Gate `6061`、World `6062`、Lobby `6064`、Record `6065`、Chat `6066`。
4. Ctrl+C（或對腳本送 TERM）會把 TERM 送給全部服務並等它們優雅關機完才返回（Gate drain 最長約 75 秒），重跑時不會撞到還沒釋放的埠；腳本以 130（INT）／143（TERM）結束。腳本開了 job control（`set -m`），各服務在自己的行程群組，終端機 Ctrl+C 的 SIGINT 只送到腳本；服務只會收到 cleanup 送的那一個 TERM，不會先收 SIGINT 開始優雅關機、又被第二個訊號直接結束（World 最後寫回被跳過）。開了 job control 後 bash 不再把背景指令的 stdin 預設為 `/dev/null`，所以各服務子 shell 明確加 `</dev/null`（第十一輪 CL-M1；否則背景的 User 讀終端機收到 SIGTTIN 被停住、收不到 TERM，Ctrl+C 後腳本卡死）。
   任一服務提前結束（埠被占用、設定錯誤、依賴未啟動等）時，腳本印出 `service <名稱> exited (rc=<碼>); see <日誌路徑>` 並以 1 結束（EXIT trap 會把其餘服務一併優雅關閉），不再默默等下去。
5. 背景執行的 User 實例只做連線冒煙：stdin 不是終端機，讀到 EOF 記 `stdin closed; commands disabled` 後不再收指令；要下指令請另外以 `go run ./tools/user` 前景執行。

## 主要參數
- MySQL／RabbitMQ 連線以環境變數覆寫（viper `AutomaticEnv`，`MYSQL_HOST` 對應 `mysql.host`）：`MYSQL_HOST`、`MYSQL_PORT`、`MYSQL_USERNAME`、`MYSQL_PASSWORD`、`MYSQL_DBNAME`（World、Record、Chat）；`CENTRAL_MYSQL_*`（Central，預設埠 `13307`）；`RABBITMQ_URL`。連線預設值全在 `config/dev/*.yaml`，腳本不補預設值；環境變數只在使用者有設定時才生效。未設 `CENTRAL_MYSQL_*` 時 Central 以 `env -u MYSQL_*` 清掉外部繼承的 `MYSQL_*`（不會繼承到 World 用的值），退回 `config/dev/central.yaml`。
- `RUN_RECORD_APP=0`、`RUN_USER_APP=0` 略過 Record、User。
