# 配置熱重載

現行配置 snapshot 與 reload 行為；設計背景見[方案草稿](../90-參考附件/方案草稿/bytes配置統一與熱重載方案.md)。

- World 以完整配置建立不可變 snapshot，驗證成功後原子切換。
- watcher 只允許白名單配置變更；請求開始時固定使用同一份 snapshot。
- reload 失敗保留舊 snapshot，不影響既有請求。
- 熱重載不等進行中的請求：盤面指令與 GM 發放只在取 snapshot 時短暫持讀鎖（`worldSnapshotStore.acquire`），同時把變數規則釘在同一版（`variable.Service.Pinned`），之後在鎖外執行；換版瞬間進行中的指令沿用舊 snapshot 與舊變數規則做完。`/ready` 只讀原子指標，不會排在熱重載後面。
- World 啟動與熱重載都以實際載入的 manifest 比對發版資訊（`startup.VerifyDataConfig`）：`client_contract`、`min_config_seq` 不符（正式版另比對 `config_version`、`config_seq`）時拒絕啟動或拒絕換版（`data_config_reload_total{result="rejected"}`），見[版本握手與強制更新](../10-核心流程/版本握手與強制更新.md#啟動驗證)。
- 熱重載在背景 goroutine 執行，panic 一律接住並計入 `data_config_reload_total{result="failed"}`（`data config reload panic`）；準備階段 panic（`data config prepare panic`）轉成準備失敗，候選不採用並依下一條還原 `current.json`，避免重啟再載同版而循環崩潰。版本政策（`cmd/gate/internal/versioncheck`）的定期重載也逐次接住 panic，單次失敗不會讓重載迴圈退出。
- 候選被準備階段（`beforePublish`）拒絕時，會把 `current.json` 還原為目前版本，但只在它仍指向被拒絕的候選時才還原；發布者或其他實例已改到更新版本時不覆蓋。正式 compose 以唯讀掛載 artifact root，World 不改寫，還原失敗只會附在拒絕錯誤上。

實作位於 `cmd/world/internal/services`；操作見[配置操作入口](配置操作入口.md)。
