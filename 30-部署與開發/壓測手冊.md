# 壓測手冊

怎麼在本機對 dev 堆疊做壓測、故障注入與判讀。測出來的邊界與基準數字在[容量與壓測基準](../20-排障與監控/容量與壓測基準.md)，逐步紀錄在[壓測紀錄](../90-參考附件/歷史/壓測紀錄-2026-10-15.md)。

壓測工具都在 `tools/private/`（私有工具，**不進主倉庫版控**），本文件所有指令都從倉庫根目錄執行。

## 前置

1. 啟動依賴與服務：`./scripts/docker-deps-up.sh`，再 `./scripts/dev-up.sh`（六個服務 `/ready` 在 `6060`、`6061`、`6062`、`6064`、`6065`、`6066`）。
2. 本機 Prometheus：`./scripts/monitoring-up.sh` 起的是 `9090`；dev 依賴 compose 內的容器 `project-dev-prometheus` 對外是 `127.0.0.1:39090`。改 `monitoring/prometheus/alert-rules.yml` 後 `POST /-/reload`，不必重啟。Prometheus 約每 15 秒抓一次，要即時值直接看服務的 `/metrics`。
3. 資料量大的壓測前，把 `config/dev/*.yaml` 的 `protocol_record_payload_enabled` 關掉（見下方「陷阱」）。

## 工具

| 工具 | 用途 | 主要旗標 |
|---|---|---|
| `pjaload loadtest` | 模擬大量玩家登入、心跳、登出、重連；可寫 baseline | `-gate`、`-n`、`-ramp`、`-duration`、`-hb`、`-soak`（斷線後自動重登）、`-session`、`-cooldown`、`-source-ips`、`-write-baseline` |
| `pjaload capacityforecast` | 讀 baseline 推估容量 | `-baseline`、`-target-p95-ms`、`-target-queue-depth` |
| `soakload` | 登入後常駐，定期擲骰，並取樣各服務 goroutine／heap／RSS／GC | `-n`、`-hold`、`-every`、`-sample`、`-prefix` |
| `cmdload` | 依序送盤面指令（載入、任務、升級…）量各指令延遲；遇 code 9 自動重試 | `-n`、`-rounds`、`-prefix` |
| `gameload` | 擲骰＋抽獎＋商店購買／跳過，統計結果碼與延遲（會送心跳） | `-n`、`-d`、`-prefix` |
| `churnload` | 登入、登出、重登穿插，結尾驗證資料一致 | `-n`、`-d`、`-prefix`、`-pace`（玩家少時放慢，避免撞單帳號登入限流 code 8） |
| `dupgate` | 同帳號重複登入（跨 Gate／同 Gate），驗證舊連線被通知或關閉 | 見 `-h` |
| `chatload` | 聊天廣播延遲；可分散到多間房 | `-n`、`-msgs`、`-gap`、`-room`、`-rooms`、`-prefix` |
| `rollload` | 擲骰系統級壓測（Gate→World→Record→資料庫） | `-n`、`-d`、`-prefix` |
| `recordload` | 直接發事件到 RabbitMQ，量 Record 消費排空時間 | `-url`、`-n`、`-window`、`-mq`（RabbitMQ 容器名） |
| `grantload` | GM 發道具佇列排空時間 | `-redis`、`-n`、`-players`、`-item` |
| `httpload` | 對 HTTP 端點做固定併發壓測 | `-url`、`-n`、`-d`、`-H "Key: Value"`（可重複） |
| `badclient` | 惡意流量：靜默、slowloris、超大 frame、垃圾資料、握手後沉默、未知訊息洪水、連線洪水 | `-s`（情境）、`-n`、`-hold` |
| `netproxy` | TCP 代理：注入固定延遲、抖動、隨機斷線 | `-listen`、`-target`、`-delay`、`-jitter`、`-kill-min`、`-kill-max`、`-src-base` |
| `shutdowntime` | 啟動服務執行檔，等 trigger 檔出現後送 CTRL_BREAK，量優雅關機時間（僅 Windows） | `<exe> <trigger> <log>` |
| `pja coldstorage` | Redis 冷資料匯出（透過私有啟動器 `go run ./tools/private/pja coldstorage …`） | `-redis`、`-output`、`-pattern` |

執行方式：`go run ./tools/private/<工具> <旗標>`。`loadtest`、`capacityforecast` 沒有獨立 main，用 `go run ./tools/private/pjaload loadtest …`。

### 共通注意事項

- **來源 IP**：Gate 對單一來源 IP 有連線數（100）、接入速率與登入嘗試限流，單機壓測會卡在約 30 人。`soakload`、`cmdload`、`chatload`、`gameload`、`badclient` 內建把玩家分散到 `127.0.x.y`；`pjaload loadtest` 要加 `-source-ips 127.0.2.2,127.0.2.3,…`（越多越好，1000 人至少 32 個）。
- **新帳號要帶密碼**：空密碼登入新帳號回 `WrongPassword`（code 13）。建立新帳號時設環境變數 `RL_PASSWORD=<至少幾個字元的密碼>`（`cmdload`、`soakload`、`gameload`、`chatload`、`rollload` 已支援）；既有無密碼帳號（`loadtest_*` 等）仍用空密碼，不要設。
- **心跳**：Gate 對沒有心跳的連線以 `heartbeat timeout` 關閉；自己寫的客戶端要每 5 秒送一次 `HeartbeatRequest`。
- **登入尖峰**：Central 同時處理登入上限 64，同時登入的人數超過會拿到 code 9（可重試）。`cmdload`、`chatload`、`gameload` 會重試；`churnload`、`pjaload loadtest` 也會重試。自己寫的工具必須退避重試，否則會看到大批「登入失敗」。
- 擲骰每個玩家每日有骰子上限（約 100 次），之後回 `result=2 fail=1`，不是錯誤。

## 食譜

### 冒煙：登入容量

```bash
go run ./tools/private/pjaload loadtest -gate 127.0.0.1:62001 \
  -source-ips 127.0.2.2,127.0.2.3,...(32 個) -n 1000 -ramp 40s -duration 60s -hb 5s
```

預期 `loginOK` 等於 `-n`、`errors=0`、p95 登入約 10～16ms。`max_connections` 不夠時新連線會被直接關閉：看 `tcp_rejected_connections_total{reason="at_capacity"}`（日誌 `rejecting connection: at capacity` 是 Debug 等級，欄位 `owner`，預設 Info 看不到）。

### 常駐與洩漏

```bash
go run ./tools/private/soakload -n 1500 -hold 60m -every 10s -sample 120s -prefix lg
```

看輸出的 goroutine、heap、RSS 欄位是否持平（heap 是 GC 鋸齒，看高點是否上升；RSS 初期會爬升再持平）。

### 重連

```bash
go run ./tools/private/pjaload loadtest ... -n 300 -soak -session 900s -cooldown 2s -duration 300s
```

中途殺 World 再重啟，看每 5 秒輸出的 `connected` 何時回到 `-n`。

### 玩法路徑

```bash
RL_PASSWORD=<密碼> go run ./tools/private/gameload -n 500 -d 120s -prefix gl
```

### 資料庫變慢

World 的 MySQL 位址可由環境變數 `MYSQL_HOST`／`MYSQL_PORT` 覆寫：

```bash
netproxy -listen 127.0.0.1:13396 -target 127.0.0.1:13306 -delay 50ms &
MYSQL_PORT=13396 APP_CONFIG=config/dev/world.yaml go run ./cmd/world
```

`-delay` 是單向，RTT 為兩倍。再用 `soakload` 或 `cmdload` 看延遲與告警。

### Gate 與 World 之間的網路劣化

複製 `config/dev/gate.yaml`，把 `dial.world.<id>.ip` 改成代理位址（例如 `127.0.0.1:61101`），代理轉到 `61001`，用該設定啟動 Gate：

```bash
netproxy -listen 127.0.0.1:61101 -target 127.0.0.1:61001 -delay 50ms -kill-min 20s -kill-max 40s
```

### 滾動優雅重啟

先把服務編譯成執行檔，由 `shutdowntime` 啟動，`touch <trigger>` 後它會送 CTRL_BREAK 並印出 `shutdown took …`：

```bash
go build -o bin/gate.exe ./cmd/gate
APP_CONFIG=config/dev/gate.yaml shutdowntime bin/gate.exe /tmp/gate.trigger /tmp/gate.log
touch /tmp/gate.trigger
```

負載用 `pjaload loadtest -soak`。預期 Gate 關機約 30 秒（drain），World、Central 約 5 秒。

### 惡意流量

```bash
go run ./tools/private/badclient -s silent -n 2000 -hold 45s
```

`-s` 可選 `silent`、`slowloris`、`oversize`、`garbage`、`hello-silent`、`unknown-flood`、`connflood`。工具同時用一個正常玩家量登入延遲（canary），並每秒讀 Gate `/metrics` 的 goroutine 與 heap。

### 資料量放大

`dbload`（`-mode read|insert|purge`、`-c`、`-n`、`-table`）在 SQL 層量 `RecordsSince`、`AppendRecords`、`PurgeBefore` 形狀的語句。大表用 `CREATE TABLE chat_message_big LIKE chat_message` 加遞迴 CTE 先灌 10 萬列，再用 `INSERT ... SELECT` 自我倍增。表超過 buffer pool 後每輪倍增耗時暴增（320 萬→640 萬列約 15 分鐘，640 萬→1280 萬列約 30 分鐘），要預留時間。測完 `DROP TABLE` 並刪掉插入到真實表的假資料。

### GCP 虛擬機

用 GCE 跑 5000 人壓測（方案、必改限制、別名 IP、建機與清除腳本）見[GCP 壓測手冊](GCP壓測手冊.md)。`soakload` 的 `-srcnet`、`-world-host`、`-gate-host`、`-central-host` 就是為此加的。

### 多 World

**S2S 認證開啟**：用 `scripts/new-s2s-dev-secrets.ps1`（需要 openssl）產生開發憑證與 token，複製各服務設定把 `s2s_auth.enabled` 改 `true` 並指到各節點自己的機密目錄（Chat 同時是接收端與用戶端，兩份目錄要合併）。比較前先清掉所有舊的 World／Gate 程序，否則明文客戶端會一直被拒絕而污染數據。

**Redis 停頓**：在 Redis 容器內迴圈執行 `redis-cli client pause <ms>`（例如每 100ms 停 50ms）即可模擬 Redis 變慢，同時用 `soakload` 看擲骰延遲。

**資源上限**：只能用 `GOMAXPROCS` 環境變數與設定檔 `go.memory_limit_mb` 模擬，不是 cgroup；要驗證 OOM 或 CPU throttling 必須用容器。

**容器 cgroup 限制**：`docker build -f docker/app.Dockerfile --build-arg APP_DIR=cmd/gate --build-arg HEALTHCHECK_PORT=6061 -t pja-gate-test .` 建映像，設定複製 `config/dev/gate.yaml` 並把 `127.0.0.1` 換成 `host.docker.internal`，用 `docker run --cpus <n>` 或 `--memory <m>` 執行（發佈 62001、6061）。經 Docker NAT 玩家對 Gate 都是同一個來源 IP，會撞單 IP 連線數與登入速率限制，因此客戶端要放進容器：交叉編譯 `GOOS=linux go build ./tools/private/soakload`，每個容器跑 `soakload -nobind -pace 400ms -offset <k*100> -n 100`（15 個容器共 1500 人）。`docker inspect` 的 IP 欄位在新版 Docker Desktop 要用 `.NetworkSettings.Networks.bridge.IPAddress`。

**重要**：Git Bash 不要 `export MSYS_NO_PATHCONV=1`——它會讓 `taskkill //PID` 失效（舊進程沒被殺），也讓 `APP_CONFIG=/c/...` 這種路徑無法被 Windows exe 解析；兩者都會讓「重啟後的新設定」其實沒生效，卻不報錯。每個情境開頭用 `go_sched_gomaxprocs_threads`、`go_gc_gomemlimit_bytes` 驗證設定真的生效。需要時只對 `docker` 單一命令設該變數。

見[多 World 部署](多World部署.md)的驗證步驟。

### Record 與發道具

```bash
go run ./tools/private/recordload -url amqp://project:project_pass@127.0.0.1:25672/ -mq project-dev-rabbitmq -n 120000
go run ./tools/private/grantload -redis 127.0.0.1:16379 -n 5000 -players 50
```

### 備份與維運作業對負載的影響

在 `soakload` 穩態期間執行 `docker exec project-dev-mysql sh -c "mysqldump -uroot -prootpass --single-transaction --quick project | wc -c"` 或對大表做全表聚合，看擲骰 p99。

## 判讀清單

- 大量 `code 9` 或 `login failed, notifying gate directly`：Central 同時登入上限，不是故障；`game_login_total{result="busy"}` 會增加。
- 只連得上約 30 人：單一來源 IP 限流，補 `-source-ips`。
- `login code: 13`：新帳號沒帶密碼。
- 玩家全被 `heartbeat timeout` 關閉：自製客戶端沒送心跳。
- 玩家送了 Gate 沒轉送的訊息（`UseItem`、戰鬥指令）：整條連線被關閉，見[盤面回合與事件結算](../10-核心流程/盤面回合與事件結算.md)。
- `connectex: Only one usage of each socket address`：Windows 暫時埠耗盡，通常是工具在失敗時無退避地大量重連；會讓 World 連 MySQL 失敗並使熔斷器開啟。降低重連頻率。
- 壓測後 `GameRecoveryMismatchDetected` 持續 firing：它看 10 分鐘窗口，約 10 分鐘後自行消失。
- 壓測期間 Central 一致性稽核報 `account cache missing from redis` 並自動修復：新帳號大量建立後的正常現象。

## 陷阱與環境

- **`protocol_records` 磁碟**：dev 設定 `protocol_record_enabled: true`、`protocol_record_payload_enabled: true` 時，1000 人常駐每小時約 500MB，保留 24 小時。壓測前關閉；正式設定 `docker/prod/config/*.yaml` 已是 `protocol_record_enabled: false`，不可開。payload 開啟時登入密碼會原樣落檔。協定記錄開啟時（dev、docker 設定預設開啟，prod 關閉）每則訊息仍會取共用 ring 鎖並做 `json.Marshal`，會拉高延遲與配置數；程式端已改為沒有檔案記錄器時不複製 payload。壓測基準請固定「關閉協定記錄」再量，或在結果中註明記錄狀態。要試非同步日誌時可在單一服務設 `LOG_ASYNC_BUFFER=8192` 並觀察 `logger_async_dropped_total`。注意 `BenchmarkInfoStderrFile/async` 的 ns/op 大多量到丟棄路徑（benchmark 另回報 `dropped/op`，本機約 0.97），不能直接當正式環境開啟的效益依據，要看壓測時的丟棄數與延遲。
- **Windows 暫時埠**：短時間大量連線與重連會耗盡暫時埠，不要在壓測迴圈裡無限重連。
- **機器重開後 Docker Desktop 不會自動啟動**：若啟動失敗訊息是 `sailor-ingest.sock: The file cannot be accessed by the system`，把 `%LOCALAPPDATA%\Docker\run` 資料夾改名（不要刪、不要重設為出廠預設）後重啟 Docker Desktop，再 `./scripts/dev-up.sh`。
- **Git Bash 路徑轉換**：在 Git Bash 對 `docker exec`／`docker cp` 傳容器內路徑（例如 `/etc/prometheus/…`）時，要加 `MSYS_NO_PATHCONV=1`，否則路徑會被轉成 `C:/Program Files/Git/…`。
- **dev 預設用舊版設定目錄**（`data_config.allow_legacy_directory: true`，沒有 `current.json`），World 不監看設定，無法直接測熱更新；要演練需準備 artifact 目錄，見[配置熱重載](配置熱重載.md)。
- **服務診斷埠預設固定**（`pkg/debug/services.go`，World 為 6062）：同一台主機跑第二個 World 時以設定 `debug.addr` 指定其他位址，否則後啟動的沒有 `/metrics`。
- 壓測會在 dev 資料庫留下測試帳號與玩家資料（`loadtest_*`、`sk_*`、`cmd_*` 等）；放大資料量的測試（把玩家表以 `player_id + k×100000000` 複製）結束後用 `player_id >= 100000000` 刪除。
- **背景工作沒有完成通知**：用 `nohup` 起的長測試不會通知完成，請讓腳本最後 `touch` 一個 `finished` 檔，自己檢查。
- **腳本產生的設定檔路徑**：重用腳本時確認設定檔寫到本次輸出資料夾；寫到舊資料夾會讓服務因「找不到設定檔」沒起來，工具端只看到全部登入失敗。
- **既有帳號用空密碼**：舊壓測帳號（`sk_*`、`cmd_*`、`ch_*`、`rm_*`）是空密碼，登入不走新帳號的 bcrypt 建立，大規模登入應優先用它們；新帳號才需要 `RL_PASSWORD`。

## 測試後還原

- 把壓測臨時換上的實例（自編執行檔、第二個 World、代理）停掉，Gate 與 World 換回 `config/dev` 設定。
- 檢查六個服務 `/ready` 為 200、`ALERTS{alertstate="firing"}` 沒有殘留。
- 需要的話清掉測試資料，並確認 `protocol_records` 沒有佔滿磁碟。
