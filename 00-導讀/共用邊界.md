# pkg 邊界準則

`pkg` 只放可重用基建。任何帶服務語意的東西，都要留在 `cmd/*/internal`。

## 可以放

- transport
- logger / metrics
- `pkg/metrics` 可放跨服務共用的指標名稱與 label 契約，變更前要先確認所有引用端。
- generic cache / journal
- stdin / reader console adapter
- generic reconnect / backoff strategy
- generic IP rate limiter
- TCP config / address resolver
- enum / DTO
- 純工具型 helper

## 不可以放

- login / logout / session 狀態機
- world routing / assignment policy
- recovery / reconcile decision
- return code policy
- service-specific fallback
- 任何只給單一 service 用的業務規則

## 各包紅線

### `pkg/appcore`

- 只做 event loop、time sync、signal 入口
- console runner 由 `RunConsole` 提供
- signal 監聽由 `pkg/startup.Main` 以標準庫 `signal.NotifyContext` 處理
- 不加 service-specific lifecycle rule
- 不放登入、登出、重連決策

### `pkg/tcpserver`

- 只做 TCP accept / server runtime
- 不放 session、kick、login、routing policy
- 不變成 service locator

### `pkg/tcpclient`

- 只做 TCP connect / reconnect / client runtime
- 不放 session、kick、login、routing policy

### `pkg/requestjournalredis`

- 只做 generic replay cache
- 只存結果，不解釋結果
- 不塞 service-specific retry policy

### `pkg/playerstore`

- 只做 World presence store / restore helper
- 不放 session policy
- 不放 recovery 裁決

### `pkg/protocol/client`、`pkg/dataconfig`（含 `generated`、`luban`）

- 只放 PJA-Protocol / PJA-Config 的**生成物**與其 Go runtime
- 由 `scripts/sync-protocol.ps1` / `scripts/sync-data-config.ps1` 同步，不得手改
- 生成物放 `pkg/` 而非 `internal/`，是為了讓 `pkg/msg`、`pkg/enum`、`pkg/startup`
  不反向依賴 `internal/`（依賴方向只往下）
- 每個目錄都必須有 `doc.go`；`pkg/pkg_boundary_test.go` 會強制檢查
- 生成物目錄內不得放其他 `.go` 檔——同步腳本會把非生成物的 `.go` 刪掉
- `pkg/dataconfig` 只做 artifact、manifest、checksum 與快照 store 的機制，**不認識任何資料表內容**；World 專屬的換版規則（任務進度相容、道具／效果／事件 ID 不得移除、商店道具存在、變數上下限與拓撲遷移檢查、熱重載與各種發布放行的檔案）放在 `internal/gamecore/configcompat`，由組合根與 `tools/configartifact` 以 `dataconfig.CompatibilityChecker`（`NewSnapshotStoreWith`、`Publisher{Checker: ...}`）注入；Checker 為 nil 時不檢查換版規則

### `pkg/servicefinder`

- 只做 service lookup
- 不放 routing 决策
- 不放 fallback policy

### `pkg/tcpclient`（原 `pkg/reconnect`）

- 只做通用退避策略（reconnect strategy 已整併至此 package 內部）
- 不管 TCP、session、service life cycle
- 不塞 transport policy

### `pkg/ratelimit`

- 只做通用 IP rate limiter
- 不管 TCP service runtime
- 不放 session policy

### `pkg/tcpconfig`

- 只做 TCP config 讀取與地址解析
- 不管 runtime 生命週期
- 不放 session / routing policy

### `pkg/tcpsocket`（原 `pkg/tcpdeadline`）

- 只做 TCP deadline 常數（已整併至 `pkg/tcpsocket/deadline.go`）
- 不管 runtime / socket / service policy

### `pkg/netutil`

- 只做純網路 helper
- 不管 socket runtime
- 不管 service policy

### `pkg/tcpsocket`（原 `pkg/nettransport`）

- 只做最薄 net.Listen / net.Dial 包裝，Dial 帶 10s 預設逾時（已整併至 `pkg/tcpsocket/default_transport.go`）
- 不放 service policy

### `pkg/tcpclient`

- 只做連線、重連與 client runtime；服務選擇由 `pkg/servicefinder` 與各服務自行決定
- 不放 service policy

### `pkg/tcpserver`（原 `pkg/ipallowlist`）

- 只做 TCP IP allowlist 比對（已整併至 `pkg/tcpserver/accept_policy.go` 內部輔助函式）
- 不放 service policy

### `pkg/tcpserver`（原 `pkg/acceptpolicy`）

- 只做 TCP 接入裁決（已整併至 `pkg/tcpserver/accept_policy.go`）
- 不放 service policy

## 判斷規則

若一個 package 的修改會同時牽動 `Gate / Central / World` 三邊流程，它多半不該在 `pkg`。

若一個 package 名字看起來很 generic，但 API 內已出現 `Login`、`Logout`、`Session`、`World`、`Gate`、`Central` 這類詞，它已經開始越界。

## 原則

- `pkg` 要薄
- `cmd/*/internal` 要厚
- 依賴方向只往下，不往回滲

## 根層 `internal/game` 例外

需要由正式服務與根目錄 `tools/` 共用的純遊戲規則，可放在根層 `internal/game/{domain}`。這是 module 內部共用的遊戲邏輯，不屬於公開 `pkg` 基建。

只允許放：

- 與傳輸、資料庫及服務 Runtime 無關的 Domain 型別與規則。
- 可由 World 與工具注入不同 Adapter 的小型 consumer-side interface。
- 確定已有正式服務與工具兩個實際 consumer 的邏輯。

禁止放：

- Protocol／message／socket 型別。
- MySQL、Redis、GORM 或特定服務的 Store 實作。
- World、Gate、Central 等服務生命週期與路由規則。
- 只為未來可能使用而提前抽出的業務 package。

依賴方向：

```text
cmd/world ─┐
           ├─→ internal/game
tools ─────┘
```

`internal/game` 不得反向引用 `cmd/*/internal`；工具仍統一放在根目錄 `tools/`；個人用、不進 git 的工具放 `tools/private/`（見 [工具總覽](../30-部署與開發/工具總覽.md)），正式程式、CI 與腳本不得依賴它。

## World 與 simulator 共用遊戲邏輯

原則：**遊戲邏輯只有一份，通用系統放在 `internal/gamecore`，盤面等玩法放在 `internal/game`；World 與模擬工具（共用 `internal/game/simulation`）只實作外部依賴（儲存、亂數、時間）的轉接器。** simulator 只測遊戲邏輯，不測儲存語意（交易、回滾、冪等、outbox）。

| 套件 | 共用的邏輯 | World 轉接器 | simulator 轉接器 |
| --- | --- | --- | --- |
| `gameconfig` | 設定載入與跨表檢查（`Load`） | `buildWorldSnapshot` | `loadRunner`、`LoadMissionRunner` |
| `gamecore/condition` + `boardconfig.EvaluateCondition` | 條件樹求值；運算元由 `condition.Readers` 注入，盤面運算元（經過格數、建築等級）在 `boardconfig` | 變數與建築讀取器 | 變數讀取器（`variableReader`） |
| `gamecore/variable` | 缺值用預設、越界報錯（`Definition.Resolve`）與變數服務 | 組合根注入 `gamestore.VariableStore` | 同左 |
| `board` | 擲骰結算：`Inventory`（研究費用、工廠砲彈、事件獎勵）、`EffectStore`（研究效果替換） | `playerTx`（玩家記憶體交易） | `inventoryMap`、`effectList` |
| `boardconfig` | 建築升級：`PlanBuildingUpgrade`、`PayBuildingCosts`（`BuildingWallet`）、`ApplyBuildingEffects` | `playerTx`、`buildingWallet` | `simWallet`、`effectList` |
| `turn` | 擲骰回合流程 `PlayTurn`：效果、擲骰、研究費用不足降級重算、工廠效果、抽獎條件、商店報價、收集抽獎、掛回獎勵 | `RollDiceDeps.turnPorts`（`Commit` 在玩家交易內保存並抽獎） | `Runner.turnPorts`（`Commit` 在玩家副本上套用並抽獎） |
| `gamecore/mission` | 任務接取與事件流程 `Play.Activation`／`Play.Event`（輪次、流程、跨輪次欄位、待領獎勵）、`ClaimExpired`、`AutoClaims` | `restoreMissionState` 與 `missionStateRecord` | `missionSim.commit` |

規則：

- 規則函式以參數接收時間（`now time.Time`），不自己呼叫 `time.Now()`；simulator 有自己可調的時間來源。
- 抽獎必須在儲存的鎖內「讀狀態、抽、寫狀態」，所以 `turn.PlayTurn` 把抽獎交給 `Commit`，不在共用層先抽。
- 兩邊行為不同時，**以 World 現行行為為準**，只改 simulator。
- 新增 World 與 simulator 都會用到的規則時，先放 `internal/game`，不要在 `cmd/world/internal` 寫一份再讓 simulator 複製。

仍未共用：

- 任務領獎（`claim`）與抽獎狀態的儲存：World 在玩家交易內保存抽獎計數、紀錄與道具，simulator 以記憶體狀態與可重現亂數，這屬於儲存語意，不共用。
- 貨幣變數沒有資料列時，World 視為 0；若日後變數 `Default` 不為 0，兩邊要一起決定規則。

## `internal/gamecore` 通用遊戲系統

與玩法無關的系統（variable、item、effect、condition、lottery、mission、shop）放在 `internal/gamecore/<系統>`，每個系統一個包，含規則、設定載入與必要的服務。

設定換版規則（`configcompat`）也放在這裡：它只依賴 `pkg/dataconfig` 的生成物與機制，不依賴其他 gamecore 子包；World 以 `configcompat.Checker{}` 注入快照 store，任務狀態版本相容判斷用 `configcompat.MissionStateCompatible`，變數遷移步驟用 `configcompat.LoadVariableMigrationSteps`。

- 依賴方向：`cmd/world` → `internal/game`（玩法層）→ `internal/gamecore`。`gamecore` 不得引用 `cmd`、`tools`、`integration`、`internal/game`，子包之間也不得互相引用；由 `internal/gamecore/boundary_test.go` 強制。
- 外部能力一律由消費端定義介面並以建構子注入：Store（`variable.Store`、`effect.Store`）、Handler（`item.Handler`）、取值來源（`condition.Readers`）、獎勵目錄（`mission.RewardCatalog`）、指標回呼（`variable.WithSaveFailureHook`）。
- 持久化轉接器放在 `cmd/world/internal/store/gamestore`（`VariableStore`、`EffectStore`），由 `services` 組合根建立。
- 跨系統的載入與驗證放在 `internal/game`：`gameconfig`、`missionconfig`、`boardconfig`（盤面運算元 `OperandTypeBoardSpaceKindPassedCount`／`OperandTypeBuildingLevel` 與 `EvaluateCondition`、效果來源 `board.EffectSource*`）。
- 不要把 `GameConfigs` 當 service locator 傳進 `gamecore`；載入函式只在啟動時呼叫一次，之後只傳具體的 `Definitions`。
