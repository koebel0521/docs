# pkg 邊界準則

`pkg` 只放可重用基建。任何帶服務語意的東西，都要留在 `cmd/*/internal`。

## 可以放

- transport
- logger / metrics
- `pkg/metrics` 可放跨服務共用的指標名稱與 label 契約，變更前要先確認所有引用端。
- generic cache / journal
- stdin / reader console adapter
- generic reconnect / backoff strategy
- generic IP rate limiter
- TCP config / address resolver
- enum / DTO
- 純工具型 helper

## 不可以放

- login / logout / session 狀態機
- world routing / assignment policy
- recovery / reconcile decision
- return code policy
- service-specific fallback
- 任何只給單一 service 用的業務規則

## 各包紅線

### `pkg/appcore`

- 只做 event loop、time sync、signal 入口
- console runner 由 `RunConsole` 提供
- signal 監聽實作交給 `pkg/appsignal`
- 不加 service-specific lifecycle rule
- 不放登入、登出、重連決策

### `pkg/appsignal`

- 只做 OS signal 監聽 helper
- 不管 app runtime 狀態
- 不放 shutdown policy

### `pkg/tcpserver`

- 只做 TCP accept / server runtime
- 不放 session、kick、login、routing policy
- 不變成 service locator

### `pkg/tcpclient`

- 只做 TCP connect / reconnect / client runtime
- 不放 session、kick、login、routing policy

### `pkg/requestjournal`

- 只做 generic replay cache
- 只存結果，不解釋結果
- 不塞 service-specific retry policy

### `pkg/playerstore`

- 只做 World presence store / restore helper
- 不放 session policy
- 不放 recovery 裁決

### `pkg/protocol/client`、`pkg/dataconfig`（含 `generated`、`luban`）

- 只放 PJA-Protocol / PJA-Config 的**生成物**與其 Go runtime
- 由 `scripts/sync-protocol.ps1` / `scripts/sync-data-config.ps1` 同步，不得手改
- 生成物放 `pkg/` 而非 `internal/`，是為了讓 `pkg/msg`、`pkg/enum`、`pkg/startup`
  不反向依賴 `internal/`（依賴方向只往下）
- 每個目錄都必須有 `doc.go`；`pkg/pkg_boundary_test.go` 會強制檢查
- 生成物目錄內不得放其他 `.go` 檔——同步腳本會把非生成物的 `.go` 刪掉

### `pkg/servicefinder`

- 只做 service lookup
- 不放 routing 决策
- 不放 fallback policy

### `pkg/tcpclient`（原 `pkg/reconnect`）

- 只做通用退避策略（reconnect strategy 已整併至此 package 內部）
- 不管 TCP、session、service life cycle
- 不塞 transport policy

### `pkg/ratelimit`

- 只做通用 IP rate limiter
- 不管 TCP service runtime
- 不放 session policy

### `pkg/tcpconfig`

- 只做 TCP config 讀取與地址解析
- 不管 runtime 生命週期
- 不放 session / routing policy

### `pkg/tcpsocket`（原 `pkg/tcpdeadline`）

- 只做 TCP deadline 常數（已整併至 `pkg/tcpsocket/deadline.go`）
- 不管 runtime / socket / service policy

### `pkg/netutil`

- 只做純網路 helper
- 不管 socket runtime
- 不管 service policy

### `pkg/tcpsocket`（原 `pkg/nettransport`）

- 只做最薄 net.Listen / net.Dial 包裝，Dial 帶 10s 預設逾時（已整併至 `pkg/tcpsocket/default_transport.go`）
- 不放 service policy

### `pkg/tcpclient`（原 `pkg/roundrobin`）

- 只做 round-robin 選擇器（已整併至 `pkg/tcpclient/client_picker.go` 的 `RoundRobinPicker`）
- 不放 service policy

### `pkg/tcpserver`（原 `pkg/ipallowlist`）

- 只做 TCP IP allowlist 比對（已整併至 `pkg/tcpserver/accept_policy.go` 內部輔助函式）
- 不放 service policy

### `pkg/tcpserver`（原 `pkg/acceptpolicy`）

- 只做 TCP 接入裁決（已整併至 `pkg/tcpserver/accept_policy.go`）
- 不放 service policy

## 判斷規則

若一個 package 的修改會同時牽動 `Gate / Central / World` 三邊流程，它多半不該在 `pkg`。

若一個 package 名字看起來很 generic，但 API 內已出現 `Login`、`Logout`、`Session`、`World`、`Gate`、`Central` 這類詞，它已經開始越界。

## 原則

- `pkg` 要薄
- `cmd/*/internal` 要厚
- 依賴方向只往下，不往回滲

## 根層 `internal/game` 例外

需要由正式服務與根目錄 `tools/` 共用的純遊戲規則，可放在根層 `internal/game/{domain}`。這是 module 內部共用的遊戲邏輯，不屬於公開 `pkg` 基建。

只允許放：

- 與傳輸、資料庫及服務 Runtime 無關的 Domain 型別與規則。
- 可由 World 與工具注入不同 Adapter 的小型 consumer-side interface。
- 確定已有正式服務與工具兩個實際 consumer 的邏輯。

禁止放：

- Protocol／message／socket 型別。
- MySQL、Redis、GORM 或特定服務的 Store 實作。
- World、Gate、Central 等服務生命週期與路由規則。
- 只為未來可能使用而提前抽出的業務 package。

依賴方向：

```text
cmd/world ─┐
           ├─→ internal/game
tools ─────┘
```

`internal/game` 不得反向引用 `cmd/*/internal`；工具仍統一放在根目錄 `tools/`。
