# pkg 邊界準則

`pkg` 只放可重用基建。任何帶服務語意的東西，都要留在 `cmd/*/internal`。

## 可以放

- transport
- logger / metrics
- `pkg/metrics` 可放跨服務共用的指標名稱與 label 契約，變更前要先確認所有引用端。
- generic cache / journal
- stdin / reader console adapter
- generic reconnect / backoff strategy
- generic IP rate limiter
- TCP config / address resolver
- enum / DTO
- 純工具型 helper（例如 `pkg/mapx` 只有依 key 排序的 `SortedKeys`，不依賴其他專案套件）

## 不可以放

- login / logout / session 狀態機
- world routing / assignment policy
- recovery / reconcile decision
- return code policy
- service-specific fallback
- 任何只給單一 service 用的業務規則

## 各包紅線

### `pkg/appcore`

- 只做 event loop、time sync、signal 入口
- console runner 由 `RunConsole` 提供
- signal 監聽由 `pkg/startup.Main` 以標準庫 `signal.NotifyContext` 處理
- 不加 service-specific lifecycle rule
- 不放登入、登出、重連決策

### `pkg/tcpserver`

- 只做 TCP listen／accept 與 server runtime：接入時先以 `pkg/ratelimit` 的來源 IP 限流、再檢查連線上限（`server_accept.go`）
- listen 只經 `Server.listenFunc` 函式欄位（預設 `net.ListenConfig`），測試可注入替身；不另設 Transport 介面
- S2S 的來源 CIDR 白名單在 `pkg/s2sauth`（`allowed_cidrs`），不在本套件
- 不放 session、kick、login、routing policy；不變成 service locator

### `pkg/tcpclient`

- 只做 TCP dial／reconnect 與 client runtime：預設備援模式（依序嘗試、單連線），`WithDialAll` 全連模式（每個位址各一個撥號迴圈）
- 重連退避用 `cenkalti/backoff`；dial 只經 `Client.dial` 函式欄位（預設 `net.Dialer`，10 秒逾時），測試可注入替身
- 服務選擇由 `pkg/servicefinder` 與各服務自行決定
- 不放 session、kick、login、routing policy

### `pkg/s2shandshake`

- 只做 S2S 連線層握手與心跳：ConnectInfo／ServiceHello 收送、發版身分比對、hello 逾時與前置守門、背景心跳廣播
- 訊息型別在 `pkg/msg/system`，本套件只放使用它們的執行期流程
- 不放 session、login、routing policy

### `pkg/requestjournalredis`

- 只做 generic replay cache
- 只存結果，不解釋結果
- 不塞 service-specific retry policy

### `pkg/playerstore`

- 只做 World presence store / restore helper
- 不放 session policy
- 不放 recovery 裁決

### `pkg/protocol/client`、`pkg/dataconfig`（含 `generated`、`luban`）

- 只放 PJA-Protocol / PJA-Config 的**生成物**與其 Go runtime
- 由 `scripts/sync-protocol.ps1` / `scripts/sync-data-config.ps1` 同步，不得手改
- 生成物放 `pkg/` 而非 `internal/`，是為了讓 `pkg/msg`、`pkg/enum`、`pkg/startup`
  不反向依賴 `internal/`（依賴方向只往下）
- 每個目錄都必須有 `doc.go`；`pkg/pkg_boundary_test.go` 會強制檢查
- 生成物目錄內不得放其他 `.go` 檔——同步腳本會把非生成物的 `.go` 刪掉
- `pkg/dataconfig` 只做 artifact、manifest、checksum 與快照 store 的機制，**不認識任何資料表內容**；World 專屬的換版規則（任務進度相容、道具／效果／事件 ID 不得移除、商店道具存在、變數上下限與拓撲遷移檢查、熱重載與各種發布放行的檔案）放在 `internal/gamecore/configcompat`，由組合根與 `tools/configartifact` 以 `dataconfig.CompatibilityChecker`（`NewSnapshotStoreWith`、`Publisher{Checker: ...}`）注入；Checker 為 nil 時不檢查換版規則

### `pkg/servicefinder`

- 只做 service lookup
- 不放 routing 决策
- 不放 fallback policy

### `pkg/ratelimit`

- 只做通用 IP rate limiter
- 不管 TCP service runtime
- 不放 session policy

### `pkg/tcpconfig`

- 只做 TCP config 讀取與地址解析
- 不管 runtime 生命週期
- 不放 session / routing policy

### `pkg/tcpsocket`（原 `pkg/tcpdeadline`）

- 只做 TCP deadline 常數（位於 `pkg/tcpsocket/socket_loops.go`）
- 不管 runtime / socket / service policy

### `pkg/netx`

- 只做純網路 helper
- 不管 socket runtime
- 不管 service policy

### `pkg/testutil`

- 根套件只放輕量測試輔助（`VerifyTestMain`、`InCI`、測試時鐘），只依賴 `pkg/appcore`
- 測試替身（`StubSocket`、`StubService`、`StubFinder`、`EventLoopSocket`、`NoopPlayerStore`）在 `pkg/testutil/fakes`；倉庫路徑定位在 `pkg/testutil/repo`（純標準庫）
- 只供測試使用，正式程式碼不可 import

## 判斷規則

`pkg` 套件至少要有兩個實際 consumer；只有單一服務使用的放回 `cmd/<服務>/internal`（例如故障注入已搬到 `cmd/world/internal/faultinject`）。

若一個 package 的修改會同時牽動 `Gate / Central / World` 三邊流程，它多半不該在 `pkg`。

若一個 package 名字看起來很 generic，但 API 內已出現 `Login`、`Logout`、`Session`、`World`、`Gate`、`Central` 這類詞，它已經開始越界。

## 原則

- `pkg` 要薄
- `cmd/*/internal` 要厚
- 依賴方向只往下，不往回滲

## 根層 `internal/game` 例外

需要由正式服務與根目錄 `tools/` 共用的純遊戲規則，可放在根層 `internal/game/{domain}`。這是 module 內部共用的遊戲邏輯，不屬於公開 `pkg` 基建。

只允許放：

- 與傳輸、資料庫及服務 Runtime 無關的 Domain 型別與規則。
- 可由 World 與工具注入不同 Adapter 的小型 consumer-side interface。
- 確定已有正式服務與工具兩個實際 consumer 的邏輯。

禁止放：

- Protocol／message／socket 型別。
- MySQL、Redis、GORM 或特定服務的 Store 實作。
- World、Gate、Central 等服務生命週期與路由規則。
- 只為未來可能使用而提前抽出的業務 package。

依賴方向：

```text
cmd/world ─┐
           ├─→ internal/game
tools ─────┘
```

`internal/game` 不得反向引用 `cmd/*/internal`；工具仍統一放在根目錄 `tools/`；個人用、不進 git 的工具放 `tools/private/`（見 [工具總覽](../30-部署與開發/工具總覽.md)），正式程式、CI 與腳本不得依賴它。

### 根層 `internal/combat`、`internal/wallet`

- `internal/combat` 放 PvP 配對與戰鬥 session 的領域規則與型別（`MatchService`、`PickOpponentWith`、快照可挑戰判斷），由 World 與 simulator 共用；`internal/wallet` 放戰鬥結算的金幣分配。
- `internal/combat` 可依賴 `internal/wallet`；兩者對 `internal/game` 只能依賴結算公式葉節點 `internal/game/combat`，也不可依賴 MySQL、Redis、GORM 或 `cmd/`；持久化實作在 World 的 `cmd/world/internal/store/combatstore`，由 `internal/combat/boundary_test.go` 與 `internal/boundary_test.go` 守護。

## 時間規則

時間分三種來源，另加日誌類。判斷原則：**拿來與遊戲時間戳比較、或寫進會被這樣比較的欄位，就是遊戲時間**。

| 種類 | 用途 | 來源 |
| --- | --- | --- |
| 遊戲時間 | 骰子恢復、冷卻、任務輪次與領獎期限、戰鬥場次到期與保護期、商店與抽獎每日重置、公告上下架、GM 發放請求時間與重試期限、聊天時間戳與保留期、Record 事件 `OccurredAt`、玩家活動時間（`updated_at`）與封存、帳號保留 | Central 校正時鐘：`App.GameNow()`（`pkg/appcore/clock.State.Now`），只前進 |
| 計時 | 逾時、TTL、退避、心跳、寬限、期限、限流、關機等待 | 主機單調時鐘：`time.Since`／timer；`time.Now()` 只用來算期限 |
| 資料庫／Redis 仲裁 | Record outbox 租約、重試排程、第一次嘗試時間（`next_attempt_at`）與送出時間；Redis TTL | MySQL `NOW(3)`（連線 `time_zone` 為 UTC）／Redis 伺服器端 TTL |
| 日誌、指標、trace | 時間戳、耗時 | 主機時鐘 |

校正時鐘：

- Central 是遊戲時間來源，其主機時鐘（須 NTP，見 [Docker 生產部署](../30-部署與開發/Docker生產部署.md)）即遊戲時間；每秒（與 tick 異常跳躍時）以 S2S `TimeSync` 廣播給 Gate、World、Chat、Lobby，連線建立時立即補送一次。
- 接收端 `ApplySync`：第一次同步或偏差達 1 秒直接跳到 Central（記 Warn、`game_time_sync_jumps_total`，第一次不計），其餘每秒最多修正 100 ms 逐步追上；對外遊戲時間取 max(上次, 新值)，往回跳時遊戲時間停住直到牆鐘追上，不倒退。偏移見 `game_clock_offset_seconds`。
- 收到第一則 `TimeSync` 前 `/ready` 不就緒：Gate 登入回 `AuthServiceUnavailable`、World 不建立玩家（回 Gate 服務不可用）、Chat 不寫訊息、Lobby 的公告與 GM 發放回 503。整合測試的假 Central（`integration/testenv`）同樣會送 `TimeSync`，不另設旁路。
- Record 不連 Central：事件時間只採生產者填的 `OccurredAt`，缺漏進死信；Record 主機時鐘只界定日分表範圍（界限寬達數日）。

用法：

- Gate、World 直接用 `App.GameNow`。World 注入點：盤面 router（每個指令取一次 now）、任務、戰鬥 `MatchService` 與 `combatstore.Sessions`、`gamestore.Memory.SetNow`、抽獎服務 `SetNow`、GM 發道具佇列 `SetNow`、玩家歸檔、gorm `NowFunc`。
- Chat、Lobby 以 `pkg/centralclock.Start(app, tcpCfg)` 連 `<appID>.dial.central`（Central 60003／60004，S2S 授權讀 `s2s_auth.central`），`TimeSync` 在 App 事件迴圈套用，之後一樣用 `App.GameNow`。
- World 的 gorm `NowFunc` 是 `App.GameNow`：`autoCreateTime`／`autoUpdateTime` 與活動時間的 raw SQL 都寫遊戲時間，比較這些欄位（封存截止、帳號保留、金幣調整回看窗口、任務補償回看）也用遊戲時間；只有 outbox 的租約與排程欄位用 `NOW(3)`。
- 規則函式以參數接收 `now`；注入點為 nil 時的 `time.Now` 後備只給測試與模擬器。
- `internal/archtest/game_time_boundary_test.go` 以 go/ast 禁止 `internal/` 與 `cmd/*/internal/` 直接用 `time.Now`／`time.Since`／`time.Until`；例外列在 `gameTimeAllowlist`（檔案或函式＋理由），失效項目也會讓測試失敗。

## World 與 simulator 共用遊戲邏輯

原則：**遊戲邏輯只有一份，通用系統放在 `internal/gamecore`，盤面等玩法放在 `internal/game`；World 與模擬工具（共用 `internal/game/simulation`）只實作外部依賴（儲存、亂數、時間）的轉接器。** simulator 只測遊戲邏輯，不測儲存語意（交易、回滾、冪等、outbox）。

| 套件 | 共用的邏輯 | World 轉接器 | simulator 轉接器 |
| --- | --- | --- | --- |
| `gameconfig` | 設定載入與跨表檢查（`Load`）；`Bundle` 帶出已驗證的骰子規則（`DiceToken`）與戰鬥配對設定（`CombatMatch`） | `buildWorldSnapshot` | `loadRunner`、`LoadMissionRunner` |
| `dicetoken` | 骰子規則：容量、初始數量、恢復間隔的驗證（`LoadOptions`、`Options.Validate`）、玩家效果換算（`WithEffects`）、懶恢復與扣除（`Recovered`、`Consume`） | `board` 在玩家交易內套用（`recoverDiceTokens`、`newDiceSpend`） | 尚未模擬骰子顆數，只共用 `Load` 的設定驗證 |
| `gamecore/condition` + `boardconfig.EvaluateCondition` | 條件樹求值；運算元由 `condition.Readers` 注入，盤面運算元（經過格數、建築等級）在 `boardconfig` | 變數與建築讀取器 | 變數讀取器（`variableReader`） |
| `gamecore/variable` | 缺值用預設、越界報錯（`Definition.Resolve`）與變數服務 | 組合根注入 `gamestore.VariableStore` | 同左 |
| `board` | 擲骰結算：`Inventory`（研究費用、工廠砲彈、事件獎勵）、`EffectStore`（研究效果替換） | `playerTx`（玩家記憶體交易） | `inventoryMap`、`effectList` |
| `boardconfig` | 建築升級：`PlanBuildingUpgrade`、`PayBuildingCosts`（直接收 `board.Wallet`）、`ApplyBuildingEffects` | `playerTx` | `simWallet`、`effectList` |
| `turn` | 擲骰回合流程 `turn.Play`：效果、擲骰、研究費用不足降級重算、工廠效果、抽獎條件、商店報價、收集抽獎、掛回獎勵 | `RollDiceDeps.turnPorts`（`Commit` 在玩家交易內保存並抽獎） | `Runner.turnPorts`（`Commit` 在玩家副本上套用並抽獎） |
| `gamecore/mission` | 任務接取與事件流程 `Play.Activation`／`Play.Event`（輪次、流程、跨輪次欄位、待領獎勵）、`IsClaimExpired`、`IsAutoClaim` | `restoreMissionState` 與 `missionStateRecord` | `missionSim.commit` |

規則：

- 規則函式以參數接收時間（`now time.Time`），不自己呼叫 `time.Now()`；simulator 有自己可調的時間來源。
- World 遊戲時間取 Central 校正時鐘（`clock.State.Now`，對外為 `App.GameNow`）：盤面指令建立請求時取一次 now，同一指令的規則判斷與任務事件時間戳共用；combat `MatchService`、SQL store 與玩家歸檔也注入同一時鐘。TTL、逾時、重試、metrics 與 journal 等計時仍用主機時鐘，outbox 租約以資料庫 `NOW(3)` 仲裁；完整規則見〈時間規則〉。
- 模擬器 `RollOptions.Seed` 非 0 時以 PCG 決定加星道路、事件挑選、商店報價、互動 ID 與抽獎，配合 `Runner.Now` 可完全重現。
- 抽獎必須在儲存的鎖內「讀狀態、抽、寫狀態」，所以 `turn.Play` 把抽獎交給 `Commit`，不在共用層先抽。
- 兩邊行為不同時，**以 World 現行行為為準**，只改 simulator。
- 新增 World 與 simulator 都會用到的規則時，先放 `internal/game`，不要在 `cmd/world/internal` 寫一份再讓 simulator 複製。
- 合法設定只有 `gameconfig.Load` 這一份：World 的 `buildWorldSnapshot`（啟動與熱重載）與模擬工具都經它驗證，`cmd/world` 不得另外放寬或加嚴；`services/config_test.go` 以一致性測試守住兩邊對壞設定的結論相同。

仍未共用：

- 任務領獎（`claim`）與抽獎狀態的儲存：World 在玩家交易內保存抽獎計數、紀錄與道具，simulator 以記憶體狀態與可重現亂數，這屬於儲存語意，不共用。
- 貨幣變數沒有資料列時，World 視為 0；若日後變數 `Default` 不為 0，兩邊要一起決定規則。

## `internal/gamecore` 通用遊戲系統

與玩法無關的系統（variable、item、effect、condition、lottery、mission、shop）放在 `internal/gamecore/<系統>`，每個系統一個包，含規則、設定載入與必要的服務。

設定換版規則（`configcompat`）也放在這裡：它只依賴 `pkg/dataconfig` 的生成物與機制，不依賴其他 gamecore 子包；World 以 `configcompat.Checker{}` 注入快照 store，任務狀態版本相容判斷用 `configcompat.IsMissionStateCompatible`，變數遷移步驟用 `configcompat.LoadVariableMigrationSteps`。

- 依賴方向：`cmd/world` → `internal/game`（玩法層）→ `internal/gamecore`。`gamecore` 不得引用 `cmd`、`tools`、`integration`、`internal/game`，子包之間也不得互相引用；由 `internal/gamecore/boundary_test.go` 強制。
- 外部能力一律由消費端定義介面並以建構子注入：Store（`variable.Store`、`effect.Store`）、Handler（`item.Handler`）、取值來源（`condition.Readers`）、獎勵目錄（`mission.RewardCatalog`）、指標回呼（`variable.WithSaveFailureHook`）。
- 持久化轉接器放在 `cmd/world/internal/store/gamestore`（`VariableStore`、`EffectStore`），由 `services` 組合根建立。
- 跨系統的載入與驗證放在 `internal/game`：`gameconfig`、`missionconfig`、`boardconfig`（盤面運算元 `OperandTypeBoardSpaceKindPassedCount`／`OperandTypeBuildingLevel` 與 `EvaluateCondition`、效果來源 `board.EffectSource*`）。
- 不要把 `GameConfigs` 當 service locator 傳進 `gamecore`；載入函式只在啟動時呼叫一次，之後只傳具體的 `Definitions`。
