# 工作規範

## 使用技能

寫、審、除錯 Go 程式碼先使用 `golang-how-to` 技能，由它載入對應技能。通用規則以技能為準；本文件只留技能未涵蓋、且不與技能衝突的專案特有規範。

## 操作習慣

- 新增說明文檔時，檔名與內容皆使用中文。保留通用慣例名（`README.md`）與專有名詞（Docker／Redis／TCP／World／SLO／p0 等縮寫）。

## 結構與重構

- 模組須有明確責任與邊界；禁止為形式拆分、新增抽象層、讓模組過薄，或把單一流程切成無實質意義的層。
- 各 app 的同一角色使用相同命名；同義不混用（如 `svc` 與 `service`），不同責不同名。不為對齊結構強行拆併。
- 正式碼禁止匯出 slice／map 型別的 package var（可被任何套件改寫，等同全域可變狀態）；要公開常用清單就提供函式（回傳複本）或未匯出變數加存取函式，由 `internal/archtest/exported_mutable_var_test.go` 守門。
- 重構須有明確收益、小範圍、可回滾，只動正在修改的區域；禁止風格性重構、over-engineering、big-bang 重寫、為「拆薄」增加 wrapper 或重複 code。使用 `golang-refactoring` 技能。
- `refactor` 提交不得改變可觀察行為（回傳值、錯誤、日誌、指標、啟動條件等；commit-msg 軟提示會在 refactor 增刪 logger 訊息時提醒）；行為變更另開 `fix`／`feat` 提交，並在提交內文註明「行為變更」；`refactor` 本身也要在內文標「無行為變更」並寫出等價理由（為什麼行為不變）。已落地的提交不必回改。commit-msg hook（`scripts/check-perf-commit-msg.sh`）對 `fix`／`feat` 提交的內文既無「行為變更」也無「無行為變更」時，會在 stderr 印一行軟提示：只提醒、不擋提交（exit code 不變），範圍檢查（`make perf-msg-check`、CI `perf-commit-msg`）不印以免吵雜。對外可見的變更（指標名稱或標籤、日誌訊息、設定鍵、告警條件）務必標註，維運才知道要檢查倉庫外的面板與告警。

## 依賴注入

使用 `golang-dependency-injection` 技能，預設手動建構注入。

- App 層依賴（RedisClient、PlayerStore、GameStore 等）以 Functional Options 注入，欄位私有，透過存取方法（`PlayerStore()`）提供。
- `samber/do/v2` 可用於新 service（使用 `golang-samber-do` 技能）；既有 service 維持手動 DI，injector 只存在於 `run.go`。

## Handler 防禦性檢查

- nil-check 先檢查容器：`r.App == nil`（或 `r.Deps == nil`）、`c == nil`，再檢查核心參數，不檢查個別方法參數。例：`if r.App == nil || sock == nil { return }`。
- 不檢查 Init/Constructor 已驗證的欄位；nil 場景用獨立 TestCase 覆蓋，不寫進 production handler。
- per-connection goroutine + timer（handshake timeout 等）改為中央掃描 goroutine。若能由 socket 狀態（如 `sock.ID() == 0`）判定逾時，就不需 per-connection timer。參考 `cmd/gate/internal/handler/user/connect_watchdog.go`。

## 效能慣例

通用寫法使用 `golang-performance`、`golang-concurrency` 技能。

- 所有訊息型別必須實作 `PackTo(buf []byte) []byte`（預序列化的 `msg.OwnedRaw`、`tcpsocket.packedMsg` 例外，只實作 `Payload()`，由 `handleOutgoing` 直接 writev；send 路徑經 `socket.sendBuf` 零分配）；`Pack()` 委託 `PackTo(nil)`；固定大小訊息用 `binary.LittleEndian.AppendUint{64,32}`；可變大小訊息的 `Payload []byte` 搭配 `Reset` 保留 backing array。參考 `pkg/msg/chat/chat_codec.go`、`pkg/msg/board/forward.go`。
- 高頻唯讀路徑（config 快照、service picker、路由表）用 `atomic.Pointer` / `atomic.Value` + copy-on-write，不用 `sync.Mutex`。參考 `pkg/dataconfig/snapshot.go`。

## 測試

通用寫法使用 `golang-testing` 技能；測試類型與名詞見[測試名詞與類型說明](../30-部署與開發/測試名詞與類型說明.md)。新增測試前先自問：「改壞對應正式碼一處，這個測試會失敗嗎？」不會就不要寫。下列判定標準也用於日後清理無效測試。

**不該寫（或清理時刪除）**

- A：只重述常數、字串字面值、JSON 鍵名、TTL 數值。改常數時測試只會跟著改。
- B：只測日誌文字、顯示字串、模擬器內部 key；只測自己的 stub／mock；只斷言「不 panic」或「建構式回傳非 nil」；或測的是等價突變。
- C：與同套件其他測試重複覆蓋同一行為。刪除時須指出重複它的那個測試名，並確認其斷言涵蓋被刪測試的值。

**合併**

- D：同套件多個「釘住字面值」的小檔或小測試，合成一個表格測試。合併後須保留原本檢查的每個值，且對應正式碼改壞一處時仍會失敗。

**必須保留**

- E：驗證行為（鎖、重試退避、冪等、回滾、競態、邊界）；跨檔案契約（程式 ↔ 告警規則／compose／設定範本／文件／腳本、持久化 JSON 鍵與 Redis key、跨服務訊息欄位）；舊格式相容；安全矩陣；既有 bug 的回歸測試。
- F：`example_test.go`、`main_test.go`（goleak）、fuzz、benchmark 一律不刪。

**標記**

- G：在乾淨 checkout／CI 跑不起來的測試：讀 `docs/`（獨立倉庫，不在主倉庫版控內）、讀倉庫外路徑、需要資料庫或外部服務卻沒加 `integration` build tag 與環境變數守門。讀 `docs/` 的測試須在檔案不存在時 `t.Skip`，且對照的核心斷言不能只靠文件。

**刪除的證據（擇一，沒有證據就不要刪）**

1. 把對應正式碼改壞一處，該測試仍通過。
2. 刪除後該套件 `go test -count=1 -cover` 覆蓋率沒有下降（至少量三次；有浮動的套件取平均）。
3. 明確指出重複覆蓋它的另一個測試。

覆蓋率不變只代表沒有語句失去涵蓋，不代表行為仍被斷言；「只有 NotPanics」的測試若刪除會掉覆蓋率，應改寫成有斷言的測試，而不是直接刪。每批清理以套件為單位提交，覆蓋率下降超過 0.5 個百分點就停止並回報。

## Go module

服務程式碼只有一個 module：`local/server`（根目錄 `go.mod`，無 `go.work`；`go tool -modfile` 一律經 `scripts/gotool.sh`（固定 `GOWORK=off`，configaudit 的 `TestGotoolsOnlyInvokedThroughEntry` 與 archtest 守門；目錄樹出現 `go.work` 時直接下會報 `-modfile cannot be used in workspace mode`）；`Makefile` 頂端 `export GOWORK := off`、`ci-bench-gate.sh`、`lint-other-goos.sh` 另設，是為了直接呼叫的 `go test`／`go build`；`.gitignore` 擋任何目錄的 `go.work*`，`ci-lint-extra.sh` 以 `git ls-files '*go.work*'` 守門）。另有兩個隔離用 module：工具依賴的 `tools/gotools/go.mod`（`local/server/tools/gotools`），以及 `deps/` 子模組各自的 `go.mod`（`deps/PJA-Database` 等，`deps/go.mod` 為 `local/deps`），都不在根 module 的 `./...` 內。

- 服務實作在 `cmd/<service>/internal/`；服務間只能走 TCP 協定（`pkg/msg`、`pkg/protocol`），不得引用彼此 internal，由 Go 的 `internal` 規則在編譯期擋下；`internal/archtest/cmd_boundary_test.go` 另守「`cmd` 下非 `internal` 的套件只能是 `main`」，避免有人在 `cmd/<service>/` 下開可被別的服務 import 的公開套件；同檔另禁止 `cmd/**` 正式碼匯入 `local/server/tools/`（服務行程不得依賴營運工具）。
- 新增依賴前先評估：①標準庫與既有依賴能否解決（Go 1.27 標準庫已有 `uuid`，`gomodguard_v2` 擋 `google/uuid`、`gofrs/uuid`、`hashicorp/go-uuid`）；②授權相容（本專案 MIT，可接受 MIT／BSD／Apache／MPL-2.0）；③維護狀態與 importer 數；④AI 代理加依賴前先問使用者。`gomodguard_v2` 只是黑名單，擋不到沒列的新 module，所以由評估把關。升級持久化、序列化、網路、認證、加密類函式庫（gorm、mysql 驅動、rueidis、amqp091-go、goccy/go-json、x/crypto）時要讀 CHANGELOG。
- 新增依賴在根目錄 `go get` 後 `go mod tidy`；不進版控的 `tools/private` 由 `go.mod` 的 `ignore ./tools/private` 排除，本機 tidy 結果與 CI 相同（`make ci-lint`、pre-commit 與 CI 都以 `go mod tidy -diff` 檢查，見[開發規則](../30-部署與開發/開發規則.md)）；私人工具要以明確套件路徑 build／vet，`./...` 不含它們。
- 工具依賴（`golangci-lint`、`benchstat`、`govulncheck`、`goimports` 等）以 `tools/gotools/go.mod` 的 `tool` directive 宣告，執行一律走唯一入口 `scripts/gotool.sh <name> [參數]`（用法同 `go tool`，例如格式化 `scripts/gotool.sh golangci-lint fmt <檔案>`，或用對應的 make 目標）：它固定 `GOWORK=off`，並以腳本位置推導 modfile 絕對路徑，任何工作目錄（含 `deps/PJA-Database` 子模組內）都能呼叫；`configaudit` 守門擋其他地方直接寫 `-modfile=tools/gotools`。根目錄的 `go.mod` 沒有這些工具，直接 `go tool golangci-lint` 會得到 `no such tool`。

有「紅線」的 `pkg/` 套件（含 `pkg/testutil`）見 [[共用邊界]]；其餘套件的職責以各套件的 `doc.go` 為準。

## 刻意不做（第十六輪定案）

審查反覆提到、但已決定不處理或暫緩的項目；下輪審查不必重報，條件變了再重評。

- **一參數一行**：正式碼共 1466 處呼叫，逐一改成一參數一行的收益不抵 diff 噪音；新碼依 `gofumpt` 即可。
- **`lll` 上限 160 定案**：不再下調；超長行用拆變數或換行處理，不為了行寬改函式簽名。
- **錯誤訊息 `%s` → `%q`**：其餘檔案碰到再改，不做全專案掃改。
- **參數超過 4 個的函式**：不設增長上限；新函式盡量 ≤4 個參數，必要時用 options 結構。
- **`contextcheck` 刻意不開**：98 筆告警都是刻意脫離取消 ctx（關機寫回、背景補償、延後任務），逐筆加 `nolint` 只增噪音；脫離取消的地方以註解說明並用 `context.WithoutCancel` 或獨立 ctx。
- **Gate 依賴具體 `App`（R-L5）與 `GameStore` accessor 寬介面（SI-L5）**：暫不收窄；收窄會新增只有單一實作的介面，與「禁止為形式新增抽象層」衝突，待有第二個實作或測試替身需求再評估。
- **grantitem 舊 operationID 相容解碼**：待維運確認線上已無舊格式佇列訊息後才能刪，確認前不刪。
- **Debian bookworm → trixie 與 `FlightRecorder`**：待量測（映像大小、啟動與記憶體、診斷成本）後再決定，目前不升不開。
