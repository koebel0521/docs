# 玩家變數

現行 Variable 行為；完整方案背景見[方案草稿](../90-參考附件/方案草稿/玩家變數與資源消耗規範.md)。

- 定義：Luban `Variable`，Runtime 使用 `int64`、default、上下限與 `SyncClient`。
- 保存：保存所有 variable 值（包含 default），一律寫入；玩家恢復時一併載入。
- 同步：登入回傳 Client 可見變數；登入後只回傳變更值。
- 權威：Server 決定數值與扣除結果，Client 不得自行修改。
- 實作：`cmd/world/internal/variable`；配置載入見 `config.go`，快照見 `Snapshot`。

## 增減的原子性與骰子規則

- `variable.Service.Add` 走 `GameStore.AddVariable`：在玩家交易內讀取、加減、檢查 Min/Max 後寫回，與擲骰扣骰、道具使用等交易內寫入互斥。測試替身沒有實作時退回讀後寫。
- 骰子數量（`DiceCount`、`DiceRecoveryAt`）**不允許超過上限**，只由擲骰與登入載入時的恢復寫入（`nextDiceState` 會截回上限）。
- 因此設定載入時會拒絕「立即生效」道具調整骰子變數（`services/config.go` 的 `validateItemVariables`）：GM grant 在背景 goroutine 套用，會繞過上限，也會與載入時讀後寫的 `RecoverDiceTokens` 互相覆蓋。背包道具走使用交易，不受此限。
- 若日後要發放骰子獎勵，做成專門的「補骰子到上限」動作，由骰子邏輯處理，不要用道具直接加。

變數 migration 使用[配置操作入口](../30-部署與開發/配置操作入口.md)。
