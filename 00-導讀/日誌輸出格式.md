# 日誌輸出格式

所有服務透過 `pkg/logger`（zerolog）輸出日誌，預設為 `json` 格式，方便容器平台、集中式日誌收集器與機器解析。

本專案的 Go module path 是 `local/server`，因此服務內部套件使用 `local/server/...` 匯入；這是本機 module 名稱，不代表需要連線到外部網站。

本機閱讀可切換為人類可讀的 `text`：

```powershell
go run ./cmd/gate --config config/dev/gate.yaml --log-format=text
```

`--log-format` 適用於所有 `cmd/*` 服務，可使用 `text` 或 `json`。讀取設定之前（解析旗標失敗等極早期錯誤）的少數日誌一律是 `text`。

日誌層級可搭配 `--log-level=debug|info|warn|error` 設定，預設 `info`。

## 非同步日誌（`LOG_ASYNC_BUFFER`）

環境變數 `LOG_ASYNC_BUFFER`（筆數，預設 0＝關閉，行為與以前相同）。開啟後日誌先進 zerolog diode 環形緩衝、由單一 goroutine 寫 stderr，Gate／World 事件迴圈不再為每行日誌付一次 write syscall（本機 benchmark：同步約 2.6µs/op → 非同步約 0.19µs/op，3 allocs）。和 `LOG_SAMPLE_RATE` 一樣只讀環境變數（logger 在讀設定檔前就要設定）。

- 取捨：緩衝滿了會丟**最舊**的日誌，計入 `logger_async_dropped_total`，並在 stderr 寫一行 Warn `async log buffer overflow, entries dropped`（欄位 `dropped`、`dropped_total`）。
- 行程崩潰（panic、SIGKILL）時，緩衝內最後幾筆可能遺失；正常結束由 `startup.Main` 的 `logger.Close()` 排空。connect／disconnect 的 Info 維持不降級。
- 建議壓測時先在單一服務試開（例如 8192）並觀察 `logger_async_dropped_total`；是否正式環境預設開啟尚未決定。
