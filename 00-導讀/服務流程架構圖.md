# 服務流程架構圖

本文件集中說明 PJA-Server 的六個後端服務與 User 測試客戶端：

- **Gate**：玩家 TCP 閘道與 session 狀態機。可複數部署；每個實例持有自己的玩家連線，路由與服務地址由 Central / Redis / Lobby 協調。
- **Central**：帳號驗證、請求去重、World 分配與玩家路由。可複數部署；MySQL 是帳號真相來源，Redis 保存快取、鎖與短期 journal。
- **World**：即時遊戲狀態、進度持久化與重啟恢復。可複數部署，依 `world_id` 分片；同一玩家的即時狀態由一個 World 實例負責。
- **Chat**：聊天頻道、即時訊息與歷史同步。可複數部署；歷史以 Chat MySQL 為來源，不能只依賴單一實例記憶體。
- **Lobby**：服務探索與 GM 管理 API。可複數部署；透過 Redis TTL 移除停止 heartbeat 的服務。
- **Record**：消費 RabbitMQ 事件並寫入流水資料庫。可複數部署；多個 consumer 共用 queue 分攤事件，不重複消費同一訊息。

圖中的 `× N` 代表同一服務可以啟動多個實例；`World × N` 是分片，不是共享同一份玩家記憶體；`Record × N` 則是 RabbitMQ consumer 水平擴充。

主要流程為「登入 → Gate 轉送遊戲／聊天 → 非同步記錄 → 登出寫回」，World 重啟時則從 Redis 取得恢復候選，再由 Gate 驗證是否保留。

## 服務責任邊界

| 服務 | 詳細責任 | 主要輸入／輸出 | 多實例注意事項 |
|---|---|---|---|
| Gate | TCP 長連線、session、heartbeat、協定驗證、登入／登出／遊戲／聊天轉送、排空與重連 | User、Central、World、Chat；回傳玩家回應與廣播 | 連線是本地狀態；路由不能只放在單一 Gate memory |
| Central | 帳密驗證、限流、request journal、World 分配、user/account/gate/world 路由、跨服務登入協調 | Gate 登入／登出、World 路由事件；回傳帳號結果與 World 指令 | MySQL 保存帳號真相；Redis 保存快取、鎖與短期去重資料 |
| World | 遊戲規則、玩家／頻道狀態、道具／盤面持久化、登出寫回、重啟恢復與 GM 道具操作 | Gate 遊戲請求、Central 登入、GM 指令；回傳遊戲結果、廣播與流水事件 | 依 `world_id` 分片；單一玩家同時只由一個 World 實例承載 |
| Chat | 頻道成員、文字訊息、廣播、歷史保存、ChatSync 補送 | Gate 的加入／離開／傳送／同步；回傳 ChatDeliver 與歷史 | 歷史以 MySQL 為來源，不能只保存在單實例記憶體 |
| Lobby | heartbeat、地址／負載清單、服務探索、kick／ban／公告／World drain | 服務註冊與管理 HTTP；回傳清單或寫入 GM 狀態 | Redis TTL 移除失聯實例；不承載玩家主流程狀態 |
| Record | RabbitMQ 事件消費、正規化、批次落地每日分表、查詢／統計 | `record.events`；寫入 `record_events_YYYYMMDD` | 共用 consumer queue 做水平擴充，避免同一事件被多個實例重複處理 |
