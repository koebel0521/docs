# P0 作業清單

這份清單把目前最重要的三件事落成日常作業：

1. reconcile / audit / sweep
2. queue / pool / latency budget
3. daily drill

目標不是多寫文件，而是把「先看什麼、先跑什麼、壞了先收斂哪裡」固定下來。
詞彙不確定時，先看 [觀測詞彙表](./觀測詞彙表.md)。

## 1. Reconcile / Audit / Sweep

### P0 目標

- 讓 `Central / Gate / World` 的 derived state 自動回正
- 避免短暫不一致拖成長期髒資料

### 先看順序

1. `State Audit (5m)`
2. 對應服務的 audit log
3. 服務內部索引與 Redis 快照
4. 最後才看 handler / TCP / DB log

### 值班判準

- `mismatch`：邏輯不一致，先查索引與 route
- `error`：audit 自己碰到外部依賴失敗，先查 Redis / MySQL / timeout
- `repair`：代表 audit 已修回部分 Redis 漂移，但根因還要追

### 固定收斂點

- `Central`：route / world registry / account cache
- `Gate`：session state / session-derived index
- `World`：users / channels / pending writeback / cache
- `Update1m`：各服務的 sweep + reconcile 入口；已補測，別只測單一 helper

### 工具每日檢查

- `game_state_audit_total` 是否出現 `mismatch` 或 `error`
- `game_resource_recycle_total` 是否持續有值，代表 1m sweep 有在跑
- `request journal` 是否有異常重送風暴
- `tools/dephealth` 是否顯示 `ready=ok / degraded / down` 與 queue / async failure 的整體健康摘要；它看的是 warn threshold，不是任一 queue 波動都算異常
- `make reconcile-test` 是否能過，確認 `Update1m` 收斂測試未壞
- `scripts/reconcile-test.ps1` 是否能跑，確認非 Makefile 入口也可驗證
- `Central` 的 `Update1m` 已有 direct coverage，且覆蓋 audit 去重

## 2. Queue / Pool / Latency Budget

### 目的

- 先看到快爆點，不等 overflow 才處理
- 把 backlog 當一級風險

### 固定盯的三件事

1. `tcp_send_queue_depth`
2. `game_event_queue_depth`
3. DB pool 使用率

### 門檻

- `tcp_send_queue_depth` > 4096：慢 consumer 風險
- `game_event_queue_depth` 長時間高：事件消化追不上
- DB pool 長期接近上限：先看 query latency 與鎖競爭

### 搭配看的圖

- `Handler Latency P95`
- `Handler Latency P99`
- `Login Path Internal Latency`
- `Login Outcomes (5m)`
- `Logout Outcomes (5m)`
- `Capacity Budget`

### 每日檢查

- `game_event_queue_overflow_total` 是否增加；有增就是 queue 真溢出，不只是 backlog
- `tcp_send_queue_overflow_total` 是否增加；有增就是 slow consumer 已被切掉
- 任一 handler p95 是否持續高於 0.2s
- 任一 handler p99 是否持續高於 0.5s

## 3. Daily Drill

### 目的

- 確認監控、告警、容量回歸、failover drill 不是空的
- 讓值班流程變成固定動作

### 建議執行順序

1. `scripts/monitoring-smoke.ps1`
2. `scripts/alert-drill.ps1`
3. `scripts/p0-daily-check.ps1 audit`
4. `scripts/p0-daily-check.ps1 capacity`
5. `scripts/p0-daily-check.ps1 reconcile`
6. `scripts/p0-daily-check.ps1 drill`

### 補充說明

- `monitoring-smoke` 先驗 Prometheus / Grafana / dashboard
- `alert-drill` 先驗告警路徑與 inhibition
- `本機監控` 是本機監控入口，先把 dashboard 接上，再看 `dephealth` / `opsdiag`
- `dephealth` 直接拉 readiness 與 queue / async failure 概覽；它用 warn threshold 判斷 `degraded`，先看整體健康，再下鑽細節
- `opsdiag` 再補 readiness、路由查核、關鍵 metrics 摘要
- 要封存事故時，優先用 `scripts/fault-archive.ps1 -FailOnEndpointDown`，避免把 readiness 已壞的快照當成成功封存
- `p0-daily-check env` 專跑監控 / 告警，必要時再帶 failover drill
- `p0-daily-check audit` 專跑監控 / 告警，並落 `consistencysnapshot`
- `p0-daily-check monitoringsmoke` 專跑監控 provisioning 驗證
- `p0-daily-check monitoringvalidate` 專跑 monitoring 文件與 provisioning 驗證
- `p0-daily-check alertdrill` 專跑 synthetic alert 驗證

## Merge Gate

這一段是正式 merge gate。碰到 session、routing、release 或 drill 相關變更時，至少要跑下面三組：

1. `scripts/merge-gate.ps1 -UpgradeNewTag <tag>`
2. `scripts/p0-daily-check.ps1 -Mode reconcile`
3. `scripts/p0-daily-check.ps1 -Mode failoverdrill`

若動到演練流程或資料一致性，再補下面任一組：

- `scripts/p0-daily-check.ps1 -Mode circuitbreaker`
- `scripts/p0-daily-check.ps1 -Mode faultdrill -FaultDrillPlayerID <uid>`
- `scripts/p0-daily-check.ps1 -Mode canary`

- 每日：`p0 daily check all`

- 每次 release 前：capacity / regression / failover 至少跑一輪
