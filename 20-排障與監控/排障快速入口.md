# 排障快速入口

先確認影響範圍，再依順序收集證據；需要完整命令與判讀方式時，進入[問題排查筆記](問題排查筆記.md)。

## 快速路徑

| 症狀 | 先做什麼 | 詳細章節 |
| --- | --- | --- |
| 服務不可用 | 檢查依賴健康、ready endpoint 與關鍵 metrics | [依賴健康總表](問題排查筆記.md#依賴健康總表) |
| 登入失敗或卡住 | 以 `requestID`、`gameTraceID`、`playerID` 查 Central、Gate、World 日誌。**日誌刻意不記帳號**（PII，以 `account` 搜必為 0 筆）；只知道帳號時先查 playerID：``SELECT player_id FROM `user` WHERE account = '<標準寫法帳號>'``（新帳號登入失敗前還沒有 playerID，改由 Client 回報的 requestID 或 Gate 日誌的連線來源定位） | [常見問題](問題排查筆記.md#常見問題) |
| 大量登入被拒（code 9）、`GameLoginCentralBusy` | Central 同時處理登入上限 64，確認是否為開服或重連尖峰；客戶端應退避重試 | [容量與壓測基準](容量與壓測基準.md#容量邊界) |
| 服務卡住、CPU 高、記憶體持續成長 | **先採證再重啟**：事件迴圈看 `game_event_loop_last_tick_timestamp_seconds`（`GameEventLoopStalled`）；pprof 可用時抓 `/debug/pprof/goroutine?debug=2`（Go 1.27 另有 `goroutineleak`）、`heap`、30 秒 CPU profile；pprof 不可用（正式環境缺省關閉）時優先看自動堆疊日誌；不結束行程的堆疊傾印用 `docker exec <容器> sh -c 'kill -USR1 1'`（直接寫 stderr、不受 `LOG_LEVEL` 影響，之後 `docker logs <容器>`）；最後手段 `docker exec <容器> sh -c 'kill -QUIT 1'`（不可用 `docker kill -s QUIT`，會被視為手動停止而不再自動拉起）會印出全部 goroutine 堆疊但**立即結束行程**，**World 會跳過最後寫回與 spill，MySQL 異常時不可對 World 使用**。關機卡住看 Error `shutdown timed out, goroutine dump` | [現場採證](問題排查筆記.md#現場採證服務卡住cpu-高記憶體持續成長) |
| 登入失敗但日誌找不到 `wrong password`、`session expired`、`drain complete` 等字串 | 這些字串不存在；改看回應碼、`game_login_total` 的 `result` 與 Debug `login failed, notifying gate directly`（`responseCode`，預設 Info 看不到）、Warn `expired gate session cleaned (sampled)`（每 10 秒一行，帶 `suppressed`）；連線被拒是 Debug 日誌，改看 `tcp_rejected_connections_total` | [日誌關鍵字速查](問題排查筆記.md#日誌關鍵字速查) |
| 關機後懷疑玩家資料遺失 | 搜尋 Error `world shutdown lost unsaved player game data`（落地檔也寫失敗）與 `world shutdown could not write player game data to mysql; spilled to file`（已落地、下次啟動重放） | [日誌關鍵字速查](問題排查筆記.md#日誌關鍵字速查) |
| 多 World 時部分玩家登不進去 | 檢查每個 Gate 的 `dial.world` 是否列出所有 World、Gate 日誌是否對每個 World 都有 `connect` | [多 World 部署](../30-部署與開發/多World部署.md) |
| 壓測或機器重開後 Docker 起不來 | `sailor-ingest.sock` 刪不掉時把 `%LOCALAPPDATA%\Docker\run` 改名再重啟 | [壓測手冊](../30-部署與開發/壓測手冊.md#陷阱與環境) |
| 玩家狀態不一致 | 先做只讀快照，再考慮 `staterepair` 或 `datasurgeon` | [資料修復工具](問題排查筆記.md#資料修復工具) |
| 發版後異常 | 暫停切流，確認版本、配置與回退點 | [升級相容性演練](問題排查筆記.md#升級相容性演練) |
| 指標或告警異常 | 先確認 Prometheus 抓取，再看服務分級與告警 | [Prometheus 關鍵指標](問題排查筆記.md#prometheus-關鍵指標) |

## 統一入口

```powershell
powershell -ExecutionPolicy Bypass -File ./scripts/private/p0-daily-check.ps1 -Mode env
```

會改資料的修復工具預設先使用 `-DryRun`；未確認快照與影響範圍前，不直接執行修復或 purge。
