# 玩家在線行為統計方案

> **文件狀態：已實作（2026-10-15，分支 feat/online-stats）。現行行為以[玩家在線統計](../../10-核心流程/玩家在線統計.md)為準，本文保留設計背景與取捨。**
>
> 與本文的差異：表名用單數（`player_session`、`player_statistic`）；衍生統計用 `SourceStatisticId` 欄位而不是 `Field` 字串；每日彙總由 World 執行（MySQL `GET_LOCK` 互斥），不經 Record；登入訊息沒有版本、平台、IP，報表沒有這些維度。
>
> 已決定：全 Server 共用同一個換日時刻（與任務重置相同，現為 UTC 0:00，即台灣 08:00）；分析資料存 MySQL，不另架 ClickHouse。
> 本輪只做在線行為；遊戲行為（擲骰、戰鬥、金幣等）不在範圍內，但事件格式與 Statistic 設定表需預留其擴充。

## 一句話

玩家上線、在線、下線時各發一則事件；打卡單（`player_sessions`）保存每次上線的原始紀錄，Statistic 引擎依設定表把事件累計成數字（在線時長、登入天數、連續登入等），報表從打卡單彙總。

## 範圍

| 本輪做 | 本輪不做 |
| --- | --- |
| 上線、下線、在線時長、在玩時長（排除掛機） | 擲骰、戰鬥、金幣等遊戲行為事件 |
| 登入天數、連續登入、最長連續登入、上線次數 | 經濟帳本與對帳 |
| 當機時未關閉的打卡單回收 | Statistic 同步給 Client（需改 Protocol） |
| DAU、新增、留存、時長分布、版本／平台比較報表 | 任務改讀 Statistic |
| | Statistic 的 `Filter` 條件 |

## 已定決策

| 項目 | 決定 | 說明 |
| --- | --- | --- |
| 換日時刻 | 全 Server 共用一個遊戲日換日設定 | 與任務重置相同，現為 UTC 0:00（台灣 08:00）。統一用 `mission.ResetSchedule.LocalDate` 判斷遊戲日；實作時把設定鍵由 `mission_reset` 直接改名為全域的 `day_reset`，不保留舊鍵（dev、docker、prod 三份 world.yaml 同步改），任務與 Statistic 共用，不得各自另訂換日規則 |
| 時間來源 | `App.GameNow` | 與任務、盤面共用 Central 校正時鐘 |
| 分析資料庫 | MySQL | 每日彙總表；之後資料量大再評估 ClickHouse，可從打卡單補歷史資料 |
| 掛機門檻 | 預設 5 分鐘，做成設定 | 距最後操作超過門檻的時間只算在線、不算在玩 |
| 寫入頻率 | 記憶體累加，每 5 分鐘整台 World 批次寫入一次 | 當機最多少算一個週期；週期做成設定 |
| 建表方式 | 開發期由 World `AutoMigrate` 建表 | 上線前隨 PJA-Database 正式 migration 版本鏈一併寫入 |

## 流程

```text
玩家上線（World 確認登入成功）
   ├─► 建立打卡單 player_sessions
   ├─► 發 SessionStarted ──► Statistic：登入天數、連續登入、上線次數
   └─► 記憶體記下 sessionStart、lastFlushAt、lastActionAt

在線中（只在記憶體）
   └─ 收到玩家 request ──► 更新 lastActionAt

每 5 分鐘（整台 World 一次，加隨機偏移避免所有 World 同時寫）
   └─ 每位在線玩家：
        online_sec += now - lastFlushAt
        active_sec += 上述區間中距 lastActionAt 未超過掛機門檻的部分
        ├─► 發 SessionTick ──► Statistic：在線秒數、在玩秒數
        └─► 打卡單更新 last_heartbeat_at、累計秒數（同一條批次 SQL）

玩家下線
   ├─► 補寫最後一段時長（同 SessionTick 計算）
   ├─► 關閉打卡單：ended_at、end_reason
   └─► 發 SessionEnded

World 當機（打卡單沒關）
   └─ 回收器：last_heartbeat_at 超過 10 分鐘未更新
        └─► 以 last_heartbeat_at 為 ended_at 關單，end_reason = reaped
```

跨日：SessionTick 的時長若跨越換日時刻，依換日時刻切成兩段分別計入兩天的週期統計；跨日後仍在線的玩家視為新的一天已登入（登入天數、連續登入於跨日後第一次 Tick 更新）。

## 資料表

### player_sessions（打卡單）

每次上線一列，是所有在線統計的原始資料，之後統計規則改變或換分析庫都能從它重算。

| 欄位 | 說明 |
| --- | --- |
| `session_id` | 主鍵 |
| `player_id`、`world_id`、`gate_id` | 索引：`(player_id, started_at)` |
| `started_at`、`ended_at` | `ended_at` 為 NULL 表示仍在線 |
| `last_heartbeat_at` | 批次寫入時更新；回收器用。索引：`(ended_at, last_heartbeat_at)` |
| `online_sec`、`active_sec` | 本次累計 |
| `end_reason` | `normal`、`kicked`、`timeout`、`replaced`（重複登入被頂掉）、`reaped`（當機回收） |
| `client_version`、`platform`、`ip_hash` | 分析與客服用；IP 只存雜湊 |

### player_statistics（Statistic 數值）

| 欄位 | 說明 |
| --- | --- |
| `player_id`、`stat_id`、`period_key` | 複合主鍵 |
| `value` | `int64` |
| `updated_at` | |

`period_key`：`L`（總計）、`D20261015`（日）、`W202642`（ISO 週）、`M202610`（月）。日、週、月的舊資料定期清除，總計永久保留。

### 每日彙總表

報表不直接掃打卡單，每天換日後由背景工作彙總前一天，以日期為鍵、先刪後寫，可重跑。

| 表 | 內容 |
| --- | --- |
| `stat_daily_global` | DAU、新增玩家、總／平均在線與在玩時長、上線次數、各 `end_reason` 數量 |
| `stat_daily_retention` | 依首次登入日分群的 D1、D7、D30 留存 |
| `stat_daily_dimension` | 依 `client_version`、`platform` 拆分的 DAU 與時長 |
| `stat_daily_duration` | 單次時長分布（例如 <5 分、5–30 分、>30 分） |

CCU 與每小時在線人數沿用 Gate 的 Prometheus 指標，不進 MySQL。

## 事件格式

所有事件共用同一外殼，本輪只實作三種 Session 事件，但外殼需能直接容納之後的遊戲行為事件：

| 欄位 | 說明 |
| --- | --- |
| `event_id` | 去重鍵 |
| `type` | 例如 `SessionStarted`、`SessionTick`、`SessionEnded` |
| `version` | payload schema 版本 |
| `player_id`、`session_id`、`occurred_at` | |
| `payload` | 強型別，不使用 `map[string]any` |

設計前需先對齊現行任務事件管線（`mission/record_event`、Outbox、`missionqueue` 待移除），避免之後兩套並存。

## Statistic 設定表（PJA-Config）

欄位一次定齊，本輪只填用到的欄位；之後擴充遊戲行為時只新增列，不改表結構。

| 欄位 | 說明 | 本輪 |
| --- | --- | --- |
| `Id` | 統計 ID | ✓ |
| `Event` | 觸發事件類型 | ✓ |
| `Filter` | Condition 樹，限定事件 | 保留，留空 |
| `Aggregate` | `Sum`、`Count`、`Max`、`Min`、`Last`、`DistinctDays`、`Streak` | 只實作 `Sum`、`Count`、`Max`、`DistinctDays`、`Streak` |
| `Field` | 取事件 payload 的哪個值 | ✓ |
| `Period` | `Lifetime`、`Daily`、`Weekly`、`Monthly`，可多選 | ✓ |
| `SyncClient` | 是否同步給 Client | 保留，本輪不同步 |

本輪設定內容：

| Statistic | Event | Aggregate | Period |
| --- | --- | --- | --- |
| 在線秒數 | `SessionTick` | `Sum(online_sec)` | Lifetime、Daily、Weekly |
| 在玩秒數 | `SessionTick` | `Sum(active_sec)` | Lifetime、Daily、Weekly |
| 登入天數 | `SessionStarted` | `DistinctDays` | Lifetime、Monthly |
| 連續登入 | `SessionStarted` | `Streak` | Lifetime |
| 最長連續登入 | 連續登入變動時 | `Max` | Lifetime |
| 上線次數 | `SessionStarted` | `Count` | Lifetime、Daily |

`Statistic` 為新名詞，實作前需登記於 `PJA-Docs/名詞定義.md` 並確認不與 `Variable` 混用：`Variable` 是可被設定、扣除的玩家數值；`Statistic` 是只由事件累計、不可直接修改的紀錄數值。

## 保留期限

| 資料 | 保留 | 理由 |
| --- | --- | --- |
| `player_sessions` | 180 天，依月分區，到期整個分區刪除 | 涵蓋 D30 留存重算、客服追查與統計規則變更後重算；刪分區不產生大量 DELETE |
| `player_statistics` 的 `L`（總計） | 跟帳號走：90 天封存、360 天清除 | 屬玩家遊戲資料，與 `player_profile` 同生命週期 |
| `player_statistics` 的 `D`（日） | 40 天 | 夠用於「本月每日」與跨月比較 |
| `player_statistics` 的 `W`（週） | 12 週 | 約一季 |
| `player_statistics` 的 `M`（月） | 13 個月 | 可做去年同月比較 |
| 每日彙總表（`stat_daily_*`） | 永久 | 不含個人資料、體積小，是長期趨勢唯一來源 |

- 兩張新表都帶 `player_id`，實作時必須在 `cmd/world/internal/store/gamestore/player_tables.go` 的 `playerTables` 登記歸屬（見[帳號保留政策](../../帳號保留政策.md)）：`player_statistics` 隨帳號封存與清除；`player_sessions` 沿用自身 180 天規則，帳號清除時一併刪除該玩家的列。
- 週期列與分區的清理由每日彙總工作順帶執行。

## 效能

- 在線期間只更新記憶體中的 `lastActionAt`，不寫資料庫。
- 每台 World 每 5 分鐘一次批次 upsert（打卡單與 Statistic 各一條），1 萬人在線時負擔可忽略。
- 每位玩家每次上下線各一筆寫入。
- Statistic 熱數值快取在 World 記憶體，批次寫入後才落地。

## 實施順序

| 步驟 | 內容 | 返工風險 |
| --- | --- | --- |
| 1 | 打卡單、上下線串接、`lastActionAt`、批次寫入、當機回收 | 無：與決策無關，且是之後重算的原始資料 |
| 2 | 事件格式、Statistic 設定表欄位設計（與步驟 1 並行，審核後實作） | 先設計可避免之後改表結構 |
| 3 | Statistic 引擎與本輪六項統計 | 換日規則已定，可做 |
| 4 | 每日彙總表與 Grafana 面板 | 無：可從打卡單補歷史 |
| 5 | 整合測試：正常上下線、重複登入、跨日、當機回收 | |
