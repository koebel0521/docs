# 帳號綁定與多種登入方式方案

> 文件狀態：已實作（develop，尚未 push）。撰寫日期 2026-11-11。現行行為以[帳號與社群身分](../../10-核心流程/帳號與社群身分.md)與[連線與登入流程](../../10-核心流程/連線與登入流程.md)為準；本文記錄企劃需求、當時的決策與實作差異、Client 要配合的事和上線前檢查清單。

## 需求與決策

企劃要求的登入與綁定：Apple、Google 帳號、遊客、Facebook、Email。決策：

| 項目 | 決策 |
| --- | --- |
| Google | 只做 Google 登入（ID token），不做 Play Games Services |
| Email | 驗證碼登入（不做密碼、不做忘記密碼流程），用 Resend 寄信 |
| 帳號密碼登入 | 只留給內部與開發；正式範本 `login.password_enabled: false` |
| 遊客綁定正式帳號後 | 這台裝置的遊客密鑰不能再登入該角色（同一筆交易刪遊客身分）；遊客不算「最後一種登入方式」，也不可自己解除 |
| 綁定衝突 | 一律拒絕（`IdentityBoundToOther`），不合併角色；Client 提供「切換到那個帳號」（直接用那個憑證登入，遊客進度放棄） |
| Android 上的 Apple | 支援，走網頁流程（Services ID 與 Return URL） |
| 綁定獎勵 | 不做 |
| 刪帳號冷靜期 | 7 天，期間重新登入自動取消 |

## 實作與方案的差異

- **取消刪除的通知欄位**：方案說「登入回應帶旗標」。實作改為 `GetProfile` 回 `deletionCancelledAt`（`user.deletion_cancelled_at`），因為登入結果要經 Central、World、Gate 多一段 S2S 才能到 Client，改動大而價值小；Client 登入後本來就會取個人資料。
- **Email 不保存信箱原文**：方案寫「原文存在 `user_identity.provider_uid`」。實作改存信箱的 SHA-256（`accountrule.EmailUID`）：伺服器登入不需要原文、不存個資、長度固定放得進欄位。代價是客服無法由資料庫反查信箱，只能由玩家提供信箱再算雜湊比對。
- **Apple nonce 兩端都檢查**：`LoginRequest.Account`（與 `BindSocialRequest.Account`）放 nonce 原值，token 的 `nonce` 必須等於它的 SHA-256 十六進位。原因是網頁流程的 token 經過轉交，nonce 才能綁定到發起登入的 App。
- **Apple 撤銷授權在申請當下做**，且綁了 Apple 的角色必須用 Apple 重新驗證（`AppleReauthRequired`）：撤銷後 Apple 的 refresh token 立刻作廢，不必保存任何 token。取捨見 `deleteAccountSpec` 的註解。
- **`pkg/socialauth` 搬出 `cmd/gate/internal`**：Central 要驗證 Apple 伺服器通知的簽章，需要讀 Apple 公開金鑰。玩家登入、綁定、同步、刪帳號的外呼仍只在 Gate。
- **刪帳號的 Google Play 網頁入口**：只要求先放一頁靜態說明；網頁版自助刪除量大再做。

## Client 要配合的事

- **遊客**：產生 32 bytes 隨機密鑰存 Keychain／Keystore，編成 32～128 個可見 ASCII 字元（建議 base64url 43 字元）當憑證送 `AccountType=5`。綁定成功後清掉密鑰；沒綁定的遊客在適當時機（例如一定等級或第一次付費）提醒綁定。
- **Apple**：送給 Apple 的 nonce 是 `SHA-256(原值)` 的小寫十六進位，原值放 `Account`。刪帳號要附 `authorizationCode`（重新做一次 Apple 登入取得），綁了 Apple 的角色刪帳號必須用 Apple 重新驗證。Android 走網頁流程，Services ID 與 Return URL 見下方清單。
- **Email**：先送 `RequestEmailCodeRequest`（未登入也能送），再用 `AccountType=6`、`Account` 放信箱、`Password` 放驗證碼登入或綁定。回覆不透露信箱是否註冊過；限流時顯示「稍後再試」。
- **刪帳號**：成功（`DeleteAccountResponse.Result == Success`）後**立刻清掉保存的登入憑證**（遊客密鑰、社群 token 快取、Email），否則連線被關閉後的自動重登會在冷靜期內登入而取消刪除。顯示 `deleteAt`（Unix 秒）。重新登入後 `GetProfile.deletionCancelledAt` 不為 0 時顯示「已取消刪除」。
- **`AuthLoginMethodDisabled`**（code 15）是永久失敗，不要自動重登。

## 上線前檢查清單

1. 協定版本升為 6：Client 與 Server 要同版本一起上。
2. Apple 開發者後台：取得 Team ID、建立 Sign in with Apple 的 Key（`.p8` 與 Key ID）、bundle id；Android 網頁流程另建 Services ID，Return URL 填 `<status_base_url>/social/apple/callback`；Server-to-Server Notification Endpoint 填 `<status_base_url>/social/apple/notifications`。
3. Google：Web client ID，以及各平台實際簽發 token 的 client ID，都列進 Gate 的 `social.google.client_ids`。
4. Resend：API key，寄件網域驗證 SPF／DKIM。
5. 對外 HTTPS 網域（Central 的 `social.callback.addr` 前面的反向代理），給 Apple 回呼、通知與刪帳號說明頁用。
6. Gate 設定：`social.apple.*`、`social.google.*`、`social.guest.enabled`、`social.email.*`、`login.password_enabled: false`；環境變數 `SOCIAL_APPLE_PRIVATE_KEY`、`SOCIAL_EMAIL_RESEND_API_KEY`。Central 設定：`social.callback.*` 與 `social.apple.*`。
7. 正式庫關閉 AutoMigrate 時，`user` 表要補 `deletion_requested_at`、`deletion_cancelled_at` 與索引 `idx_user_deletion_requested_at`（PJA-Database 的正式遷移尚未提供，同 FB 那批的限制）。
8. 真機實測：Apple 原生與網頁流程、Google 各平台、Email 實際收信、刪帳號撤銷 Apple 授權（Apple 後台看授權是否消失）。

## 沒做的事

- 帳號合併（綁定衝突一律拒絕）。
- Play Games Services、綁定獎勵、網頁版自助刪帳號。
- 純密碼帳號（內部與開發用）的自助刪除：沒有可重新驗證的身分，`DeleteAccount` 回 NotBound。
- Email 驗證碼的限流與有效期沒有設定鍵（固定值）；要調再開鍵。
