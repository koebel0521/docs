## 刻意不改／跳過

### 程式端

| 項目 | 理由 |
|------|------|
| DS-M1（`msgpool.MaxRetainedBytes` 被當元素數上限） | `pkg/msg` 是生成碼，需改 PJA-Protocol 生成器（建議新增 `MaxRetainedIDs = MaxRetainedBytes / 8`）。 |
| N-M5、N-L1 上游欄位、N-H1 的 Mission 表／協定欄位 | 需改 PJA-Protocol／PJA-Config／PJA-Database。 |
| O-L5（帳號明文進 Debug 日誌） | `RedactedForLog` 在 `pkg/msg/auth` 生成碼，只改手寫部分會不一致。 |
| O-L8 其餘（MySQL／Redis／RabbitMQ exporter、外部心跳接收端） | 依指示跳過；只新增 `Watchdog` 規則（severity=info，路由 blackhole）。 |
| TS-L3 日誌等級熱更 | 需定義旗標／環境變數／YAML 的優先序，或新增受保護的 `/diag/log-level`（會改狀態的端點）。 |
| TS-M2 的 `/ready` 迴圈存活檢查與「深度改 scrape 時讀取」 | 採時間戳指標加告警；`/ready` 檢查可能讓 healthcheck 在長 handler 時誤殺；深度 collector 要處理全域 collector 的多 App 聚合。 |
| P-M1 的 World／Central 單人登出同步查詢 | 結果標籤、span、計時都在 `Handle` 的 defer 結算；Central 單人登出沒有 World 的同玩家順序保證。等 N1 決策（若刪除 journal，這些往返自然消失）。 |
| P-L2、C-L3、C-L5 其餘兩處、E-L5 重複記錄、E-L7 | 結構性改動或測試改寫風險大於收益。 |
| DB-L5 combatstore upsert `VALUES()` | 無法在不起 MySQL 下驗證語法，熱路徑 SQL 風險大於收益。 |
| DP-L4 httpx `BaseContext` 改 `WithoutCancel` | 現行行為有測試與文件，是刻意設計；伺服端自動產生 `operation_id` 無法讓「缺 id 的重試」冪等。 |
| R-L2 其餘（`logger.WarnEvent`、`lottery.NewRandomSource`）、R-L3 其餘六項 | 有熱路徑 benchmark 或被外部測試套件／Example 引用。 |
| SI-L2（`Runner` 改指標接收者）、SI-L3（gorm 欄位重排）、DI-L1（faultinject 全域 map） | `tools/private/boardsimulator` 會編不過／無法跑 schema parity／要穿過三層建構子。 |
| N-L9、N-L12、N-L5 的 `mysqlstore` 前綴 | 範圍大收益低／僅記錄（`mission.ResetSchedule`／`mission_reset` 就是名詞定義的 GameDay，等 online-stats 合併、做 `day_reset` 決策時一起改名）。 |
| CI-L9 JUnit、CS-L4 參數過多、CS-L2 其餘守衛、M-L1 `slices.Clone` nil 語意、M-L2 `cmp.Or` 提前求值、M-L3 `strings.CutLast` | 需新增工具與改所有 test job／對外 41 個呼叫點／語意會改變／改寫更長。 |
| PLY-L2 `modules.xml`、PL-L2、PL-L3（rueidislock 需停機切換）、CL-L2、DM-L1 子模組 `toolchain` 行 | 引用被 gitignore 的檔案／需決策或停機／文件已說明是刻意行為／屬子模組。 |
| B-L4、B-L5 後半、B-L6 的整合 benchmark | 報告自評可接受／共用輔助函式拆檔無實益／未起 Docker 只驗編譯。 |
| TF-M1 剩餘約 140 處 `require.Error` | 多為輸入驗證表格，正式碼只回 `errors.New` 無哨兵，或第三方／OS 錯誤文字不穩；要繼續需先補哨兵錯誤。 |

## 行為變更

- 啟動：World `max_players` 為負值拒絕啟動；沒有設定 MySQL（`mysql.host` 空）的 World 在 `openWorldStores` 拒絕啟動（錯誤含 `world requires the memory game store`）；`compose.prod.yml` 六個服務的 `DEBUG_PPROF_BASIC_AUTH` 改為必填（格式 `user:pass`、密碼至少 16 字元、不可 `change-me` 開頭），**升級正式環境前必須先在 `.env.prod` 設定，否則 `compose up` 失敗**；有設定但不合格時 pprof 與 Gate `POST /diag/reconcile` 一律回 503 並記 Error。
- pprof：缺省關閉（維持現行實際行為，`docker/prod/config/*.yaml` 沒有此鍵）；要開需寫 `debug.pprof_enabled: true` 並重啟。
- 關機：Gate `drain_timeout` 只套 drain 任務，其餘任務維持 5 秒；各 compose 補齊 `stop_grace_period`（Gate 75 秒、Central 65、World 70、Chat 30、Lobby／Record 20）；World 關機順序改為 PreDrain 只等 persist 佇列閒置、不關 pool，PostDrain 停事件迴圈與等背景工作後才關 pool 並最後寫回；關機任務逾時會輸出一筆 Error `shutdown timed out, goroutine dump`；啟動自檢與 S2S 握手隨停止訊號中止。
- RabbitMQ：World 啟動連不上改為背景指數退避（1 秒到 30 秒）重試，有設定 RabbitMQ 就一律啟動 outbox relay；`recordmq_connection_status=0` 變成暫態。
- 熱重載：`config hot reload applied` 只列真的套用的鍵；套用失敗記 Warn `config hot reload not applied`（`keys`、`err`）；Central 啟動期間收到的 `traffic_slice_*` 重載會在 App 建好後套用。
- 聊天：Gate 與 Chat 靜默丟棄非法 UTF-8 與 C0 控制字元（含換行、Tab）的聊天內容（`pkg/chatrule.ValidPayload`）。
- Lobby admin：失敗鎖定追蹤表（10000 筆）滿且無可回收條目時，未追蹤來源共用一組失敗額度（5 次突發、每 12 秒回復 1 次），用完一律 429；GM 稽核日誌新增 `actor_role`。
- 指標與告警：新增 `game_event_loop_last_tick_timestamp_seconds`、`GameEventLoopStalled`、`game_account_purge_last_run_timestamp_seconds`、`GameAccountPurgeStalled`、`GameGrantItemDeadLettered`、`Watchdog`、`go_sync_mutex_wait_total_seconds_total`、`logger_async_dropped_total`；`GameCircuitBreakerOpen` 改 `min_over_time(...[2m]) >= 1`；Gate 掃描到的 pending 逾時計入登入／登出指標，登入失敗 regex 加 `session_expired`；S2S 讀取逾時計入 `game_heartbeat_timeout_total`（日誌改 Warn `peer read deadline exceeded`）。
- 日誌：panic 復原欄位統一為 `err`；標準庫 `log` 帶 Warn 層級；`LOG_ASYNC_BUFFER`（預設 0＝關閉）開啟後丟最舊日誌並記 `logger_async_dropped_total`。
- 資料：Record 日分表名與回看範圍一律以 UTC 計；抽獎每日重置先轉 UTC；World 登入的重複請求回放判斷改在容量檢查之後（滿載時先回 `AuthServerFull`）。
- CI：新增 `alloc-guard`；`coverage-report` 計入整合測試覆蓋；`integration` 不再需要 Redis service；`build-images-mr` 加 `trivy image` 掃描；runner 故障才重試；lint 另跑 `GOOS=windows`；**不要關閉 GitLab 的「Use separate caches for protected branches」**（第五輪紀錄曾要求關閉，已反轉）。
- API 改名（`tools/private` 若有引用需同步）：`boardconfig.BuildingLevel`→`BuildingLevelConfig`、`TurnProgress`→`Progress`、`Session.Invalidated`→`InvalidatedAt`、`Connected`→`IsConnected`、`RecordSinkReady`→`IsRecordSinkReady`、routingcache `Write`→`Store`、`tcpsocket.SocketOption`→`Option`、`mysqlstore.NewMySQL`→`New`；刪除 `debug.Default`、`debug.RegisterReadyChecker`、`debug.CheckReady`、`mysql.Connect`、`GormLogger`、`ErrorEvent`、`tcpruntime.Socket.Conn`、`combat.SessionService.Load`、`requestjournalredis.KV.Delete`；`combatstore.NewSessions`／`NewNotifications`／`NewCandidateIndex` 必須傳遊戲時鐘（nil 會 panic）；`OutboxRecord`／`ErrOutboxRecordInvalid` 移到 outbox（`Record`／`ErrRecordInvalid`）。
