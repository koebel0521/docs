## 重複合併

- DI-M1 = R-M2 = V-M1 ⊂ SC-L1，T-L1 為其測試缺口：Lobby admin token 熱重載不跑 `RejectDevStackToken`，公開開發 token 可熱重載生效；SC-L1 另指 `compose.debug.yml` 固定 `ALLOW_DEV_TOKENS`。
- R-M1 ⊃ V-L4：啟動與熱重載各一套「讀設定檔＋驗證」；`bootstrap.ReadConfig` 只剩測試用、註解過時。
- N-M1 ≈ DP-L1：Lobby 公告用 `debug.Server.CheckReady`（只跑啟動自檢，不含 `time_sync`／啟動閘門），`/ready` 503 的 Gate／World 仍被公告分配；監聽失敗行程不退出。第十一輪 DI-M1 修正不完整。
- CI-M1 ⊃ T-L4：協定 schema hash 測試在 CI unit 恆 Skip，擋不住合併。
- L-M1 ≈ CS-L4 ≈ R-L3：`panicx`／`appcore` 兩套 panic 輔助；`panicx` 的 kv 函式未登記 loggercheck。
- DP-L2 = V-L2 ≈ DI-L2：Chat `room_max_members` 用 `GetInt`、建構後 setter 注入。
- DP-L3 = DI-L1：World record sink 撥號以套件層可變變數當測試縫。
- V-L1 = DOC-L3：Central 啟動窗口不合法 `traffic_slice` 重載先記 applied、canary 被關，註解寫「沿用現狀」。
- O-L3 = TR-L3：`GameReadyCheckFailing` 未排除 `startup` 閘門。
- E-L4 ≈ O-L7：多處 Warn 未取樣／取樣器共用。
- DOC-L1 ≈ PL-L2、DOC-L2 ⊂ PL-L2：文件與註解仍指向搬走的檔案。
- SC-L2 為第十一輪 SC-L2（房間上限 500）的副作用。

## 行為變更摘要

- 資料一致性：World 盤面指令期限含排隊時間，開始前已過期的指令直接回失敗；「stop board workers」逾時即取消執行中與排隊中的指令；`FlushAllForShutdown` 開始後 `gamestore` 提交一律回 `ErrStoreShutdown`（CX-M1）。
- 計時：Gate 心跳、握手逾時、pending session 清理、版本寬限期與 `redis.BackendCooldown` 改用單調時鐘（`pkg/timex`），牆鐘跳動不再大量斷線或拉長冷卻；`Session.LastSeenUnixNano()` 改為 `LastSeen() time.Time`（TR-M1）。
- 寫回：連續 panic 3 次的玩家走隔離路徑（固定訊息 `write-back panicked repeatedly`），不再每秒重試（TR-L1）；雙重故障的資料遺失日誌每 500 個 ID 一行全部列出（TR-L2）。
- GM 發道具：道具不存在、指令不合法、變數超範圍等確定失敗（`gm.ErrPermanent`）第一次就進死信，計量記 `invalid_payload`（E-L3）。
- 安全：Lobby admin token 熱重載與啟動共用 `services.NewTokenValidator`，非 loopback 時拒絕公開開發 token；`allow_dev_tokens` 固定取啟動值（DI-M1 群組、SC-L1）。Record `/events` 成功查詢記 Info 稽核日誌 `record events audit`（SC-L3）。Gate 限制同一來源 IP（IPv6 以 /64）在同一 Chat 房間最多 50 人（`session.chat_room_members_per_ip`），被拒計入 `game_chat_rate_limited_total{kind="join"}`，Client 收不到失敗回覆，每台 Gate 各自計數（SC-L2）。
- Lobby 公告：Gate／World／Central 的 lobbyreporter 改用 `CheckServing`（與 `/ready` 相同，含啟動閘門與 `time_sync`）；原 `CheckReady` 改名 `CheckStartup`。Central 連不上時所有 Gate／World 撤除公告；重啟後第一次公告最多晚 10 秒（N-M1）。
- 啟動：`tcp_listen_<name>` 在 `tcpserver.New` 時就登記，自檢最多等 `ReadyCheckTimeout`（3 秒）讓監聽有結果，監聽失敗即自檢失敗、行程退出；World 新增啟動自檢（MySQL／Redis／data_config），通過後才放行閘門與公告（DP-L1）。
- 設定：啟動與熱重載共用 `ReadConfigPair`＋`bootstrap.ValidateLoaded`，熱重載也嚴格解析 `id`（R-M1）；設定檔未加引號的前導零整數若八進位與十進位結果不同（`010`、`09`）讀檔即拒絕，`00`、`07` 與加引號字串放行（V-L3）；Central 啟動期間不合法的 `traffic_slice` 重載回錯、不覆寫已存重載（V-L1）；Chat `room_max_members` 嚴格讀取，`1.9`、`"1e3"` 拒絕啟動（V-L2）。
- 可觀測：新增 `game_config_reload_total{result}` 與 `GameConfigReloadRejected`（O-L6）、`game_chat_history_ops_total{op,result}` 與 `GameChatHistoryWriteFailing`／`SyncFailing`／`PurgeFailing`（O-M1）、`GameStartupStuck`（O-L3）；`GameReadyCheckFailing` 排除 `check="startup"`；`GameProcessRestarted` 發版只容許重啟一次（O-L1）；延遲直方圖補 2s 與 0.2s 桶界（O-L2）；`game_heartbeat_timeout_total` 預建序列（O-L4）；MySQL 驅動與 OTel 內部日誌改走 `pkg/logger`（PLIB-M1）。

## 陷阱

- **Debug 檢查函式改名**：`debug.Server.CheckReady` 已改名 `CheckStartup`（只跑啟動自檢），與 `/ready` 一致的是新的 `CheckServing`；舊名稱字面上像 `/ready`，正是 N-M1 的根因。
- **單調時鐘與 synctest**：`timex.MonoNow` 在 synctest 假時鐘下可能為負，`BackendCooldown` 另以零值判斷可用；新程式碼存時間點到 atomic 欄位時用 `timex.Mono`／`FromMono`，不要存 `UnixNano`（換回會丟單調讀數）。
- **`toolcli.ExitCode` 先改不匯出又恢復匯出**：CS-L3 與 PL-L4 兩個分支先後改動，最終是匯出（World 工具傳給 `clihelp.Run`）。
- **appcore panic 轉呼叫仍在**：標 Deprecated，`staticcheck SA1019` 擋新用法；全部遷完可刪 `pkg/appcore/recover.go`。`RecoverPanic` 因 `recover()` 不能委派而無 `//go:fix inline`。
- **日誌查詢改寫**：搜尋 `http handler panic` 的查詢要改為 `message="panic recovered"` 且 `msg="http handler"`；取樣後的 Warn 帶 `(sampled)` 後綴，次數改看計量。
- **前導零整數**：拒絕只看「八進位與十進位結果不同或非法八進位」，因此 `07` 放行、`010` 拒絕；環境變數一律十進位。
- **benchmark 基準檔缺列**：本輪刪了 90 列、新名稱尚未補列，重產前 bench-gate 對新名稱沒有比較基準。
