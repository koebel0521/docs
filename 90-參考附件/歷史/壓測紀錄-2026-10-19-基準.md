## 測試 1：登入容量（冒煙）

```bash
go run ./tools/private/pjaload loadtest -gate 127.0.0.1:62001 \
  -source-ips 127.0.2.2,...,127.0.2.33 -n 1000 -ramp 40s -duration 60s -hb 5s
```

| 項目 | 結果 | 手冊預期 |
|---|---|---|
| 登入成功 | 1000／1000 | 等於 `-n` |
| 登入重試 | 0 | — |
| 登入失敗 | 0 | — |
| 錯誤 | 0 | 0 |
| 平均登入延遲 | 7 ms | 約 7～11 ms |
| p95 登入延遲 | 10 ms | 約 10～16 ms |
| 登出 | 1000／1000 | — |

結論：與歷史基準一致，沒有退化。

## 測試 2：常駐與資源（soak）

```bash
RL_PASSWORD=<密碼> go run ./tools/private/soakload -n 500 -hold 180s -every 4s -sample 30s -prefix bl20261019
```

500 人全數登入後常駐 3 分鐘，每 4 秒擲骰，每 30 秒取樣一次。

| 項目 | 結果 |
|---|---|
| 登入 | 500／500，失敗 0 |
| 擲骰總數 | 17383，遺失 0（0.00%） |
| 擲骰 p50 | 約 1.56 ms（各取樣點幾乎不變） |
| 擲骰 p99 | 3.3～4.3 ms（暖機後）；第一個取樣點 25.6 ms |
| 擲骰 max | 5.3～10.7 ms（暖機後）；第一個取樣點 48.7 ms |
| World goroutine | 410（不隨時間成長） |
| World heap / RSS | 32～48 MB ／ 94～106 MB（RSS 緩升後持平） |
| World GC 停頓占比 | 0.00～0.01% |
| Gate goroutine | 約 1550（約 3.1／連線） |
| Gate heap / RSS | 37～64 MB ／ 135～162 MB |
| Central goroutine | 63 |
| Central heap / RSS | 13～20 MB ／ 47～52 MB |

結論：goroutine 與 RSS 持平，沒有洩漏跡象；擲骰 p50 與歷史基準（約 1.6 ms）一致。第一個取樣點的尖峰是登入剛完成的暖機，不算退化。

## 限制

- 單機 loopback，客戶端與服務同機，數字當相對比較，不能當正式容量。
- 電源計畫為「平衡」，之後比較要用同樣設定，或先切高效能再重測並註明。
- 只量 500 人常駐與 1000 人登入，沒量 3800 人等大規模，也沒做故障注入。
- 這是單次執行，沒有重複取平均；要判斷退化，建議至少跑 3 次看變異。
- 服務為 `go run` 啟動，未使用預先編譯的執行檔。
- 結果沒有保存 `pjaload` 的 baseline 檔進版控（本輪產出在暫存目錄），之後要比對需重新寫入。
