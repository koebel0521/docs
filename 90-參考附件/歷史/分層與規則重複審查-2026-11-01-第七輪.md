## 六、白話說明（每類一個本專案例子）

- **A1 資料層混入業務**：存資料的程式自己決定規則。本輪沒有新的 A1。前輪已把 World MySQL 版縮到只剩持久化；例外是 F2，store 自訂「attempts 至少 1」，與發送端的規則打架。
- **A2 型別放錯層**：純粹的型別或介面放在資料層檔案。例：`PlayerArchiver` 介面放在 gamestore，真正的消費端卻各自重宣告了一份（R4）。
- **A3 傳輸層自做規則**：HTTP handler 自己判斷業務。例：Lobby 的封禁期限上限只寫在 HTTP handler，直接呼叫 `gm.Ban(ttl=0)` 會變成永久封禁（R5）。
- **A4 業務層直接碰基礎設施**：例：World 的 services 為了判斷「是不是資料庫暫時壞了」直接 import `pkg/mysql` 與 gobreaker，這個分類本該放在 itemaction（R1）。
- **A5 同流程多套後端**：本輪沒有新的 A5。Memory 與 MySQL 共用領域函式已在前輪完成。
- **B 測試工具與真實不一致**：測試或模擬器跟正式版不一樣，測試全綠但正式版壞了。例：outbox 的測試替身不檢查 attempts，所以 F2 在測試裡永遠是綠的（F2b）；模擬器接受負星星，World 不會（F20）。
- **C 同一規則多份**：同一件事寫在兩個地方，改了一邊就分歧。例：抽獎上限一邊檢查倍率、一邊檢查展開數，乘起來沒人檢查（F3）；PJA-Config 編輯器少了 Server 新加的三條規則（F9）。
- **D 設定與協定**：同一份設定寫兩次。例：`.env.prod` 的資料庫密碼同時寫在 `MYSQL_DSN` 和 `MYSQL_PASSWORD`，只改一個，migration 就連不上（N7）。
- **E 背景任務與觀測**：例：Central 把「拒登回報」計進登出指標，登出失敗率的告警因此被稀釋（F15）。
- **F 工具套件重複**：例：「工具不接受多餘參數」的檢查寫了六份（R8）；退避計算寫了三份（R9）。
- **G 資料庫與依賴**：沒有外鍵，關聯靠程式維持。例：帳號清除的守門只認名叫 `player_id` 的欄位，以後新增 `target_player_id` 的表會漏掉（R11）。
- **H SOLID/DRY/KISS/YAGNI**：例：`grantitem.NewOperationID` 已經沒有正式呼叫端（R4）；`grantDeadLetterItem` 是現有型別的子集複本（R5）。
- **I 並行與錯誤**：兩件事交錯時，舊的結果蓋掉新的狀態。例：Gate 舊一輪的封禁查詢結果把同連線新一輪的登入拒掉（F1）；Central 一個晚到的拒登回報把同 Gate 的新 session 登出（F4）。
