## 行為變更摘要（文件已同步）

- 工具鏈：pre-commit 新增 `golangci-lint (other GOOS)`、`golangci-lint (full tree)` 兩個 hook，預設一併安裝 commit-msg hook；`make ci-lint` 呼叫 `scripts/lint-other-goos.sh`。CI 新增 `release-preflight`（`allow_failure`）、`lint` 的 `scripts/*.py` 語法檢查；`unit` 加 `-coverpkg`、分片以 `ci-cover-merge.sh` 合併；fuzz artifact 路徑縮小；bench-gate 不再略過 `pkg/dataconfig/generated`；映像一致性測試納入 `.env.prod.example` 與備份還原演練腳本。
- 腳本：`ci-deploy.sh` 的 `HEALTH_TIMEOUT` 須為正整數秒；`dev-up.sh` 開 job control 並報服務提前結束；三支 CI 腳本缺參數印用法並回 2；`integration-deps-up.sh` 等 MySQL 逾時回報失敗；`docker-restore-redis.sh` 解壓失敗不留空 `.restore-old`。
- `compose.debug.yml` 的 Lobby 埠只綁 `127.0.0.1`（已知安全風險第 4 項）。
- `/ready` 啟動閘門：放行前回 503（`startup: starting`）；`compose.prod.yml` 六個服務 healthcheck 加 `start_period: 120s`；新 API `debug.Server` 的 `BeginStartup`／`MarkStarted`／`StartupCheck`。
- 熱重載：差異比對看設定檔本身；被環境變數遮蔽的鍵「修改」也記 Warn `config change shadowed by environment variable, not applied`。設定驗證提前到連線之前（World、Central、Chat、Gate）。
- 追蹤：`StartSpan` 無遊戲 traceID 但 ctx 有取樣中 span 時建子 span。
- 業務：`start_combat`、`submit_combat_result`、`activate_mission`、`claim_mission_reward` 的內部失敗計入 `game_board_command_total{result="error"}`（`GameBoardCommandErrorRatioHigh` 涵蓋）；World 開戰哨兵改名 `ErrCombatStartRejected`；Gate 封禁查詢失敗日誌改取樣；落地檔重放中途失敗時扣掉已處理異動；寫回收尾 panic 不留永久鎖並計為失敗；TCP accept 迴圈 panic 後關 listener 並讓 `/ready` 失敗；MySQL 錯誤日誌不帶出唯一鍵衝突的帳號。
- 日誌鍵：persist pool `world` → `worldID`；Lobby discovery `id` → `gateID`；Central `sendDirectError` `code` → `responseCode`。
- Gate 登入限流表滿載（10 萬 key）改淘汰最久沒碰的 key，不再拒絕新 key。
- 關機與登入指標：事件迴圈 panic 先 `app.Stop()`；`httpx.ServeLimited` 關機不取消 in-flight 請求；pending 逾時補計後晚到回覆不再計 `game_login_total`。
- 演練用 Alertmanager 抑制規則與正式一致（`equal: [job, instance]`、排除 `GameHandlerP99Critical`），`TestAlertmanagerInhibitRulesMatchProd` 比對。

## 實機未驗項

以下只經程式碼閱讀與單元測試，沒有在真實環境跑過：

- `release-preflight`：GitLab 上以 `GIT_SUBMODULE_STRATEGY: recursive` 實際跑 `releasemanifest generate`／`verify`，以及 `allow_failure` 在 MR 頁面的呈現。
- `dev-up.sh` 的 `set -m`：在 Git Bash（Windows）、Linux、WSL 下按 Ctrl+C 的行程群組行為與結束碼（130／1）。
- `start_period: 120s`：正式堆疊實際重啟時 World 還原玩家的耗時是否落在 120 秒內，以及與 `ci-deploy.sh` 的 `HEALTH_TIMEOUT`（180 秒）的搭配。
- `-coverpkg` 變慢風險：unit 四個分片都帶全專案 `-coverpkg`，加 `-race` 與 `-covermode=atomic` 後可能顯著變慢或逼近 `-timeout=10m`，需看第一次 MR pipeline 的耗時。
- fuzz artifact glob：`cmd/**/testdata/fuzz/` 等路徑在 GitLab artifacts 的 glob 語意是否如預期（是否仍涵蓋深層目錄）。
- User 實例（`tools/user`，`:6063`）的 `/ready`：`InitializeObservability` 回傳的 debug 伺服器在 `tools/user/run.go` 被丟棄（`_`），沒有人呼叫 `MarkStarted`，從程式碼判斷 `/ready` 會恆為 503 `startup: starting`（`compose.full.yml`、`compose.debug.yml` 的 user healthcheck 會一直不是 healthy）。程式側待修；文件已註明。
