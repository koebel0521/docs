### 11.3 中嚴重度

**身分與連線處理（Gate／World／Central）**

- N6 `cmd/world/internal/handler/gate/on_validate_gate_to_world.go:38-43`、`cleanup.go:14-31`：Gate 驗證失敗回覆與寬限期清理無條件 `DeleteUser`，不看玩家目前綁在哪個 Gate。玩家改連 Gate B 後，Gate A 的回覆會刪掉 B 上的新 session，盤面指令被靜默丟棄直到重登，Redis 狀態也被刪。`lifecycle/recovery_reconcile.go` 已用 `DeleteUserIfGate`，這兩處漏用（`gate.UserRegistry` 介面需補方法）。

**慢 I/O 在共用鎖內與關機**

- N9 `pkg/tcpsocket/owner_base_socket.go:88-105`：`Disconnect` 在 `authenticatedMu` 寫鎖內呼叫 `ownerEvent.Disconnect`，該鎖被事件迴圈上每則訊息的 `RLock` 共用；Central 處理 Gate 斷線時在鎖內做無逾時的 Redis 呼叫（`DeleteUserRoutings`），Redis 變慢時整個事件迴圈停擺。

- N11 `pkg/appcore/shutdown.go:131-143`：`executeShutdownTask` 同步呼叫任務，逾時沒有強制力；`Registry.Close()` 會等所有 `ServeConn` 與 `Disconnect`，其中一個卡住（N9），後面的 cleanup（關 Redis、DB）不會執行，流程卡到被 SIGKILL。

- N12 `cmd/world/internal/store/gamestore/memory_player.go:267-321`：GM 發放的 `OperationID` 沒有長度檢查（只有任務事件路徑檢查 64），而欄位是 `size:64`、`pkg/grantitem` 只檢查非空。超過 64 字元時 MySQL 回 1406，寫回每秒重試永遠失敗，該玩家所有異動與登出都卡住；關機時落地成 spill 檔，`ReplaySpills` 遇第一筆失敗就整個回錯，下次啟動被擋。前提：strict `sql_mode`（8.0 預設）。

### 11.5 已確認沒問題（避免重複查）

- 帳號鎖記憶體版與 Redis 版的 `refs` 計數、Lua 條件解鎖；登入重放同時檢查 Gate；`routingOnly` 條目不進帳號索引。
- 金幣結算重送（以 `settlementID` 去重）；session 鎖 `FOR UPDATE` 順序一致；快照寫入欄位順序。
- luban `ByteBuf` 每個 Read 檢查剩餘長度；framecodec 長度欄位上下限；物件池歸還與別名；手寫 `Unpack` 預檢；`ConfigVersion` 先過 40 位十六進位正規式；`os.Root` 加拒絕符號連結。
- 規則計算：condition 加減法溢位、lottery 亂數無偏差（rejection sampling）、effect 用 `big.Int`、mission 週期對齊、variable 溢位檢查。
- S2S 驗證設計（TLS 1.3、雜湊 token 常數時間比對、輪替關閉受影響連線）；Gate 玩家端登入握手逾時、per-IP 上限、frame 大小與限流。
- gamestore 寫回冪等、鎖順序（先 `flushing` 再 `mu`）、SQL 全部參數化、斷路器 `IsSuccessful` 用 `IsInfraError`。
- `staterepair`、`coldstorage`（purge 前綴白名單與「內容未變才刪」）、`s2s-secret-receiver.py`、`docker-backup-*.sh`、`reset-local-deps.ps1` 的防護設計。
