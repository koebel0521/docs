# 效能演進記錄

這裡收錄逐輪效能優化的流水記錄。它們是「當時做了什麼」的歷史，**不是現行架構規則**；
現在仍然成立的架構決策請看 [[系統導讀]]，效能上限與資源預算請看 [[資源預算]]。

新一輪優化不必再往這裡追加，直接回歸 git log；只有當優化改變了架構層級的設計時，
才需要回頭更新對應的現行功能文件。

## 優化記錄

- **TCP socket 層**：使用原生 buffered channel 取代第三方無界佇列（每連線省 2 goroutine）；收發路徑用 `DecodePooled`/`WriteFrame` 走 sync.Pool 重用緩衝與 net.Buffers 零拷貝寫入
- **World 狀態鎖**：按領域拆分 `userMu`/`chanMu`/`dataMu` 三把 RWMutex，取代單一全域鎖；`recordSink` 用 `atomic.Value` 免鎖
- **World 資料結構**：`users` 從紅黑樹改為原生 `map[uint64]*User`（O(1)）；`activePlayerCount` 用 `atomic.Int64` 取代 O(n) 遍歷
- **批次查詢**：`ChannelMembers` 搭 `FindUsersGateMap` 一次取回 gate 資訊；`refreshPlayerTTLs` 用 Redis pipeline 批次刷新
- **Redis 層**：啟用 RESP3 客戶端快取；`Multi.Exec` 後清空 cmds 防重複執行；熱路徑 `fmt.Sprint` 改 `strconv`；`RestoreByWorld` 用 pipeline 批次 GET
- **msgpool**：`Pack` 緩衝走 `sync.Pool` 重用，減少每訊息分配
- **MySQL**：臨時連線加 5s timeout 防 hang；`reconnect` 加 1ms 下限防 busy retry
- **tcpserver**：`acceptLoop` 加信號量限制並發連線數，防連線湧入 OOM
- **Gate 鎖拆分**：`stateMu` 拆分為 `sessionMu`（sessionsByKey/sessionKeyByUser/sessionCentral）與 `userMu`（users/usersByWorld），sweep 不再 block 線上人數查詢
- **World checkpoint 批次化**：`BatchSave` 單次 `INSERT ... VALUES (...),(...)... ON DUPLICATE KEY UPDATE` 取代每玩家一次 MySQL 事務
- **World 道具批次寫入**：`BatchSaveItems` 單一交易取代逐筆 `SaveItem` 的 N 次 round-trip
- **Central 無鎖化**：`trafficSlicePercent/WorldID` 改 `atomic.Int64/Uint64` 免鎖讀取；`BatchInsertUsers` 單次 Lock 批次寫入
- **sync.Pool 擴展**：`packedMsg`（每廣播）加 pool 重用，Put() 保留 payload buffer（`payload = payload[:0]`）避免每次廣播重新分配
- **熱路徑 JSON 序列化**：player store（Redis 讀寫）、recordmq（RabbitMQ 發布 + 消費）、recordevent、audit snapshot、request journal、grantitem 等 8 條路徑改用 `goccy/go-json`（相容 encoding/json 介面）
- **熱路徑 micro-opt**：`fmt.Sprintf`→`strconv`、`SessionState` string→uint8、`centralring` idCache
- **資源生命週期**：`ratelimit` IP map 加背景清理防無限增長、`ProtocolRecorder` purge goroutine lazy start
- **Central 鎖拆分**：`mu` 拆分為 `userMu`（users/usersByAccount/usersByGate/usersByWorld）與 `worldMu`（connectedWorlds/worldEverConnected/worldWarmupUntil），World 連線事件不再競爭 user 查詢鎖
- **Gate audit snapshot 精簡**：`snapshotForAudit` 只深拷 authoritative data（users/sessionsByKey），derived indexes 現場重建，每分鐘省 3 個 map 深拷
- **Gate reconcile 雙階段**：`reconcileDerivedState` 先 RLock 掃描收集問題，有問題才 Lock 修復，消除每分鐘雙寫鎖 STW
- **Gate pendingLogin 索引**：`pendingLoginKeys` map 加速 sweep，只掃 pending session 而非全部
- **World 熱路徑 alloc**：`SetUserGate` 回傳 `*User` 消除 cloneUser heap escape；`InsertUser` 跳過無效 removeGateIndex
- **persistPool backpressure**：`Submit` 改非阻塞 select+default，queue 滿時 drop 而非阻塞 event loop
- **requestjournal cache 生命週期**：`Journal.Close()` 停止 sweepLoop goroutine，各 App Release() 中關閉
- **Gate OnlineCount O(1)**：`atomic.Int64` 線上人數計數器，lobby 查詢免 O(n) 遍歷
- **Gate pendingLogoutKeys**：新增 `pendingLogoutKeys` map，sweep 只掃 pending 兩個 map 而非全體 sessionsByKey
- **Gate sweep 鎖最佳化**：`SweepExpiredSessions` 僅持 sessionMu 迭代，userMu 由 sweepOne 內短暫取得後釋放，減少雙鎖保持時間
- **Socket struct field alignment**：Socket struct 欄位經自動重排減少 padding，降低 10k+ 連線場景記憶體佔用
- **Gate audit 免深拷**：`auditConsistency` 改 read-lock 直讀 live state（同 World），每分鐘省全量 users/sessions 深拷
- **Gate findUserNoClone**：內部唯讀路徑用 `findUserNoClone` 免 cloneUser 堆分配
- **Central Redis HMGET**：`findAccountFromRedisLookup` 用 HMGET 取 uid/wid/hash 三欄，減少網路傳輸
- **Central context 傳遞**：Redis 查詢改用 caller context，trace 鏈不中斷
- **World RestorePlayers 批次**：`BatchInsertUsers` 單次 Lock 完成恢復，減少鎖競爭
- **PublishRecord envelope pool**：`sync.Pool` 重用 envelope，減 GC
- **ratelimit ipEntry pool**：`sync.Pool` 重用 ipEntry struct
- **audit consistency strconv**：一致性檢查 `fmt.Sprintf` 改 `strconv` 字串拼接
