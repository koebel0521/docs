# 玩家在線統計

> **尚未合併（feat/online-stats）**：本文描述的元件、資料表與設定（含 `day_reset`、`internal/gamecore/kernel/gameday`）只存在於未合併的 `feat/online-stats` 分支，develop 目前沒有這些實作。

World 以打卡單記錄每次上線，依 `Statistic` 設定表把上線、心跳、下線事件累計成玩家統計值，每天換日後把打卡單彙總成報表。設計背景與取捨見[方案草稿](../90-參考附件/方案草稿/玩家在線行為統計方案.md)。

## 一句話

玩家上線開一張打卡單（`player_session`），在線期間只在記憶體累加，每 `flush_interval` 批次寫一次心跳；下線關單。統計引擎聽同一批事件，依設定表更新 `player_statistic`。報表讀每日彙總表 `stat_daily_*`，不掃打卡單。

## 元件

| 元件 | 位置 | 職責 |
| --- | --- | --- |
| 遊戲日 | `internal/gamecore/kernel/gameday` | 全 Server 共用的換日時刻（World 設定 `day_reset`，預設 UTC 00:00）；任務週期與統計週期都用它 |
| 打卡追蹤 | `cmd/world/internal/session.Tracker` | 開單、關單、操作時間、在線／在玩時長累加、批次寫入、當機回收、關機收尾 |
| 打卡單儲存 | `cmd/world/internal/store/sessionstore` | `player_session` 單句 upsert、回收、保留期清理、每日彙總 |
| 統計核心 | `internal/gamecore/statistic` | 設定表載入與驗證、週期鍵、各累計方式的純運算 |
| 統計引擎 | `cmd/world/internal/statistic.Engine` | 事件佇列、上線載入、記憶體累計、髒列寫回、週期列保留期 |
| 統計儲存 | `cmd/world/internal/store/statisticstore` | `player_statistic` 載入與整列覆寫 |
| 上下線轉換點 | `cmd/world/internal/app.applyGateLocked` | 唯一的在線 ↔ 離線轉換處：上線開單、下線帶原因關單、換 Gate 重登先 `replaced` 再開新單 |

## 流程

```text
登入成功（InsertUser／SetUserGate）──► Tracker.Opened ──► 打卡單開單列排入 pending
                                                      └─► Engine.SessionStarted（登入天數、連續登入、最長連續、上線次數）

盤面指令進入 World（onClientBoardCommand）──► App.PlayerActed ──► Tracker.Touch（只更新最後操作時間）

每 flush_interval（整台 World，起點隨機錯開）
  └─ 每位在線玩家：在線秒數 += 距上次寫入；在玩秒數 = 每次操作起算 idle_threshold 區間的聯集
     ├─► 心跳列排入 pending（同一句 INSERT ... ON DUPLICATE KEY UPDATE 累加）
     └─► Engine.SessionTick（在線秒數、在玩秒數：總計、日、週）

登出／Gate 斷線／重登頂掉（SetUserOffline、DeleteUserIfGate）──► Tracker.Closed(reason)
  ├─► 關單列（ended_at、end_reason、最後一段時長）
  └─► Engine.SessionEnded（先當最後一段心跳套用，再套用下線統計）

每秒：Tracker 把 pending 落地；Engine 批次載入未載入玩家的總計與當期列後套用事件
每 30 秒（statistic.write_interval）：Engine 整列寫回髒列，已下線玩家寫回後卸載
每分鐘：回收器把心跳早於 stale_after 且未結束的打卡單以最後心跳關單（reaped）
每 5 分鐘：補算最近 7 天缺的每日彙總（換日後等 10 分鐘）
每小時：刪除超過保留期的打卡單與日／週／月週期列
```

- 時間一律取 `App.GameNow`（Central 校正時鐘）。
- Tracker 的 Sink 在服務啟動後才接上；重啟還原玩家在那之前開單的事件會暫存重放。
- 關機：Tracker 以 `shutdown` 關掉所有打卡單並做最後一次寫入；Engine 套用剩餘事件後寫回。
- 跨日仍在線：新一天第一個心跳以出席語意補計登入天數與連續登入，不算一次上線；該段秒數整段歸入新的一天（誤差最多一個 `flush_interval`）。

## 關單原因

| `end_reason` | 來源 |
| --- | --- |
| `normal` | Central 登出，結果碼 Success／LoggedOut |
| `replaced` | 同一玩家他處登入（結果碼 ReLogin／LoggedIn，或同 World 換 Gate） |
| `timeout` | 結果碼 SessionExpired |
| `kicked` | 結果碼 AccountBanned |
| `code_<n>` | 其他結果碼 |
| `gate_lost` | Gate 斷線寬限期滿清理 |
| `recovery_stale` | World 重啟後還原的玩家沒有重連 |
| `shutdown` | World 關機 |
| `reaped` | 心跳逾時由回收器關單（World 當機） |

## 資料表

全部由 World `AutoMigrate` 建立（`gamedb.Models`）；上線前隨 PJA-Database 正式 migration 版本鏈一併寫入。帶 `player_id` 的表都登記在 `gamestore.playerTables` 為 `roleExternalPurge`，帳號清除時由各自的 `DeletePlayerTx` 刪除。

| 表 | 內容 | 保留 |
| --- | --- | --- |
| `player_session` | 每次上線一列：`session_id`（`<world>-<player>-<開單毫秒>`）、開始、最後心跳、結束時間與原因、在線／在玩秒數 | `online_session.retention`（預設 180 天），每小時逐批刪已結束的舊列 |
| `player_statistic` | （玩家、統計、週期鍵）→ `value`、`state`；`state` 在 Max／Min／Last 是已有值旗標，在 DistinctDays／Streak 是最後計入的遊戲日序號 | 總計永久；日 40 天、週 12 週、月 13 個月（`statistic.*_retention_*`） |
| `stat_daily_global` | 每日 DAU、新玩家、打卡單數、在線／在玩秒數、當機回收數 | 永久 |
| `stat_daily_retention` | 每日對 1／7／30 天前新玩家群的留存 | 永久 |
| `stat_daily_duration` | 每日單次時長分桶（`lt5m`、`5m_30m`、`gt30m`） | 永久 |
| `stat_daily_end_reason` | 每日關單原因分組 | 永久 |
| `stat_player_first_day` | 每位玩家首次上線日；新玩家與留存群以它為準 | 隨帳號清除 |
| `stat_rollup_run` | 已彙總完成的日期 | 永久 |

週期鍵固定寬度：`L`、`D20261015`、`W202642`（ISO 週）、`M202610`，字串比較即先後。

## Statistic 設定表

來源 `PJA-Config/Datas/Statistic.xlsx`，列舉在 `Datas/enums/Shared.Statistic*.xlsx`。每列一項統計：

| 欄位 | 說明 |
| --- | --- |
| `Id` | `Shared.StatisticId` |
| `Event` | 觸發事件：`SessionStarted`、`SessionTick`、`SessionEnded` |
| `Aggregate` | `Sum`、`Count`、`Max`、`Min`、`Last`、`DistinctDays`、`Streak` |
| `Field` | 取事件哪個欄位：`OnlineSeconds`、`ActiveSeconds`；Count／DistinctDays／Streak 留空 |
| `SourceStatisticId` | 不為 0 時改取該統計的總計值當輸入（衍生統計，來源必須排在前面） |
| `Periods` | flags 可組合：`Lifetime|Daily|Weekly|Monthly` |
| `FilterConditionId` | 保留欄位，本輪未實作，填非 0 載入即拒絕 |
| `SyncClient` | 保留欄位，本輪不同步 Client |

本輪六項：在線秒數、在玩秒數（Tick Sum）、登入天數（DistinctDays）、連續登入（Streak）、最長連續登入（Max of 連續登入）、上線次數（Count）。新增統計只需加一列，熱重載後生效。

## 設定

`config/*/world.yaml`：

```yaml
day_reset:            # 全 Server 遊戲日換日時刻，任務與統計共用
  timezone: UTC
  hour: 0
  minute: 0
online_session:
  flush_interval: 5m   # 心跳批次寫入間隔；當機最多少算一個間隔
  idle_threshold: 5m   # 無操作多久只算在線、不算在玩
  stale_after: 10m     # 心跳逾時多久回收；必須大於 flush_interval，否則啟動失敗
  retention: 4320h     # 已結束打卡單保留期
statistic:
  write_interval: 30s
  daily_retention_days: 40
  weekly_retention_weeks: 12
  monthly_retention_months: 13
```

## 報表

Grafana 儀表板 `Player Online Stats`（`monitoring/grafana/dashboards/player-online-stats.json`）讀 `World MySQL` 資料來源（`monitoring/grafana/provisioning/datasources/world-mysql.yml`，本機指向 compose.deps 的 13306）：DAU／新玩家、CCU（Prometheus `game_world_online_players`）、平均在線與在玩、留存率、時長分布、關單原因、當機回收比例、上線次數。正式環境把資料來源改成唯讀帳號。

## 效能與限制

- 在線期間只動記憶體；每台 World 每 `flush_interval` 一句批次 upsert（分批 500 列），每位玩家上下線各一列。
- 寫入失敗保留重試；資料庫長時間不可用時 Tracker 最多保留 100,000 列，超過丟最舊（只少算時長）。
- 回收器是全表作業：多台 World 都會跑，冪等。資料庫中斷超過 `stale_after` 時，仍在線的玩家可能被另一台 World 誤收，之後的心跳只累加秒數不會重開。
- 登入訊息沒有 Client 版本、平台與 IP，打卡單與報表沒有這些維度；要有需改 PJA-Protocol。
- `player_session` 保留期清理逐批 DELETE；正式 migration 建立後改按月分區。
