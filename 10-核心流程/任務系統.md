# 任務系統

玩家在 World 中接取、進行與完成任務，系統支援任務進度追蹤、自動啟用、失敗冷卻、周期重置與領獎機制。

## 架構總覽

任務系統由設定層、狀態層與事件層組成：

- **設定層**：從 PJA-Config 載入任務定義、獎勵、周期與條件
- **狀態層**：玩家任務進度、待領獎勵與冷卻狀態儲存於 MySQL
- **事件層**：道具使用、盤面事件等觸發任務進度增長；獨立佇列消費事件並更新進度

## 任務定義與驗證

任務設定由 `PJA-Config` 的 `Mission` 提供，World 啟動時驗證：

- 必要欄位：任務 ID、名稱、類型、目標
- 可選欄位：前置條件、固定獎勵、可選獎勵、顯示欄位、規則版本
- 驗證項目：
  - 引用的條件樹必須存在且有效
  - 引用的道具必須支援任務事件（`UsableFromInventory`）
  - 獎勵分配與領獎冷卻時間相容性

## 任務週期與重置

任務支援多種週期重置策略，在 World 設定中配置：

| 周期類型 | 配置 | 重置時機 | 用途 |
|---------|------|--------|------|
| 無重置 | `none` | 不自動重置 | 一次性任務 |
| 每日 UTC | `daily` | 每日 00:00 UTC | 日常任務 |
| 每週 | `weekly` | 每週一 00:00 UTC | 週任務 |
| 每月 | `monthly` | 每月 1 日 00:00 UTC | 月任務 |
| 全服固定間隔 | `interval` | `mission_reset_interval` 時間間隔 | 固定間隔任務 |

可透過 `mission_reset_timezone` 與 `mission_reset_time` 調整全服任務重置的時區與時刻。

## 任務生命週期

```
未啟用
  ↓ 手動接取或自動條件成立
待進行 ← 條件檢查失敗時自動拒絕
  ↓ 進度達標
待領獎
  ↓ 玩家手動領獎或自動領獎
完成 ← 領獎逾期時進入冷卻
  ↓ 冷卻期滿後周期重置
未啟用（下一輪）
```

### 手動接取

1. 玩家發送 `TakeMissionRequest`
2. World 檢查玩家狀態、任務前置條件與啟用條件
3. 接受或拒絕；成功時記錄接取時間與進度

### 自動啟用

World 在玩家登入或周期重置後檢查所有任務的自動啟用條件：

- 依玩家當前變數與盤面狀態評估條件
- 條件成立時自動進入「待進行」狀態
- 條件失敗時保持「未啟用」或自動返回「未啟用」

### 進度與事件

進度由以下事件增長：

- **道具使用**：玩家使用任務道具時，World 轉發事件到任務佇列
- **盤面事件**：擲骰、建築、抽獎等觸發的事件
- **時間戳**：事件發生時間用於版本相容性判斷

任務進度與事件去重在同一筆 MySQL 交易中保存，確保不遺失。

### 進度相容性

任務升級時（門檻調高、顯示欄位變更），系統檢查既有進度是否仍有效：

- **門檻調高**：允許平行任務目標的門檻調高，玩家既有進度保留
- **版本判斷**：以設定版本對比玩家記錄的任務規則版本
- **舊事件相容**：設定未變的積壓事件可繼續用於已啟用任務

### 領獎機制

#### 自動領獎

World 定期檢查是否有待領獎的任務：

1. 檢查獎勵是否逾期（超過 `missionClaimExpiresAt` 時刻）
2. 驗證任務版本相容性
3. 成功則自動發放固定獎勵
4. 失敗則進入失敗冷卻

#### 手動領獎

玩家發送 `ClaimMissionRewardRequest`：

1. 檢查任務是否待領獎
2. 驗證版本相容性與時間限制
3. 發放固定獎勵與執行可選獎勵（可選獎勵允許玩家於領獎時選擇）
4. 成功時記錄領獎時間

#### 領獎逾期與冷卻重開

- 待領獎超過逾期時刻時，任務進入失敗冷卻
- 冷卻期滿後，系統在下次周期重置時重新啟用或等待玩家手動接取
- 冷卻期間若發生周期重置，冷卻被重置

### 失敗冷卻與重試

任務失敗（自動或手動領獎失敗）時進入冷卻：

- **自動失敗**：事件觸發但條件失敗時冷卻
- **手動失敗**：玩家接取後未在期限內完成時冷卻
- **冷卻時間**：可由任務設定或全局設定指定
- **重試**：冷卻期滿後由自動啟用流程或玩家手動接取重試

## 超額進度與跨輪保留

任務支援超額進度跨輪保留：

- 進度達標後仍可繼續增長（例如「擊敗敵人 3 次」達標後仍可增長到 5 次）
- 周期重置時，超額進度部分保留到下一輪
- 下一輪進度初值為上輪的超額部分
- 允許玩家在同一周期內達成多輪的進度需求

## 任務佇列與非同步消費

任務事件獨立佇列消費，確保不阻塞其他流程：

1. 道具使用或盤面事件發生時，World 發布事件到任務佇列
2. 消費端分派事件到對應任務目標的進度計算
3. 進度更新與去重在 MySQL 交易中完成
4. 失敗時透過斷路器與重試機制處理

## 訊息與指令

### 登入時回傳

玩家登入時，World 回傳：

- 當前周期的任務列表（接取狀態、進度、待領獎勵）
- 待領獎勵詳情與逾期時刻

### 主要指令

| 指令 | 發起者 | 用途 |
|------|-------|------|
| `TakeMissionRequest` | Client | 玩家手動接取任務 |
| `ClaimMissionRewardRequest` | Client | 玩家手動領獎 |
| `MissionProgressUpdate` | Server (internal) | 事件觸發進度增長 |
| `MissionListResponse` | Server | 回傳任務列表與待領狀態 |
