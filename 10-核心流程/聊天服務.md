# 聊天服務

這份文件描述目前聊天服務的責任邊界、資料來源與同步規則。

## 目標

- 文字聊天與世界廣播群組分離
- 聊天歷史可從 MySQL 補回
- client 換機或重連時，可以用 `ChatSync` 補缺
- 即時送達仍走 TCP 廣播，不引入額外 queue

## 責任邊界

### 聊天服務

- 接收 `ChatSend`、`ChatSystem`、`ChatSync`
- 將聊天歷史寫入 MySQL
- 維護 `MessageID`
- 根據 room membership 做即時 fanout
- 對 `ChatSync` 回傳指定區間的歷史訊息

### Gate

- 只負責轉發玩家聊天請求
- 收到 `ChatDeliver` 後轉給本地玩家 socket
- 不保存聊天歷史

### World

- 保留 `Channel*` 作為世界廣播群組
- 世界頻道由 Server 依 `WorldID` 決定，玩家登入時自動加入
- Client 不提供頻道加入或離開操作；頻道成員由登入與登出流程管理
- 頻道訊息一律由 Server 依權威狀態產生，Client 不提供頻道發送命令
- World 對每個 Gate 送一份帶 `channelType` 的 `ChannelBroadcast`，不按玩家逐筆送出
- Gate 維護各種類型的本地頻道成員投影，再將原始 Client 協定直接 fanout 給本地玩家
- World 以 `SetChannelMembership` 同步成員變更到玩家所在的 Gate；Gate 只負責本地 fanout
- 不承擔文字聊天主流程
- 不保存文字聊天歷史
- `Channel` 是 Server 端的廣播分組，識別鍵為 `(channelType, channelID)`，可支援多種頻道類型
- World 以 `BroadcastChannel` 對每個 Gate 送一份 `ChannelBroadcast`，不按玩家逐筆送出
- `ChannelBroadcast` 帶原始 Client 協定的 `messageID`、`payload` 與 `senderPlayerID`
- Gate 依本地頻道成員投影，將原始 `messageID + payload` 直接 fanout 給本地玩家
- World 以 `SetChannelMembership` 發送 `ChannelMembershipUpdate` 同步成員變更
- World 與 Gate 連線建立或重連完成 `ConnectInfo` 後，會先送出 `ChannelMembershipSnapshot`；Gate 以快照重建該 World 的本地投影，再套用後續的 `ChannelMembershipUpdate` 增量變更
- 不存在 `ChannelDeliver` 包裝協定，Client 也不提供頻道加入、離開或發送操作

## 訊息

### `ChatSend`

- 玩家送出文字聊天訊息
- `Gate` 轉給 `ChatService`
- `ChatService` 先落 MySQL，再即時廣播

### `ChatSystem`

- 其他服務送入的系統訊息
- `RoomID = 0` 代表全域廣播
- 會進歷史，之後也能被 `ChatSync` 補回

### `ChatSync`

- 玩家在登入後或斷線重連後請求歷史補送
- `SinceMessageID` 只當 hint
- `ChatService` 只回 `SinceMessageID` 之後的訊息
- 最多回 `Limit` 筆，server 端有硬上限

### `ChatDeliver`

- `ChatService` 派送到 `Gate` 的單則訊息
- 帶 `MessageID`
- client 可用來去重與更新 sync 起點

## 資料來源

### MySQL

- `chat_message`
- 目前是聊天歷史的 source of truth
- `ChatSync` 的查詢入口

### Memory

- room membership
- user membership
- 鮮活在線目標集合

## 同步規則

1. client 送 `ChatSync(SinceMessageID, Limit)`
2. `ChatService` 查 MySQL
3. 回傳 `SinceMessageID + 1` 之後的歷史
4. 最多回 `Limit` 筆
5. client 用 `MessageID` 去重

## 即時廣播

1. `ChatService` 收到 `ChatSend` 或 `ChatSystem`
2. 寫 MySQL
3. 查目前 room 的在線成員
4. 對各個 Gate 做 TCP fanout
5. `Gate` 再送到本地玩家 socket

## 保留與清理

- `chat_message` 可持久保存或後續再做歸檔
- room membership 不持久化
- 若未來要做長期歸檔，再補歷史分表或冷資料搬移
