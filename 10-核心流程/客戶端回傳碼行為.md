# Client 回傳碼行為

這份文件定義 `client` 在收到不同 `return_code` 時應採取的行為。

目標不是描述 server 內部流程，而是把 `client` 的重試、重登、提示策略固定下來，避免不同端各自實作出不一致行為。

相關文件：

- [[連線與登入流程]]
- [[資料一致性]]

## 基本原則

### 1. 優先依 `return_code` 決定行為

- 不要用錯誤文字判斷。
- 同一個 `return_code` 在不同 client 端應有一致處置。

### 2. 先區分「可重試」與「不可重試」

- 可重試：
  - `AuthServiceUnavailable`
- 不可直接重試：
  - `AuthAccountEmpty`
  - `AuthLoggedIn`
  - `AuthLoggedOut`
  - `AuthSessionExpired`
  - `AuthRecoveryMismatch`
- 可在冷卻後重試：
  - `AuthRateLimited`

### 3. retry 只適用於建立新鏈路

- `client` 不應重放舊的請求上下文。
- retry 應視為重新發起新的 login/logout 操作，由 `Gate` 建立新的 `request_id` 與 `trace_id`。

### 4. 發生 session 失效時，優先回到登入入口

- `AuthReLogin`
- `AuthSessionExpired`
- `AuthRecoveryMismatch`

以上 3 種都不應在原地無限重送原請求。

## 回傳碼對應規則

回傳碼定義位於 `pkg/enum/return_code.go`。

| Return Code | 語意 | Client 行為 | 是否自動重試 |
| --- | --- | --- | --- |
| `AuthSuccess` | 操作成功 | 更新本地狀態並進入下一步 | 否 |
| `AuthServerFail` | 未分類伺服器錯誤 | 顯示通用錯誤訊息 | 否 |
| `AuthLoggedIn` | 玩家已登入 | 視為重複登入或本地狀態過期，導回主畫面或線上狀態 | 否 |
| `AuthAccountEmpty` | 帳號輸入不合法 | 提示修正輸入 | 否 |
| `AuthSaveFail` | 存檔或持久化失敗 | 顯示錯誤並停止目前操作 | 否 |
| `AuthReLogin` | 必須重新登入 | 清本地 session 並回登入入口 | 否 |
| `AuthLoggedOut` | 玩家已登出或 session 已不存在 | 本地直接視為已登出 | 否 |
| `AuthServerFull` | 目標 World 已滿 | 提示伺服器滿員，可由玩家稍後再試 | 否 |
| `AuthRateLimited` | 短時間請求過多 | 顯示冷卻中提示，等待冷卻後再允許操作 | 否 |
| `AuthServiceUnavailable` | 依賴服務不可用 | 顯示暫時不可用，可啟用有限次數自動重試 | 是 |
| `AuthSessionExpired` | session 或登入上下文失效 | 清本地 session，回登入入口 | 否 |
| `AuthRecoveryMismatch` | 恢復校驗失敗 | 視為線上狀態失效，清本地 session 並回登入入口 | 否 |

## Login 規則

### 成功

- 收到 `AuthSuccess` 時：
  - 建立本地登入狀態
  - 進入遊戲流程

### 可提示玩家修正的失敗

- `AuthAccountEmpty`
  - 提示帳號不可空白
- `AuthServerFull`
  - 提示伺服器滿員
- `AuthRateLimited`
  - 顯示冷卻中提示

### 可由 client 自動重試的失敗

- `AuthServiceUnavailable`
  - 可做有限次數重試，例如 `1~3` 次
  - 每次重試應有 backoff
  - 若超過上限，改為提示玩家稍後再試

### 必須回登入入口的失敗

- `AuthReLogin`
- `AuthSessionExpired`
- `AuthRecoveryMismatch`

這三種都代表原本上下文已不可信，不應保留原 session 狀態。

## Logout 規則

### 成功或可視為成功

- `AuthSuccess`
- `AuthLoggedOut`
- `AuthSessionExpired`

這三種在 `client` 端都應最終收斂成：

- 清本地 session
- 回登入入口或 title 畫面

原因：

- 對玩家來說，目標都是「現在已不在線」。
- 不需要因為 server 已經先清掉狀態，就阻止本地完成登出。

### 可重試情況

- `AuthServiceUnavailable`
  - 不建議背景無限重試
  - 可以提示玩家目前服務不穩，並讓 UI 提供一次明確的「再試一次」

## 恢復與重連規則

### 恢復成功

- `client` 不需特別處理。
- 由 `Gate / World` 完成恢復校驗與路由收斂。

### 恢復失敗

- `AuthRecoveryMismatch`
  - 直接視為本地線上狀態失效
  - 清本地 session
  - 回登入入口

### 連線中斷但尚未收到回傳碼

- 若 socket 已斷線，`client` 應先區分：
  - 是否仍在登入中
  - 是否已登入完成

建議行為：

- 登入中斷線：
  - 提示登入失敗，允許重新登入
- 遊戲中斷線：
  - 先顯示重連中
  - 若重連失敗或 server 回 `AuthSessionExpired` / `AuthRecoveryMismatch`，回登入入口

## UI 提示建議

`client` 不應直接把 enum 名稱顯示給玩家，而應映射成固定文案。

建議分類如下：

- 輸入問題
  - `AuthAccountEmpty`
- 系統暫時不可用
  - `AuthServiceUnavailable`
  - `AuthServerFail`
- 狀態已失效
  - `AuthReLogin`
  - `AuthSessionExpired`
  - `AuthRecoveryMismatch`
- 操作過於頻繁
  - `AuthRateLimited`
- 容量限制
  - `AuthServerFull`

## 實作準則

之後若新增 `return_code`，應同時回答 3 個問題：

1. `client` 是否允許自動重試
2. `client` 是否必須清本地 session
3. 玩家應看到哪一類提示

如果這 3 個問題沒有明確答案，代表回傳碼語意還不夠完整，不應直接加入協定。
