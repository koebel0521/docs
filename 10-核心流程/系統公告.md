# 系統公告

Lobby 提供所有玩家共用的公告儲存與增量同步。公告不傳送固定語言文字，而是傳送語系 key 與少量參數；玩家端依自身語系檔顯示內容。

## 玩家 DTO

```json
{
  "seq": 125,
  "key": "maintenance.scheduled",
  "params": {"minutes": "10"},
  "exp": 1788811200
}
```

| 欄位 | 說明 |
|------|------|
| `seq` | Lobby 以 Redis 配置的遞增序號；用於去重與增量同步。 |
| `key` | 玩家端語系 key。 |
| `params` | 選填字串參數；僅傳變動值。 |
| `exp` | Unix 秒數；到期後 Lobby 不再回傳。 |

玩家端應保存每台裝置自己的 `lastNoticeSeq`。首次同步不帶 `after`，後續使用上一個 `nextSeq`；這不依賴玩家裝置時間。

```http
GET /notices?after=125
```

```json
{
  "notices": [
    {"seq": 126, "key": "event.started", "exp": 1788814800}
  ],
  "nextSeq": 126
}
```

最多一次回傳 100 則，超出時 `hasMore` 為 `true`，玩家端以 `nextSeq` 繼續拉取。回應使用 `Cache-Control: no-store`。

## 管理端 API

所有 `/admin/*` 路由均需既有的 `Authorization: Bearer <ops token>` 與 `X-Requested-By: admin`。

### 建立公告

```http
POST /admin/notices
Content-Type: application/json
```

```json
{
  "key": "maintenance.scheduled",
  "params": {"minutes": "10"},
  "exp": 1788811200
}
```

成功回傳 `201 Created` 與包含 `seq` 的公告 DTO。`key` 最長 128 bytes；最多 16 個參數，參數名稱與內容分別限制為 64、256 bytes。

Windows 維護前可用：

```powershell
curl.exe -X POST "http://127.0.0.1:8080/admin/notices" `
  -H "Authorization: Bearer <ops token>" `
  -H "X-Requested-By: admin" `
  -H "Content-Type: application/json" `
  --data '{"key":"maintenance.scheduled","params":{"minutes":"10"},"exp":1788811200}'
```

### 撤下公告

```http
DELETE /admin/notices/{seq}
```

成功回傳 `204 No Content`；找不到序號時回傳 `404 Not Found`。

## Redis

| Key | 類型 | TTL | 用途 |
|-----|------|-----|------|
| `lobby:notice:sequence` | String | 永久 | 公告遞增序號。 |
| `lobby:notice:records` | Hash | 最晚公告到期時間 | 以序號為欄位保存公告 DTO。 |

## 目前界線

此階段完成公告建立、到期、撤下與玩家端增量同步；不重用 `ChatSystem`，因為它只傳原始文字，無法正確支援語系 key。即時推播需要玩家協議新增 `SystemNotice` 訊息，再由 Chat／Gate 轉送；該協議不在本專案中，不能用既有文字聊天訊息冒充。
